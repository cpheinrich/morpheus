# Executable workflow comparison

This follow-up evaluates small executable repairs, after the first Paperclip pilot tied
12/12 on historical decisions. The Git/Paperclip bridge and authenticated snapshot jobs
are a separate increment in PR470. Neither dispatch nor a successful model run proves
that an organization layer improves accepted work.

## Frozen method

Eight incident-inspired Python tasks are split into two development and six held-out
cases. All arms get the same public contract, history, starter, smoke test and requested
model: gpt-6.1-sol/xhigh through pinned native Codex0.163.0. Served model is unknown.

| Arm | Execution | Separate manager |
|---|---|---|
| A | Direct through the native quota/process wrapper | No |
| Q | Paperclip assignment through the same wrapper | No |
| P | Direct through the wrapper | Yes |
| F | Paperclip assignment through the wrapper | Yes |

A/F run on all six held-out cases. Q/P and a direct repeat run on T01/T02 only. The
manager has at most45 seconds within the same170-second initial total, returns a brief
from public facts, and does not implement. One fresh130-second continuation is permitted
only for primary A/F jobs whose independently run public smoke test fails. Hidden checks
never enter that feedback. No hidden grading occurs until all relevant model processes
terminate. All inference runs on the controller account; this is not a two-host benchmark.

The predeclared screening rule requires at least two additional F repair successes,
zero A-only successes, no critical regression and at most25% more input plus output
tokens per verified success. Missing provider usage makes the cost condition inconclusive.
Six cases are screening evidence; additional manager reasoning prevents a compute-matched
claim that role labels caused any difference. Event counts are not human minutes saved.

## Development and controls

The first development case diagnosed deadlines, a duplicate upstream retry classification,
and skill-triggered MCP re-enablement. The final isolation profile disables app/plugin
loading, skill MCP auto-install, external tools and tool network access. Effective-thread
status exposes zero MCP tools and actual v2 development traces contain no MCP tool calls.
Earlier variants are retained as diagnostics and excluded from held-out rankings.

All four variants on development case D02 implemented the literal public contract but
failed an undisclosed whitespace-receipt restriction. An independent contract audit found
that ambiguity and no further blocking mismatch in the six held-out contracts. Only D02
public wording changed; all held-out case objects and42 companion files were checked
unchanged. These pre-clarification failures are not evidence of model-contract errors.

26 controls pass, including real native denial of oracle reads/chmod, network, forks,
source writes and forged grader output. Public smoke imports and hidden candidate calls
execute in separate deny-default Seatbelt processes. The trusted grader retains hidden
checks and expected values. Completed workspaces and traces are sealed from later workers.
An uncertain submission keeps the private credential vault sealed until termination is
reconciled. No new subscription or paid API fallback is enrolled.

## Reproduction and limits

The [collector and scorer](../qa/evals/workflow-repair/README.md) use cached paid outputs;
rescoring does not call a model. Private campaign storage is
`~/.local/share/morpheus-paperclip/deeper-20261023/locked-v1`, and the clarified private
corpus is its sibling `curation-clarified`. Raw traces and credentials stay private.

After terminal proof, run `score_campaign.py PRIVATE_CAMPAIGN PRIVATE_CORPUS --split
locked --models-terminal`, then `summarize.py PRIVATE_CAMPAIGN` with /usr/bin/python3.
Reports distinguish acceptance of JSON values, immutable-file integrity, basic handoff
material presence, actual command traces, known/unknown token use and elapsed time.
Handoff presence alone does not attest report truth or protected project delivery.
The RPC boundary copies values and cannot preserve Python object identity; these checks
do not establish in-process aliasing or argument-mutation guarantees. Those need native
project tests or a separate operation-specific probe.
