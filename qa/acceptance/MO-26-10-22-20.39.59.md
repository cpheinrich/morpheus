# Empty external tester lists are a safe pending condition

## Design before implementation

A valid empty list from an exact existing external group is expected waiting,
not internal delivery failure and not permission to add testers. Preserve exact
receipt/build/app/group identity, external type and automatic-distribution guards.
Require actual array evidence containing only nonblank string tester IDs; empty
arrays are valid but cannot establish external availability.

Classify terminal, rejected, processing and unknown build states first. For an
otherwise reconcilable build, any empty configured external group records
pending/wait-external-testers, exact observation and the ordinary poll deadline.
Return before notify, membership, review or dispatch calls. No tick error is added.
A later populated readback resumes the current once-only flow, with no reupload,
new native work or review-claim reset. Keep absent opt-in/config digest unchanged.
The existing record/CAS path is sufficient; no package or generic framework.

## Required outcomes

- Both channels: zero testers waits without errors or provider mutation, including
  IN_BETA_TESTING with exact membership; it never becomes available prematurely.
- Observe only at the existing poll boundary, with no early repeat; populated
  groups resume exact membership and one review POST before availability.
- Every configured group must have testers; one empty group prevents all external
  mutations. Invalid tester evidence, foreign app/group, internal group and
  automatic access remain errors. Empty lists cannot hide rejected, expired,
  processing or unknown build-state blocks.
- Preserve internal receipt/attempts/lineage/cursors/group operations/builds,
  agents/budget and any uncertain exact-build review claim. Existing pauses,
  observation mode, no opt-in and concurrency/read-first tests remain applicable.
- The original core must fail the new regression. Targeted unsafe mutations must
  fail meaningful assertions; retain failures and restore the final source.

## Qualification boundary

Tests use normal Controller.tick with FakeGitHub and mocked Apple observations;
no live controller, provider, credentials or delivery operation runs. Local source
checks do not establish Apple availability or consumer runtime adoption. This task
stops locally before publication until its separate source release.
