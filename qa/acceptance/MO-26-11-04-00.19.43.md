# Release preflight: pinned reviewed sources contained in main

- A source equal to current main passes exactly as before, with no compare call.
- A source that current main strictly contains (`compare source...main` = `ahead`) passes, and
  the `sha` output is the pinned source, never the newer head.
- Compare status `behind`, `diverged`, `identical` with different SHAs, an empty status, or a failed
  compare refuses and writes no output.
- An unreadable or malformed main SHA refuses.
- A source contained in main still needs its own merged PR into main whose merge commit is that
  SHA; main's head PR never vouches for an ancestor.
- A non-main ref or a dirty or mismatched checkout still refuses; a dirty checkout refuses before any GitHub call.
- The workflow interface is unchanged: no inputs, no secrets, read-only permissions, `sha` output.
- Mutating the compare order, the `ahead` test, the ancestry branch, the main-SHA shape check, the
  head short-circuit or the PR SHA binding fails the focused suite.
- Evo controller adoption and real TestFlight deliveries are separate acceptance.
