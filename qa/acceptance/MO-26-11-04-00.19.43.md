# Release preflight: opt-in pinned reviewed sources

- `release-preflight.yml` declares one `workflow_call` input, `allow-pinned-source` (boolean,
  default false). There is still no caller-selected source, no secret, read-only permissions and
  the same `sha` output. A manual dispatch has no inputs.
- **Default (absent, false, empty, or any value but `true`).** Unchanged from before: a source
  equal to current main passes with no compare call. A source main has moved past refuses with
  "is not current origin/main", with no compare or pull-request call, including when a caller's
  cached `build=true` decision reaches the preflight on a re-run.
- **Opted in (`true`).** A source current main strictly contains (`compare source...main` = `ahead`)
  passes, and the `sha` output is the pinned source. `behind`, `diverged`, `identical` with
  different SHAs, an empty status or a failed compare refuses with no output.
- Unreadable or malformed main refuses in both modes.
- In both modes the source needs its own merged PR into main whose merge commit is that SHA;
  main's head PR never vouches for an ancestor.
- A non-main ref, a mismatched checkout or a dirty checkout refuses before any GitHub call
  (executed fixtures).
- No workflow in this repository opts in. `ios-nightly-build.yml` is byte-identical to the base,
  and its rendered input is the default, so re-running an older night refuses.
- Mutants that turn the default on, accept any value, ignore the opt-in, default it to true, drop
  the ancestry proof, swap the compare order, drop the main shape check, accept any PR, or
  hard-wire the env each fail the focused suite.
- Evo controller adoption (`allow-pinned-source: true`) and real TestFlight deliveries are separate
  acceptance.
