# Retry a failed test bundle's selected tests, not its placeholder

- A bundle-startup placeholder (`Test Case` under `System Failures`, no `Class/method()` identifier,
  e.g. "Failed to install or launch the test runner") is never passed to `-only-testing` and never
  appears as a test id in `test-attempts.json` `failed` or `flaky`.
- The retry for a failed bundle runs that bundle's original selection on the erased simulator: the
  whole bundle when the caller selected all of it, otherwise exactly the caller's `-only-testing`
  entries inside it. A caller that selected five UI tests never gets the whole UI bundle.
- The caller's `-skip-testing` entries for that bundle are carried into the retry.
- Real failed test cases in other bundles are still retried individually; passing tests outside the
  failed bundle are not rerun.
- A bundle retry that executes none of the bundle's tests is not recovery: the job fails and names
  the bundle as an infrastructure failure, not a fictional test id.
- A bundle that runs on retry with every test passing is reported as recovered (warning, not
  failure); a real test failing there is retried or fails like any other test.
- `maxAttempts`, caller attempt policy, first-attempt evidence and fail-closed handling of failures
  that name nothing are unchanged.
