# Discover queued CI jobs missing from filtered lists

Host change: cpheinrich/agent-host-setup `ci-vm/dispatcher.mjs` `queuedJobs`.

- The `queued`, `pending` and `in_progress` status-filtered run queries are unchanged, so an older
  queued run that only a filtered list returns still produces demand.
- One unfiltered `actions/runs?per_page=30` page is read per repository per poll. A queued
  exact-label job in a run every filtered list omits becomes demand.
- Each run id is inspected at most once per poll across all four lists; a job is never counted
  twice.
- Unfiltered runs whose status is `completed` get no jobs lookup.
- Running and completed jobs are never demand; demand still passes `wantedJobs`, foreign-runner
  ownership and fairness unchanged.
- A failure of the unfiltered list or of its jobs lookups keeps the filtered demand. A failure of a
  filtered list still rejects that repository's poll, as before.
- Mutants removing deduplication, the `completed` filter, the catch or the filtered queries each
  fail the focused suite; the replay test fails on the base revision.
- Limit, documented in `ci-vm/README.md`: an omitted run older than the 30 most recent runs is
  still missed.
- Production acceptance, after reviewed merge and install by the root: a real queued exact-label
  job omitted by a status filter is assigned to a new owned VM and completes, with normal teardown.
