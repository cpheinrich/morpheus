# Host-scoped native CD repair

- A local-only agent configuration validates. Absent hosted repair performs no hosted ledger reads, API calls or writes; an explicit unconfigured hosted worker fails before ledger access.
- Existing hosted configuration normalizes to byte-identical JSON and the same canonical digest, including existing command/ref defaults. Configured hosted dispatch/resume behavior remains supported.
- `cd worker --executor local --host-id ID` persists a stable nonsecret native host/user/session-store identity. Old callers default to the native hostname; multi-host operators pin unique IDs.
- Resume only the latest local invocation with a session and the exact current host ID. A foreign, legacy unidentified or latest sessionless local invocation starts fresh even if an older matching session exists.
- Fresh native sessions receive the immutable task, original diagnostics and durable prior checkpoint summaries/evidence, without copying auth stores or native session files.
- Global local-subscription reservation, Git CAS and lease ownership still serialize work across hosts. Stale owner/fence combinations cannot persist session/completion or escape through the error fallback.
- Focused tests exercise actual `runWorker` and CLI flow through a synthetic executable/real process guardian and Git database fake, never a real model. Cover same-host resume, fresh-host/legacy recovery, two-host CAS contention, cross-host reservation and stale checkpoint failure paths.
- No live ledger/configuration migration, source/host/service mutation, real repair or off-host acceptance is claimed. Those remain consumer/operator work after this reviewed source merges.
