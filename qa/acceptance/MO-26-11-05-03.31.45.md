# Release preflight: protected iOS release-branch source (opt-in)

- **Default callers unchanged.** Every caller that passes no new input keeps exactly the current
  behaviour: `main` head equality, or `allow-pinned-source` containment, the merged-PR binding,
  read-only permissions and the same `sha` output. A test fails if the default path changes.
- **Opt-in source check.** With `release-branch` and a source SHA set, preflight accepts that source
  only when all of these hold:
  - the branch name matches `release/ios-*`;
  - the branch is protected;
  - the source is the branch tip or an ancestor of it;
  - the branch's base A (recorded by the caller) is contained in current `main`;
  - every commit in `A..source` (at most 250) is the merge commit GitHub recorded for a merged PR
    whose base is that branch, so a direct push or a merge commit's own parents refuse (repairs are
    squash-merged).

  Anything else refuses with a message naming the failed condition. An unreadable API answer refuses;
  it never passes.
- **Control check still applies.** The control commit (`github.sha`) is still verified exactly as
  today, so a release-branch source never lets an unreviewed workflow revision run.
- **Separate outputs.** The verified source is a separate output from the control `sha`.
- **Test environment record.** `ios-ci.yml` writes `Results/environment.json` beside the evidence:
  macOS and Xcode versions and builds, simulator runtime and device type, runner, and the Morpheus
  refs. A value it cannot read is `null`, never guessed, and a failure to write it never fails the
  run. Evo's remediation planner compares it between the baseline and the candidate.
- **Tests.** The checks are exercised against recorded or faked GitHub API answers for each refusal
  and the accept path. No live repository mutation happens.
- **Release path.** The work is a draft PR only: independent review, required CI, no merge, no
  auto-merge.
