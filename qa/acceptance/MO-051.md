# MO-051 — acceptance criteria

The first item to set `RoadmapItem.acceptance`. The field has existed since MO-001 and had never
been used, which is why verifier rung 3 could not exist — conformance means comparing a change
against stated criteria, and there were none anywhere in the repo to compare against.

These are written to be checked, not admired. Each is either met or not.

## The rung

- [x] An independent agent — a different session from the one that opened the PR — reviews it.
- [x] The review **never blocks the merge**. No job depends on it; a failure leaves the PR
      mergeable. *(Asserted by a test over ci.yml, not only by reading it.)*
- [x] It reports findings as a comment on the pull request. *(Failed on first live run — the
      reviewer was denied every delivery tool and exited green. Fixed in MO-26-08-02-02.34.24.)*

## When no credential is configured

- [ ] The workflow does **not** report success as though it ran.
- [ ] The job summary states plainly that rung 2 was skipped, and that green means skipped rather
      than passed.
- [ ] An Actions warning annotation is emitted, so it is visible without opening the summary.
- [ ] The message names what to configure.

## The prompt

- [ ] Assembled from a versioned persona file (`.github/agent-review-prompt.md`), not a string
      buried in YAML.
- [ ] Carries the roadmap item's stated intent — the one thing the reviewer cannot infer from the
      repository itself.
- [ ] Carries acceptance criteria when the item declares them.
- [ ] Omits the conformance section entirely when it does not. An empty heading claims there are no
      criteria to meet, which is not the same as none being stated.
- [ ] Reports a declared-but-missing acceptance file as a defect rather than as an absence.

## Scope

- [ ] Generating or enforcing acceptance criteria is **out of scope**. This item consumes them.
