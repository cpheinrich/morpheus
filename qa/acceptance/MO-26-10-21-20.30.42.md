# Terminal job placeholders in the no-start census

Source-only correction to `src/cd/controller.ts`. Nothing here is a drill, a live
cancellation, an installed runtime or an adoption.

GitHub's public REST description (`api.github.com.json`, sha256
`3177ad6a86ca04c57a9bef3fc24e28a339efb8eb040c6f950af3d3ed2fee7fa3`, fetched
2026-10-22) is relevant in four ways:

- It declares `created_at` and `started_at` as required, non-nullable date-time strings.
- It declares the four runner fields nullable, "null" until a runner is assigned.
  The real cancelled row reports `0`/`""` instead.
- Its job example omits `created_at` entirely.
- The [conditions guide](https://docs.github.com/en/actions/how-tos/write-workflows/choose-when-workflows-run/control-jobs-with-conditions)
  says a job whose `if` is false "will be marked as skipped".

No page documents the timestamp GitHub writes for a job that never ran. The rule
below rests on the observed rows, not on the documentation.

## Defect

`unassigned()` accepts only `started_at === null`. With real-shaped rows, a terminal
run goes to `run-repair-agent` instead of `dispatch-hosted`. Such a run contains a
cancelled-before-assignment native job, a successful preflight, and skipped `upload`
and `qualify` rows. With `started_at` nulled on those same rows, the run takes the
hosted fallback.

## Requirements

1. **Terminal placeholder.** A row counts as never-run under either of two rules:
   - It passes the existing strict rule, unchanged.
   - It matches all of the following:
     - status `completed`;
     - an allowed conclusion: `skipped` for companions, `skipped` or `cancelled` for
       the native no-start census;
     - non-null `completed_at`, with no ordering against `created_at`, because real
       skipped rows complete one second before creation;
     - `started_at === created_at` as an exact string;
     - `runner_id` null or 0, and `runner_name` null or `""`;
     - `runner_group_id` null or 0, and `runner_group_name` null or `""`;
     - an empty `steps` array.
2. **Queued rows stay strict.** The queued branch of the admission census keeps
   `started_at === null`, which preserves the existing 15-minute admission bound. A queued
   row whose `started_at` equals `created_at` is not recognized as waiting.
   A terminal skipped placeholder may accompany a strictly queued native row, as a
   strict skipped row already may.
3. **No schema broadening.** `knownJob` does not change. `created_at` and both
   runner-group fields are required only to qualify for the placeholder. When they are
   absent, only the strict rule applies, and every other path keeps its current
   behaviour. The rationale is that the API example and older fixtures omit
   `created_at`.
4. **Unchanged guards.** All of the following keep their current behaviour:
   - Census: complete, non-empty, paginated and exact-attempt (count, duplicates, run
     id, head SHA and attempt).
   - No-start: at least one cancelled native job.
   - Companions: only Ubuntu preflight (successful) or skipped rows. Other executors,
     and cancelled companions, require repair.
   - Ownership and timing:
     - upload-claim, stale-attempt, delivered and recorded-tests guards;
     - deadlines;
     - one dispatch per effect;
     - burned build reservations;
     - repair ownership.
5. **Hosted lane.** Skipped companions use the same predicate on both lanes. A terminal
   skipped placeholder with neither an Ubuntu nor a macOS label is therefore a
   recognized companion on the hosted lane too. The real unlabelled `tests` row is an
   example. A completed census with no local job then records `hosted-terminated`
   quiescence and fails the attempt, as a strict skipped companion already did. The
   intent still goes to repair; this path dispatches nothing. A companion started at any
   other time leaves the attempt active, with "absence is not proved" evidence.
6. **Not claimed.** The following are unknown:
   - the cancellation shape of the drill's conjunctive-label target;
   - the shape of a live queued row;
   - whether a cancelled run's dependents report `skipped` or `cancelled`;
   - whether an assigned runner that never reported can show 0/`""` with no steps.

   Each case either matches the exact shape above or fails closed to repair.

## Boundary matrix

Every case runs through `Controller.tick`, with the in-memory `GitHubStore` over
`FakeGitHub`. Fixture rows are exact-field projections of the retained rows. The
projection preserves status, conclusion, labels, runner and runner-group values,
step count, and the start-to-creation and completion-to-creation relations. It rebinds
id, run, attempt and SHA to the harness run, and rebases times onto the harness clock.

| Case | Expected |

## Validation

- Focused controller tests run, with the baseline failures recorded against the
  unchanged source.
- Targeted mutants of each placeholder clause are killed.
- Typecheck, compile, PM index and `git diff --check` pass.
- A local projection check compares the fixtures with the retained raw files.

This is source correctness only. No hosted delivery, drill outcome or runtime
adoption is claimed.
