# morpheus wait-ci

`morpheus profile` put polling of running processes and CI at about 24% of agent busy time and 20%
of tokens, because each poll re-reads the whole session context to learn "still running".
`morpheus wait-ci [<pr|branch>] [--repo] [--timeout 45m] [--required-only]` replaces the loop with
one tool call: it polls one GraphQL query with backoff (10 s, ×1.5, capped at 60 s), prints nothing
while waiting, and ends with a digest. Exit 0 green, 1 failed, 2 timeout or no checks, 3 usage or
`gh` error. Pure logic is in `src/wait-ci/{checks,logs,digest}.ts`; the loop in `wait.ts` takes an
injected `gh` runner, clock and sleep, so timing, SHA moves and error handling are tested with a
scripted fake.

## What the real data changed

- **The tail of a failed-job log is useless.** `gh run view --job <id> --log-failed` returns the
  whole job — 400 to 3,000 lines — and its last 40 are git cleanup. The useful window is the
  output of the step containing the last `##[error]`, starting after that step's `##[endgroup]`
  (which closes the echoed script and its `env:` block). Over budget, the first 15 lines and the
  tail are kept: the real `verify-build-clean` failure is a 1,700-line diff whose subject is at the
  top, and a test runner summarises at the bottom.
- **gh renders ANSI as literal `^[[36;1m` text** when stdout is not a terminal, and every step
  column read `UNKNOWN STEP`. Both forms of escape are stripped; the step name comes from the
  `##[group]Run …` header instead.
- **Head SHA and checks come from one response.** `commits(last: 1) { commit { oid
  statusCheckRollup } }` pairs them atomically, so a push between two requests cannot mix commits.
- **Two `pr / conventions` checks can coexist.** The `Review metadata` workflow re-runs conventions
  on `labeled`, beside CI's own. Required checks are de-duplicated by name — the rule branch
  protection applies — and other checks by workflow and name; the latest attempt wins, and a queued
  attempt (no `startedAt`) counts as the latest, so a superseded label-race failure is not reported
  and a fresh run is not judged by the failure it replaces.
- **Most recent Morpheus CI failures are `pr / conventions`,** many of them the label race. The
  digest labels it, and prints "blocked only by the agent-reviewed label race" when it is the only
  failure.

Fixtures in `tests/wait-ci/fixtures/` are condensed from real job logs on this repository (runs
37612371526, 37724003461, 37095803968), keeping their original line format, BOM and escapes.

Decisions taken without asking, all reversible:

- A head that moves mid-wait is **followed**, and the move is named in the digest; the newest push
  is what the caller needs a verdict on.
- A failure is decisive: at the deadline with a known failure the exit is 1, not 2.
- No checks at all is never green. An empty rollup is treated as "not created yet" for three
  minutes, then reported as no CI with exit 2.
- Three consecutive failed polls end the wait with exit 3; one blip does not.
- At most five failed jobs get logs, sharing a 150-line budget (15 to 60 each).
- The label race keeps exit 1 — GitHub still blocks the merge — but its verdict line says no code
  needs fixing.
- No `--fail-fast`: the brief asked to wait for all checks so the digest lists every failure.
