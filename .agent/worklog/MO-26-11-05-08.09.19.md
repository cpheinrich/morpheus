# iOS CI runs the host's declared simulator lanes

## Why

A consumer (Evo) runs its iOS jobs on a VM pool spread over two hosts: one whose VMs hold two
booted simulators and one whose VMs do not. Its owner authorized two concurrent simulator lanes
wherever the VM can hold them and one lane elsewhere. `ios-ci` only took a fixed
`parallel-testing` / worker count from the caller, and a caller cannot know which host its job
lands on. History argues against a blanket two: a two-worker run on a 24 GB host without VMs
reached load 535 with ~4 GB of swap and timed out async tests (Evo, 2026-09-25), and an early
two-worker lane exposed short hard-coded waits (Evo, 2026-09-02).

## What changed

- `simulator-lanes-from-host` (boolean, default false). When true, the runner's
  `MORPHEUS_IOS_SIMULATOR_LANES` decides attempt 1: unset or `1` runs with Xcode's parallel
  testing off; `2` is `-parallel-testing-enabled YES -maximum-parallel-testing-workers 2`, Xcode's
  own parallel testing capped at two workers (a cap, so a small selection may use fewer); anything
  else fails before the pre-test script runs. The validation step refuses it beside
  `parallel-testing`.
- Retries are unchanged: serial, on the erased job simulator, so a parallel first attempt still
  retries only what failed on a clean device.
- `test-attempts.json` gains `simulatorLanes` when the caller opted in, and attempt 1's `timing`:
  its pre-test and xcodebuild intervals on the runner's monotonic clock, so a run's wall time
  never comes from a result bundle's summary. The run prints a notice naming the setting.
- Morpheus names no host. The value comes from the host's private runner configuration.

Tried and removed: explicit lanes, where Morpheus enumerated the selection, split whole classes
over the job's simulator and a clone, ran two serial xcodebuilds and merged the bundles. On the
consumer's fixed cohorts it gained on UI tests (604 s against 906 s) but not on units, and its
serial lanes (`-parallel-testing-enabled NO`) also kept Swift Testing from running tests
concurrently inside each process. Xcode's own parallel testing reached 570 s on the same UI cohort.
The owner chose native parallel testing for units and UI alike (2026-11-05), so the partitioning,
cloning, merging and duration hints are gone.

Considered: Morpheus reading the VM's CPU/memory and choosing for itself. Rejected: it hides a
capacity decision in a heuristic, and an operator qualifies a host by running it, not by its size.
