# iOS CI runs the host's declared simulator lanes

## Why

A consumer's iOS jobs can land on hosts of different sizes, and `ios-ci` only took a fixed
`parallel-testing` / worker count from the caller, which cannot know where its job lands. A blanket
two workers is unsafe: on a host too small for two booted simulators it has caused severe memory
pressure and timed-out async tests. The host that was qualified for two should say so, and every
other host should keep running serially.

## What changed

- `simulator-lanes-from-host` (boolean, default false). When true, the runner's
  `MORPHEUS_IOS_SIMULATOR_LANES` decides attempt 1: unset or `1` runs with Xcode's parallel
  testing off; `2` is `-parallel-testing-enabled YES -maximum-parallel-testing-workers 2`, Xcode's
  own parallel testing capped at two workers (a cap, so a small selection may use fewer); anything
  else fails before the pre-test script runs. The validation step refuses it beside
  `parallel-testing`.
- Retries are unchanged: serial, on the erased job simulator, so a parallel first attempt still
  retries only what failed on a clean device.
- `test-attempts.json` gains `simulatorLanes` when the caller opted in, and attempt 1's `timing`:
  its pre-test and xcodebuild intervals on the runner's monotonic clock, so a run's wall time
  never comes from a result bundle's summary. The run prints a notice naming the setting.
- Morpheus names no host. The value comes from the host's private runner configuration.

Tried and removed: Morpheus sharding the selection over two simulators itself (enumerate, split
whole classes, clone, two serial xcodebuilds, merge). Xcode's own parallel testing keeps one
enumeration, one result bundle and Swift Testing's in-process parallelism, so it replaced that
approach before review.

Considered: Morpheus reading the VM's CPU/memory and choosing for itself. Rejected: it hides a
capacity decision in a heuristic, and an operator qualifies a host by running it, not by its size.

## Verification

- `npx vitest run tests/ios-test-retry.test.ts tests/workflows.test.ts` — 226 tests, including attempt 1 with
  parallel testing capped at two workers and its recorded intervals, a serial retry on the erased
  device, one lane for unset/empty/`1`, refusal of `0`, `3`,
  `two`, `2x`, `-1` and `1 2` before any process runs, the caller's own settings kept when the
  opt-in is absent or false, the input's wiring, and the validation step refusing the combination.
- `npx tsc --noEmit -p .`.
- Real-VM qualification and acceptance run in the consumer's own repository.
