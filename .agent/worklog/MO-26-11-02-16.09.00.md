# Factory plugin is experimental and off unless a machine opts in

## Outcome

The repository now states, and tests, that Factory is experimental and off by default, and that
only a machine's own private `mode` turns it on.

- `release` (`experimental`, default `off`) in `plugins/factory/src/config.mjs` is the schema
  default and appears in `bridge.mjs doctor` as `factory: { status, mode, enabled }`. The Codex
  and Claude Code manifests start "Experimental, off until enabled on this machine."
- The per-machine override is the existing `config.json` `mode`. A separate `enabled` flag was
  considered and rejected: it could disagree with `mode`, and global `off` already wins over
  every project and task choice.
- `bridge.mjs enable` with no mode, or an unknown one, used to save `off` and print
  `{"mode": undefined}`, because the schema filled the default. It now refuses before writing.
- The installer's "never overwrite saved settings" rule is now `settingsMigration` in
  `install-lib.mjs`. Behaviour is unchanged: settings are written only to carry an old
  `codex-claude` install's choice to a machine with no factory config.
- README status section, both skills, architecture §18.0 and a decision entry explain
  `factory@personal` and `factory@factory-local`, that nothing distributes the plugin, that the
  coordinator stays the manager, and that automatic dispatch is not implemented.

Normal Morpheus distribution already left Factory alone: `src/` and `.morpheus/` named it nowhere,
and `npm pack` for `self install` ships only `dist` and one script. The new Morpheus test pins
both facts.

## Dead ends and notes

- This session runs as a delegated worker with `FACTORY_DELEGATED=1`, which makes both hooks exit
  before reading the mode. The hook test removes the variable; without that it passed vacuously.
- macOS has no `timeout`; the first mutation loop silently ran nothing. Rerun without it.
- The hook mutants (mode check removed) each started a bridge service from the worktree with a
  deleted temp home. Four such processes were found and stopped by exact PID. A regression of
  that guard would leave the same short-lived services (they exit after five idle minutes).

## Appendix A — tests

Focused scope: the plugin package changed, plus one Morpheus test and the manifest/CI-scope tests
that read the same paths. No shared core changed, so no full Morpheus suite was run locally.

```sh
pnpm typecheck                                   # pass
pnpm exec vitest run tests/factory-distribution.test.ts tests/package-manifest.test.ts tests/ci-scope.test.ts
                                                 # 3 files, 42 tests pass

(cd plugins/factory && pnpm test)                # 140 tests pass, including 6 in release.test.mjs
pnpm compile                                     # dist/ unchanged
pnpm morpheus pm index                           # unchanged
```

## Appendix B — mutation checks

Each mutant was applied, `tests/release.test.mjs` (or the Morpheus test) run, and the file
restored; a checksum confirmed restoration.

| Mutant | Caught by |
|---|---|
| `claude-hook.mjs` ignores `mode: off` | hooks on a fresh or disabled machine |
| `hook.mjs` ignores `mode: off` | hooks on a fresh or disabled machine |
| `settingsMigration` ignores an existing factory config | install or update never replaces a saved choice |
| `enable` mode guard removed | enable requires an explicit mode |
| `release.defaultMode` = `manual` | four tests |
| a Factory install path appended to `src/self.ts` | factory-distribution: never named by init, CLI, self or shims |
