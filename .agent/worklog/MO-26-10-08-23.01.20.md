# codex-claude: accept any explicit Claude model id

Issue [#368](https://github.com/cpheinrich/morpheus/issues/368). On 2026-10-08 Codex tried to
delegate a task to Claude Fable 5.1 (`claude-fable-5-1`) and the bridge refused with
"No approved subscription model mapping": `modelSelection` only launched models named in
`subscriptionModels`, whose default was `opus`, `sonnet`, `haiku`. The run went ahead only after
the host's bridge configuration was hand-edited to add the id, which is the workaround this
change makes unnecessary.

## What the allowlist was for, and what replaces it

The comment on the list said it stopped a moving `best` alias from selecting a paid-credit-only
model. That is a real hazard and is kept: `best`, `latest`, `default`, `newest` and `auto` are
refused by name, case-insensitively, on the override path and the `modelMap` path alike. Everything
else the list did was duplicate a check the Claude CLI already makes a release late. Verified on
Claude Code 2.1.284: `claude -p --model claude-nonexistent-9 …` returns at the first request with
`[claude-code:unrecognized_model]`, `is_error: true`, `api_error_status: 404` and
`total_cost_usd: 0`, and `src/service.mjs` already records a result with `is_error` as a failed run.
So the CLI is the availability authority and the bridge passes the id through.

Ids must match `^[a-zA-Z0-9][a-zA-Z0-9_.-]*(\[[a-zA-Z0-9]+\])?$`: plain characters, an optional
bracketed context suffix (`sonnet[1m]`), and never a leading dash, so a value can never be read
as another CLI flag. The old Zod regex for `subscriptionModels` allowed a leading dash.

Compatibility: `subscriptionModels` is now optional in the strict schema and ignored, so a saved
configuration (this host carried `["opus","sonnet","haiku","claude-fable-5-1"]`) keeps parsing and
round-tripping; `doctor` prints a note naming the key as deprecated.

Not changed: subscription-auth verification (`claude auth status` must report `claude.ai` /
`firstParty`), provider-environment stripping, the paid-overage stop, and explicit model/effort
overrides.

## Tests

- `plugins/codex-claude`: `node --test tests/config.test.mjs` (7 pass) and `pnpm test` (35 pass)
  after each commit; `node scripts/check.mjs` clean. New tests: an explicit id and a family alias
  pass through, a `modelMap` target does too, every moving alias is refused on both paths with the
  guard's own message, the leading-dash boundary (`-opus` refused, `claude-opus-5-5` accepted),
  `[1m]` accepted and malformed brackets refused, and a saved `subscriptionModels` key parsing
  without restricting the model.
- Not run: the repository-wide `pnpm test`/`typecheck`/`lint`, which do not cover the plugin
  (the plugin has no TypeScript and its own test runner).

## Installing on the host

The author's own bridge was running this change's parent task, so it was not reinstalled or
restarted here. Once this merges, from a clean Morpheus checkout:

```sh
cd plugins/codex-claude && node scripts/install.mjs   # copies to ~/plugins/codex-claude, installs, tests, registers
codex app-server daemon start
node ~/plugins/codex-claude/scripts/bridge.mjs doctor  # expect a notes entry about subscriptionModels
```

The `subscriptionModels` key can then be removed from `~/.local/share/codex-claude/config.json`.
