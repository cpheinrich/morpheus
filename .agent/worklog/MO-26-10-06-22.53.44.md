# MO-26-10-06-22.53.44 — simulator watchdog

- Trigger: Chris's Mac hit 100% disk (4.3 GB free). 85 GB of CoreSimulator devices, 30+ GB of
  `/private/tmp/EvoDerivedData-*` and 24+ GB of `iOS DeviceSupport`; a manual purge recovered
  ~110 GB. He asked for a watchdog that shuts down any simulator idle for 24 hours, in Morpheus,
  for every iOS project.
- Already existed: `qa preview ios` has a four-hour lease and its own supervisor; CI deletes the
  devices it creates. What was unbounded is everything else (Xcode runs, the Simulator MCP,
  hand-booted devices, XCTest clones, a dead supervisor), so this is a Mac-level sweep, not a change
  to either.
- **The first design would have failed, and measuring is what showed it.** Plan: idle = newest file
  mtime under the device's `data/`. Probed two real booted simulators: `logd`, IdentityServices and
  `xpc.activity2` write every minute on a device nobody touches, and Apple's own AppGroup
  (News widget cache, Intelligence embeddings) and PluginKitPlugin (chrono widget timelines)
  containers every few minutes. Any whole-tree or system-container signal makes every device look
  busy forever, so the watchdog would have shut nothing down. Replaced with writes inside
  *user-installed* apps only.
- Found the authoritative split by looking, not guessing: `xcrun simctl listapps <udid> | plutil
  -convert json` marks apps `ApplicationType = User` or `System` and carries `DataContainer` and
  `Bundle`. On the Evo QA sim that is 2 user apps and 39 system apps. A bundle-id prefix test
  (`com.apple.`) would have worked too, but listapps is what the OS says.
- Boot time: CoreSimulator does not record it. The device's own `launchd_sim` process exists from
  boot to shutdown and names its directory in argv, so `ps -axo etime=,command=` gives uptime and
  the device path in one line, for the default and XCTest sets alike. `etime` rather than `lstart`:
  no locale or time-zone parsing.
- Added a heartbeat because a person who only looks (scrolling, tapping through a list) writes
  nothing to any app. The QA overlay's `/api/touch` and `/api/key` already hold the UDID, so they
  touch `~/Library/Caches/morpheus/simulator-activity/<UDID>` at most once a minute, after
  validation, so a rejected request does not count.
- Rule kept from `qa preview`: only `simctl shutdown` of one named device. A test pins the verbs
  the sweep can emit. Anything unmeasurable keeps the device up.
- Rollout: explicit `enable`, not an install side effect (decisions: codebase-memory, auto-update).
  `self update`/`ensure` spawn the *installed* `morpheus simulator watchdog refresh`, not
  in-process code, because after an update this process is still the old code and would write the old
  agent definition. Considered default-on at install; rejected, noted in the PR as a one-line change.
- Verified against the real thing, not only the scripted suite (the standing rule on this machine):
  - `run --dry-run` on the two real booted devices: boot ages 41m and 50m, matching 22:25 and 22:15.
  - Real `listapps`, install signal and container walk with only the process age rewritten to 30h
    and the evaluation clock shifted +23.5h / +24.5h, dry-run: Evo kept ("wrote data 23h 39m ago",
    agreeing with an independent Python walk to ~20 s), Lakina "would shut down" at +23.5h and both at
    +24.5h. Never ran a non-dry sweep against a device in use.
  - Real shutdown on a throwaway device (`Morpheus Watchdog Test`, created and deleted for this), the
    sweep scoped to it by filtering `simctl list`: a 1h-old heartbeat kept it Booted; with none, the
    real `simctl shutdown` took it to Shutdown. Evo QA and Lakina QA stayed Booted throughout.
  - Real launchd agent, with temp paths so the real `~/.morpheus` and `~/Library/LaunchAgents` were
    untouched: `plutil -lint` OK, `launchctl print` loaded, RunAtLoad ran once with exit code 0
    under launchd's minimal PATH, quiet log empty, second `enable` reported current, `disable`
    unloaded and removed it.
- Mutation-checked both modules and the overlay wiring (12 + 12 + 3 mutants: boundaries, symlinks,
  system-app filter, dry-run, unmeasurable, consent bypass, bootout-before-bootstrap, the heartbeat
  and its position after validation). Every mutant was killed.
- Not done, on purpose: this frees RAM, not disk. Reclaiming the 2-5 GB of state per stale device is
  `erase`/`delete`, which this tool refuses to do; an expiry for long-idle devices is a separate
  decision.
- Gotcha for the next person: macOS has no `timeout`, so `timeout 60 npm search ... | python`
  silently produced empty input and a JSON error that looked like an npm failure.

## Review

A fresh reviewer read the diff, ran the focused tests and dry-runs against the two real simulators, and compiled to compare the committed dist. No substantive findings; five minors, all fixed. The most useful was R1: real simctl errors put the cause on a second line and the code read only the first, so the already-shut-down race handling could never fire, which the author's one-line mock had hidden and the reviewer caught by running read-only simctl against a real Shutdown device. The author confirmed it on the real tool, fixed all five, added suites for the previously untested update/refresh and nudge glue, and mutation-checked the fixes (18 mutants killed). Cleared.
