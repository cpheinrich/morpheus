# Waive the review floor for trivial diffs

Six independent reviews of the same five-line workflow `if:` change (evo#412,
lakinacapital#509, kairos#70) took 21–30 s and were all clean. The 30-second normal/high-risk floor
refused them, and #361's authorized-follow-up rescue did not help because the authorized turns
(24.5 s, 24.8 s) were under the floor too. Chris chose option A: waive the floor for trivial diffs.

## The predicate

`trivialDiff(root, base, covered)` in `src/review/local.ts`, called by `verifyReviewRecord` only —
so CI's `check pr` and `review validate` compute it from Git and no record field can claim it:

- `git diff --numstat --no-renames base covered` — the whole reviewed range, including late
  corrections. A trunk merge inside the range only adds lines, which errs toward keeping the floor.
- Not counted: `.agent/worklog/` and `hq/product/` — the task's own records.
- Test-named files (`*.test.*`, `*.spec.*`, `test_*.py`, `*_test.py|go`, `*Test(s).swift|kt|java`)
  counted separately: at most `TRIVIAL_DIFF_MAX_TEST_LINES = 40`. Directory never makes a test.
- Everything else: at most `TRIVIAL_DIFF_MAX_LINES = 20` added plus removed, and every file must be
  configuration, workflow or prose by extension (`md mdx txt yml yaml json jsonc toml`).
- Any binary row makes it non-trivial.
- Every turn (initial and follow-ups) must be measured above zero, or the waiver is not consulted.

When trivial, the floor check is skipped; everything else — resumption of an incomplete initial
turn needs `humanAuthorization`, ceilings, same reviewer, finding resolution — still applies. When
not trivial, the floor error now ends with the measured counts, so a refusal says why.

## Choices and dead ends

- **Chris's proposed 20 lines counting everything would not have covered the motivating PRs.** Evo
  #412 was 5 workflow + 2 docs + 19 test lines (26); kairos #70 was 5 workflow + 27 test lines (32).
  Rather than raise one number until they fit, tests got their own cap: they change no shipped
  behaviour and CI runs them, but a large test rewrite still keeps the floor.
- **Source files keep the floor at any size.** "Keep the floor for anything with real logic" is
  implemented by extension, not by line count: a one-line `.ts` change still needs 30 s. Workflows
  are eligible because the motivating changes were workflow conditions.
- **`dist/` is counted, not excluded.** Excluding generated output would trust every project to
  verify its mirror; in Morpheus counting it only doubles a change that is already small.
- **Lazy, and only under the floor.** The Git measurement runs only when a turn is under 30 s at
  normal/high risk, so no existing record pays for it; a range Git cannot measure keeps the floor.

## Test plan

`tests/local-review.test.ts` › "the floor is waived for a trivially small change": exactly 20 and
21 non-test lines; added+removed counted together (10-line rewrite = 20, plus one = 21); 40 and 41
test lines; worklogs and roadmap records not counted while `.agent/decisions.md` and `dist/` are; a
one-line `.ts` and an extensionless script keep the floor; binary refused; a late source correction
in `reviewed..covered` counts; above the limit the 29,999/30,000 ms boundary holds; small risk
unaffected; the evo/kairos record shape (incomplete 22.1 s initial, authorized 24,492 ms clearing
turn) accepted when trivial, refused when a source file is added, and still refused without
authorization. Full `pnpm test` (2028 tests), `pnpm typecheck`, `pnpm compile`, `pm index`.
