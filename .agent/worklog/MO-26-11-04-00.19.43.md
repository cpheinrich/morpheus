# Release preflight accepts pinned reviewed sources contained in main

## Outcome

`.github/workflows/release-preflight.yml` no longer requires the release source to be main's
current head. When main has moved, it asks GitHub's compare `source...main` and requires `ahead`.
Every other check is unchanged: `refs/heads/main`, a clean exact checkout of `github.sha`, and a
merged PR into main whose merge commit is that SHA. The interface is also unchanged: no inputs, no
secrets, `sha` output. The tests now execute the real script against a fake `gh` that answers only
the exact routes, for 13 behaviours. Architecture §18.2 and the preflight contract paragraph, plus
a new decision, record the change.

## Scope history

The first handoff also asked for Claude support in the Factory unattended gateway worker. The
coordinator withdrew that before any Factory edit: runtime repair stays on the existing Codex
gateway path. No Factory source was changed. The item's title and body were rewritten around the
final scope, and the ID and claimed branch were kept.

## Design choices

- **No `source-sha` input.** All three callers verify `github.sha`: Evo `ios-delivery` and
  `ios-full-verification`, and Morpheus `ios-nightly-build`. Evo's production verifies the
  workflow/control revision; its promoted app source passed this gate in its staging run.
  Architecture also states the preflight "accepts no caller-selected source". Ancestry alone fixes
  the observed failure, a dispatched run that waited while main moved, without widening the gate.
- **Compare API, not `git merge-base`.** The checkout is depth 1. Fetching main's history would add
  shallow-ancestry hazards (#445) and a credentialed fetch. One read-only API call answers the
  question.
- **Compare against the resolved main SHA, not the branch name.** This avoids tag/branch name
  ambiguity and checks exactly the main the step read.
- **Short-circuit at head.** A source equal to main makes no compare call, so the common case
  behaves exactly as before.
- **Fail closed.** `identical` with different SHAs, an empty status, a failed `gh` (via `set -e` in
  the command substitution) and a non-40-lowercase-hex main SHA all refuse.
- **The merged-PR binding is what keeps ancestry safe.** A feature-branch commit merged with a
  merge commit is reachable from main. It still fails, because no merged PR names it as its merge
  commit. A test pins that main's head PR cannot vouch for an ancestor.

## Checked and left alone

- `src/firebase-release/run.ts` (the shared Firebase action) has its own current-main check. Evo
  uses its own local `firebase-deploy` action, so this change does not cover that. It is out of
  scope here; flag it if the Evo controller sees rules deploys refuse as main advances.
- The `src/init/templates.ts` comments say "exact-main preflight". That is still accurate (an exact
  SHA on main), so the scaffold template was not touched.

## Mutation check

Run outside CI by editing the workflow and re-running the focused tests. Each mutant failed:
swapped compare order (3 failures), reject only `behind` (4), no ancestry branch (5), main-SHA
shape `.` (2), always compare (1), any PR SHA (2). The workflow was restored from a backup and
the diff re-inspected.
