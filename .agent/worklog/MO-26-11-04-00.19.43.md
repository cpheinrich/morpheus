# Release preflight accepts pinned reviewed sources contained in main

## Outcome

*The final scope is the opt-in described under "Final scope after turn 4" below. This section records the first implementation, which applied ancestry to every caller.*

`.github/workflows/release-preflight.yml` no longer requires the release source to be main's
current head. When main has moved, it asks GitHub's compare `source...main` and requires `ahead`.
Every other check is unchanged: `refs/heads/main`, a clean exact checkout of `github.sha`, and a
merged PR into main whose merge commit is that SHA. The interface is also unchanged: no inputs, no
secrets, `sha` output. The tests now execute the real script against a fake `gh` that answers only
the exact routes, for 13 behaviours. Architecture §18.2 and the preflight contract paragraph, plus
a new decision, record the change.

## Scope history

The first handoff also asked for Claude support in the Factory unattended gateway worker. The
coordinator withdrew that before any Factory edit: runtime repair stays on the existing Codex
gateway path. No Factory source was changed. The item's title and body were rewritten around the

## Design choices

- **No `source-sha` input.** All three callers verify `github.sha`: Evo `ios-delivery` and
  `ios-full-verification`, and Morpheus `ios-nightly-build`. Evo's production verifies the
  workflow/control revision; its promoted app source passed this gate in its staging run.
  Architecture also states the preflight "accepts no caller-selected source". Ancestry alone fixes
  the observed failure, a dispatched run that waited while main moved, without widening the gate.
- **Compare API, not `git merge-base`.** The checkout is depth 1. Fetching main's history would add
  shallow-ancestry hazards (#445) and a credentialed fetch. One read-only API call answers the
  question.
- **Compare against the resolved main SHA, not the branch name.** This avoids tag/branch name
  ambiguity and checks exactly the main the step read.
- **Short-circuit at head.** A source equal to main makes no compare call, so the common case
  behaves exactly as before.
- **Fail closed.** `identical` with different SHAs, an empty status, a failed `gh` (via `set -e` in
  the command substitution) and a non-40-lowercase-hex main SHA all refuse.
- **The merged-PR binding is what keeps ancestry safe.** A feature-branch commit merged with a
  merge commit is reachable from main. It still fails, because no merged PR names it as its merge
  commit. A test pins that main's head PR cannot vouch for an ancestor.

## Checked and left alone

- `src/firebase-release/run.ts` (the shared Firebase action) has its own current-main check. Evo
  uses its own local `firebase-deploy` action, so this change does not cover that. It is out of
  scope here; flag it if the Evo controller sees rules deploys refuse as main advances.
- The `src/init/templates.ts` comments say "exact-main preflight". That is still accurate (an exact
  SHA on main), so the scaffold template was not touched.

## Independent review, turn 1, and the response

Fresh reviewer session `d2d4b2ff-27d8-45c8-9a76-2163b379ed74` reviewed `89f2f1b7` at high risk
and returned **blocked**. Root measured the turn by clock at 178,450 ms, from the
`factory_delegate` start to the terminal `factory_wait` return (2026-11-04T08:28:05.635Z to
08:31:04.085Z).

- **F1 (substantive): accepted and fixed.** `ios-nightly-build` (used `@main` by kairos, pace and
  lakinacapital) treats a baseline that is not an ancestor of the run's SHA as "build
  conservatively". Before this PR, preflight's current-head equality refused a re-run of an older
  night. Without it, re-running night A after B uploaded would ship A under a higher build
  number. Root selected the reviewer's option (a): the decision step now skips, as superseded, a
  run whose SHA is a strict ancestor of the last successful upload.
  - **Forced runs too.** The scaffolded caller forces every `workflow_dispatch`, and a re-run of
    a forced manual dispatch is the same hazard. Forcing still skips the watched-path diff.
  - **Unchanged cases.** Equality (the uploaded commit itself), unrelated history, and an
    unreadable or unavailable baseline keep their earlier outcomes. A forced build is never
    skipped on a baseline it could not read.
  - **Tests.** An executed real-script test covers each case.
  - **Mutation check.** Mutants dropping the unforced check, the forced check, or the equality
    boundary, or swapping the ancestry order, each failed. A separate `cat-file` guard inside the
    helper was an equivalent mutant (`merge-base` already fails on a missing commit), so it was
    removed.
  - **Docs.** `architecture.md` now describes the nightly behaviour and moves the stale-run
    protection to callers; the decision and acceptance were updated.
- **F2 (minor): fixed.** Executed fixtures now cover a non-main ref and a mismatched checkout
  (both refuse before any GitHub call). Mutants dropping either guard failed.

## Late correction after turn 2: F3

CI passed 14 checks at `e9527fe8`. Root then held the merge after finding a continuation of F1,
restored the draft and removed `agent-reviewed`. The same reviewer, `d2d4b2ff`, took turn 3 at
`e9527fe8` (clock 177,577 ms) and returned **blocked** with F3 (substantive).

F3: when the Actions API cannot be read (HTTP 502) but git refs, compare and pull requests answer,
the decision step's "building conservatively" fallbacks passed a re-run of an older source A
(build=true, forced or not), and the relaxed preflight admitted A because main B contains it. The
old preflight refused. The reviewer showed this with an executed fixture combining the real
decision step and both preflight versions. The turn-1 test had codified that outcome.

Response, choosing root's minimal local guard over a caller opt-in:
- **The guard.** `require_current_main` runs on each branch where the baseline cannot prove age,
  forced or not:
  - the history is unreadable;
  - no upload is found;
  - the upload commit is unavailable;
  - the baseline is not an ancestor of the run (unrelated or diverged).

  Forced runs take it on any failed baseline read. It reads main fresh through
  `/git/ref/heads/main`, not the checkout's `origin/main` snapshot. It refuses (exit 1) when main
  cannot be read, is not 40-hex, or differs from `CURRENT_SHA`. Main's head keeps the earlier
  conservative build.
- **No new knobs.** No input, option or framework was added. The forced path now also checks for
  an available baseline commit before trusting it.
- **Tests.**
  - The turn-1 test lost its unknown-history assertions, which encoded the bug.
  - A new test covers every unknown baseline, forced and unforced: head builds, an older commit
    refuses, and an unreadable or malformed main refuses. Unrelated history builds only at head.
  - A combined test runs the real decision step, then the real preflight with the checkout
    detached at the source, through a fake gh: Actions routes from fixtures, main from a fixture,
    compare by real git ancestry, and a merged PR for every commit. An older source never
    uploads, whether the Actions API is down, history is healthy, no upload exists yet, or main
    is unreadable. Main's head and a newer pinned source still ship.
- **Mutants.** Each of these failed the suite: a no-op guard (2 failures, including the combined
  test), no head comparison, no 40-hex check, and removing the guard from each branch (forced,
  unreadable, empty, unavailable, unrelated and forced-unrelated).
- **Docs.** Architecture, decisions, acceptance, the roadmap and the `force-build` description
  were updated.

Turn 2's clearance of `6feca934` is kept as history; it does not cover this code.

## Final scope after turn 4

The same reviewer took turn 4 at `e75b6918` (clock 167,525 ms) and **cleared** F3. It raised I1
(incidental, non-blocking): "re-run failed jobs" reuses a successful `changes` job's `build=true`.
If night A's preflight failed in its first attempt, re-running it after B uploaded meets the relaxed
check, which admits A where the old head check refused it. The test and upload failure variants
pre-date this PR.

Root treated the PR-caused variant as a substantive acceptance gap and chose the earlier, simpler
alternative over another layered fix. The reviewer's verdict and severity are recorded as given;
no blocked finding was invented.

- **The preflight.** `release-preflight.yml` gains one `workflow_call` boolean,
  `allow-pinned-source`, defaulting to false. When main differs from the source and the rendered
  value is not exactly `true`, it refuses with the original "is not current origin/main" message
  before any compare or pull-request call.
  - Opted in, the earlier ancestry path applies unchanged.
  - The 40-hex main check refuses in both modes.
  - There is no caller-selected source, and a manual dispatch has no inputs, so it keeps the
    default.
- **The nightly.** Every `ios-nightly-build.yml` change since the base was reverted (the file is
  byte-identical to `fc17447`), along with its tests and docs. Its existing conservative and force
  behaviour is safe again because its preflight call renders the default.
- **Tests.**
  - The executed preflight fixtures now cover head passing in every mode.
  - The default refuses a moved-past source for an absent, empty, `false`, `TRUE` or `1` value,
    with no compare call.
  - Opted in, the four non-ancestor statuses refuse, a failed compare refuses, an unreadable main
    refuses in both modes, the PR binding applies, and the F2 ref and checkout refusals stay.
  - A regression renders `ios-nightly-build`'s actual preflight call and runs the real script for
    a re-run with a cached `build=true` after main moved; it refuses. No other workflow here opts
    in.
- **Mutants.** Each of these failed the suite: default on, any non-empty value enabling it, the
  opt-in ignored, default true, no ancestry proof, a swapped compare, no main shape check, any PR
  accepted, and the env hard-wired to true.
- **Docs and records.** Architecture (the Evo preflight step, the block/warn table and the
  preflight contract), the decision entry, acceptance and the roadmap title and approach were
  rewritten around the opt-in. The nightly architecture paragraph is restored to the base.

The pre-existing test and upload re-run variants of I1 are unchanged from the base and outside this
PR's causal scope. Root acknowledges them; no ticket is opened here. No turn covers this new source
yet; it needs turn 5.
