# Factory delegates through a provider-neutral tool the root chooses to call

## Outcome in progress

Automatic prompt dispatch has been removed from both host plugins. Claude retains a settings-only
`UserPromptSubmit` recorder because its `SessionStart` payload can omit the live permission mode;
that hook returns no model context and never launches work. Codex and Claude now expose the same
six `factory_*` lifecycle tools. The MCP host injects a verified root identity,
run controls are ownership-scoped, the first successful primary launch pins the worker route, and
fresh worktree conversations cannot overwrite the primary provider session.

The earlier design critique changed the initial proposal in four material ways: provider/gateway
identity is sticky but provider conversations never cross worktrees; a failed preflight cannot
bind; post-bind provider preferences conflict rather than reroute; and installed qualification
must invoke a Factory tool and guard, not merely list tools. The implementation keeps the old
provider-specific tools as compatibility aliases, but scopes their run controls through the same
root-ownership checks.

## Dead ends and corrections

- The first focused run had ten failures, all but one obsolete expectations from automatic-mode
  semantics and route-key names. The real defect was fresh `needs_input` continuation: it could
  not resume without being treated as a primary run. Continuation now inherits the originating
  run's `fresh` identity and can resume its saved provider conversation without changing the
  primary checkout or session.
- The initial test command was run from the repository root and found no package-local test path;
  subsequent commands used `plugins/factory`.
- Codex initially could not launch the installed MCP server because its plugin host does not expand
  raw `${CLAUDE_PLUGIN_ROOT}` arguments. The launcher now uses the documented `${PLUGIN_ROOT}` via
  a shell wrapper, passes `CODEX_THREAD_ID`, and opts the six tools into host approval.
- Claude print-mode (`claude -p`) loads MCP tools but did not execute the installed session hook in
  these isolated invocations, so the bridge correctly refused unverified permissions. Interactive
  Claude did execute the hook, exposing a second defect: its hook payload omitted `permission_mode`.
  Claude's transcript records the live mode as a typed top-level field, so the recorder now accepts
  only a recognized value from that field and ignores prose. Unknown modes still fail closed.
- A candidate install initially failed its own probe because the probe prohibited every prompt hook.
  It now distinguishes automatic dispatch from Claude's exact settings-only recorder. The rerun
  passed all 152 tests and installed cleanly.
