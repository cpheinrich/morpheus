# Profile agent sessions from local transcripts

`morpheus profile extract` streams `~/.claude/projects/**` (subagent transcripts attributed to the
parent session through `<session>/subagents/agent-<id>.jsonl` and its `.meta.json`) and
`~/.codex/sessions/**` into JSONL `session` and `span` rows. `morpheus profile report` sums them by
phase, repository, role, model × effort, first-turn context (p50/p90), slowest and most-repeated
commands, and subagent share. It has no new dependencies; `ccusage` was considered and is recorded
in `.agent/decisions.md`.

## What the data looked like, and what that changed

- **Claude repeats `usage` on every content-block line of one response.** A response with two tool
  calls spans several lines sharing `message.id`, and each line carries the full usage. Counting
  per line over-counts tokens two to five times. Usage is counted once per message id. Recorded in
  `learned.md`.
- **Subagent lines carry the parent's `sessionId`.** The subagent's identity comes from the file
  name and the meta file, so subagent rows are `<parent>:<agentId>`.
- **Codex re-emits identical cumulative `token_count` events.** A response is counted only when
  `total_token_usage` moves. Codex `input_tokens` include cached tokens, so the cached part is
  split out to match Claude's shape.
- **Codex's `exec` custom tool wraps JavaScript.** The reliable per-command record is
  `event_msg/item_completed` with a `CommandExecution` item and a `{secs, nanos}` duration, not the
  call input. Note that `started_at_ms` equals `completed_at_ms` on these items.
- **Truncating first made "repeated commands" useless.** In a worktree, every command opens with
  the same 80-character `cd /…/worktree &&`, so the truncated text was all prefix. `displayCommand`
  strips leading `cd`/assignment prefixes before truncating.
- **One `mcp__ccd_pr__bind_pr` call took 46 hours.** It came from a resumed session, not work, and
  on its own it made `gh` the largest phase. Tool results more than 4 hours late
  (`MAX_CREDIBLE_SPAN_MS`) are now neither busy time nor phase time, and the report names them.
- **Repository attribution needed worktree rules.** `.claude/worktrees`, `local/worktrees`,
  `.morpheus-worktrees/<repo>-<12hex>`, `.<repo>-worktrees`, `.codex/worktrees/<hash>/<repo>`, and
  Codex desktop chat folders (`(chat)`) each have their own rule. The registry roots fold
  subdirectories into their project.

Decisions taken without asking, all reversible:

- Two phases were added beyond the brief: `wait` (Monitor, ScheduleWakeup, sleep, Codex `wait`) and
  `context` for reads of `.agent/`, `hq/team/` and `AGENTS.md`.
- Active time caps idle gaps at 5 minutes rather than dropping them.
- Item ids are emitted in canonical upper-case form.
- The model × effort time column attributes each session to its most-used pair.

## Independent review

A fresh reviewer, a Claude Code general-purpose subagent with no inherited history, reviewed
fd0905c at normal risk. It ran the focused suite and the CLI against the real transcripts, and
checked the parser's assumptions against real data: no message id spans files, main files have no
sidechain lines, and forked Codex rollouts replay no earlier timestamps.

It raised these findings:

- **S1 (substantive, conditionally cleared).** `--repo` also matched the cwd path, so
  `--repo morpheus` pulled in 11 evo and 4 scratch sessions through `.morpheus-worktrees` paths.
- **M1 (minor).** Credential masking missed URL userinfo, header values, `-u user:pass` and
  `mysql -p`.
- **M2 (minor).** The docs overstated the privacy claim, because heredoc bodies could appear in
  commands.

All three were fixed in 515708b. That commit also regenerated `dist/profile/report.*`, which
fd0905c had left stale. That file was outside the S1 condition, so the same reviewer spent one
follow-up turn on it as a late correction. It cleared everything, with no new findings.

The reviewer also noted two incidental, non-blocking follow-ups:

- Time spent waiting on a person or a permission prompt (under 4 h) lands in phase `other` and
  active time.
- `--since` accepts impossible dates such as `2026-02-30`.

These are listed as follow-ups in the PR. They are not recorded as deferred findings, because
filing their roadmap item on this branch after coverage would invalidate the review.
