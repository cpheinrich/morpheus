# Complexity baseline refactor

## Ask

Bring every first-party function to cyclomatic complexity 15 or below. The scope covers:

- runtime code in `src/`, `scripts/`, `plugins/` (Factory included), the maintained `.github`
  actions and `qa/evals`
- browser scripts embedded as strings
- executable test-support implementations: fake services, command runners and fixture scanners

Change no behaviour. Ship as a held WIP draft PR, with no merge and no hard complexity gate.
Cognitive complexity is advisory. Root added the test-support class on 2026-11-06; the earlier
224-target inventory is now historical.

## Result

- All **231** targets are now at CCN ≤15:

  | Class | Targets |
  |---|---|
  | Runtime analyzer rows | 219 |
  | Executable test-support functions | 7 |
  | Embedded browser-script functions | 5 |

  The 7 test-support functions are `FakeRepo.command`, the public-fixture `findings` scanner,
  `FakePaperclip.handle`, `FakeGitHub.request`, the codebase-memory fake runner, the
  pilot-enrollment fake server and the self-install runner.
- The final canonical scan was taken at the shared pin 484bbd0 with the `outside` extension.
  It reports 0 runtime rows over 15 and 0 module bodies over 15, with no unmeasured files and no
  suppression directives.
- 86 runtime functions still exceed cognitive 15. That metric is advisory, so it was not a target.
- The official `morpheus complexity check --all` now reports 0 CCN rows anywhere: 15,013
  functions in 596 files.
- Generated `dist/` stays outside the measured scope; it was recompiled here. No test assertion
  was weakened, and no suppression or exception was added.
- Method: no thresholds, ignores or forgive directives. Each change extracts real steps. Error
  messages, the order of side effects and external calls are unchanged.

## How it was verified

- Focused tests ran per family, and all pass. The full local suite was not rerun; its single
  allowance had already been used, so CI runs the full suite.
- Every major dispatch, invariant and accounting path also had an **old-vs-new differential**. In
  most families this was a fuzz or scenario harness; a few also had a mutation check. Appendix A
  lists them.
- A function-inventory audit compared base and head for every changed file (Appendix B). It caught
  two accidental drops before commit.

## Needs reviewer attention

1. `ci_trace_stage.py` pins the digest of `stage.py` (`CORE_SHA256`). The refactor changes that
   file, so the pin moves to its new digest. This follows the same companion-pin pattern as
   a58f02bd.
2. `qa/evals/workflow-repair` campaigns freeze the digests of their collector and scorers. A
   campaign frozen before this change must be scored with its saved `frozen-*.py` copies, because
   the new files will refuse it.
3. Some paths were checked by review and syntax only, never run:
   - the iOS preview start path
   - the Factory installer's activation and swap (a real install changes the machine)
   - `scripts/paperclip-hq/native.mjs`, which can spend native allowance
4. The Playwright QA specs passed 20/20 on a cached Chromium build, before and after. WebKit was
   not installed locally, so CI covers it.
5. Root coordinated a fresh independent review, recorded below. It cleared the change with no
   findings. The draft still carries no labels and stays held for Chris.

## Dead ends and lessons

- The first inventory, 209 targets, was incomplete. The scanner lacked the `outside` extension, and
  pin 7f14ea5 hid the functions in `src/profile/codex.ts`. Corrected to 224.
- Replacing a slice up to the next definition can silently delete whatever lies between. That
  happened twice and the inventory diff caught both. Run that diff before every commit.
- A safety review rightly refused one fixture `rm -rf $T/home`. The installer differential was
  rewritten with a contained `TemporaryDirectory`.
