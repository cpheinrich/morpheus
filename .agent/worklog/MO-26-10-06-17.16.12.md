# MO-26-10-06-17.16.12 — Review records accept a summary that contains code spans

## What happened

The GitHub Manager's first run on Morpheus (ops run 37549663365) gave PR #327 a manager review: it
merged main, reviewed the change, fixed one substantive finding and wrote a
`morpheus-manager-review` record with its summary repeated word for word. Apply then escalated:
`the manager review record does not validate: repeat the manager review summary as a visible
paragraph outside the JSON block`.

Reading the worklog through the API settled it: the paragraph and the JSON summary were
identical, and both contained backticks. The check ran `visibleProse(page).includes(summary)`.
`visibleProse` strips inline code spans, which is right for waivers (a backticked example must not
waive a check) and wrong here: it removed the spans from the page and left them in the summary.

## What shipped

`visibleText` (in `src/check/pr.ts`) removes only HTML comments and fenced blocks. Both
`parseReviewRecord` and `parseManagerReviewRecord` use it. The ordinary record had the same latent
bug; authors had been avoiding it by not writing backticks in summaries.

## Evidence

- `tests/local-review.test.ts` and `tests/manager-review.test.ts`: a summary naming a path in
  backticks validates; the same summary hidden only in an HTML comment or a fenced block is still
  refused.
- Live verification: after this merges and the operations pin moves, PR #327's existing record
  should validate on the manager's next look.

## Independent review

One fresh reviewer session reviewed 8f8335d at normal risk and found nothing substantive: only the two summary checks changed, every other visibleProse caller behaves as before, and a summary hidden in a comment or fence is still refused. Its minor finding, a missing tilde-fence test, was fixed by the author; two pre-existing gaps in the regex-based check are tracked as MO-26-10-06-17.48.00.
