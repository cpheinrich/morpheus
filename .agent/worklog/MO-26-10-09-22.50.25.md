# iOS QA pin placement and scrolling

## Cause

The overlay stored viewport fractions at placement but captured the only PNG at Send. A later
native scroll changed the content under the stationary indicator, and agents then received a
frame from a different moment. The shared comment schema had no screen identifier.

## Approach

The simulator already streams native accessibility element IDs and frames. The overlay now
attaches a marker to a nearby element's frame, moves it as that frame moves, and hides it off
screen or on another screen. Each pin keeps its original coordinates, placement PNG, and
screen ID. A named accessible `*Screen` ID from the raw native tree takes precedence; otherwise
`ax:<landmark ID>:<digest>` is a fallback candidate from the first two app-specific accessibility identifiers. The
simplified serve-sim stream omits screen-sized SwiftUI roots: live Evo Today had `todayScreen`
in the raw tree but only `mainNavigationVisualBounds` first in the stream. Morpheus now emits
the screen ID and normalized element positions from the same raw native tree in each
accessibility event. This removes the separate screen-ID read that could label a placement
with the next screen's ID, and it allows progress animations without image-equality gating.
At placement, the overlay now captures a native screenshot bracketed by two native AX snapshots;
it uses that image and ID together and shows the captured image beside the comment editor.
A changed or unavailable ID or missing placement PNG blocks Send. The anchor under the click
must keep the same element ID and position across the click snapshot and both capture snapshots;
otherwise the operator must replace the pin. The server holds the fallback identity through
a vertical drag, so recycled lazy rows do not change an unchanged screen's ID; a later tap
permits a new candidate to identify navigation. Anonymous AX tree paths are not anchors,
because lazy rows can reuse a path and frame for different content. A pin without a nearby
stable named element is rejected instead of remaining fixed over unrelated content. Browser
IndexedDB preserves unsent placement PNGs across reloads;
sessionStorage continues to preserve the small pin metadata and draft.

No new package: the existing serve-sim accessibility stream, browser EventSource, canvas and
IndexedDB cover the behavior. The shared batch schema and agent guide carry the same evidence
for Codex, Claude and other responders.
