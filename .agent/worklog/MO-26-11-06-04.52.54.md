# Adopt the Lizard JSX attribute fix pin

## Ask

Move the shared analyzer pin from `484bbd0` to the root-verified `3b53c11` (tag
`morpheus-analyzer-2026-11-06-tsx`), which fixes JSX spread attributes and hyphenated attribute names
inside children. Extend the existing pin, canary, tests, docs and `dist/` only: no new tool, catalog
or gate. Keep the Swift and template-literal canaries, the wheel hashes and the Python floor.

## What changed

- `src/complexity/pin.ts`: commit `3b53c116fe93aebea86f44cd5d001813cfc13401`, reachable from the
  annotated tag `morpheus-analyzer-2026-11-06-tsx` (object `f47acdc9…`, checked with
  `git ls-remote`). Wheels and the 3.9 floor are unchanged. Older tags still resolve as before
  (`-ts` → `484bbd0`, the plain tag → `7f14ea5`). `CANARY_EXPECTED` gains eight rows. A row can now
  carry `lines: [start, end]`.
- `src/complexity/lizard_runner.py`: the root's `attributes.tsx` repro (sha256 `ee2a5bbd…`, the
  same bytes as `attributes.jsx`) is one `ATTRIBUTES` string, measured as `attributes.tsx` and as
  `attributes.jsx`.
- `src/complexity/install.ts`: `canaryMismatch` (now exported) also compares line bounds when a row
  records them, and names the bounds in its refusal.
- `tests/complexity-check.test.ts`: the canary list; a unit test that a bounds-only change (Grid
  ending at 12, not 11, with the same CCN and cognitive score) is refused; and a test that installs
  `484bbd0` through the real installer and asserts its exact refusal. The `7f14ea5` refusal test
  stays.
- `docs/runbooks/complexity.md`: names the current pin, the attribute fix, the known remaining
  limit and both older tags. `dist/` is recompiled.

## Result

- The new pin installs and passes `complexity install --check`. The canary measures exactly the
  contract's rows for `.tsx` and `.jsx`: Row 1–3 CCN 1, Grid 4–11 CCN 3, Card 12–14 CCN 2, after
  15 CCN 2.
- `484bbd0` is refused: "canary attributes.tsx Grid measured CCN 4, cognitive 3, lines 4-15". Run
  directly, it also measures no `Card` and no `after`. Every older canary row (JS, Swift, TSX, TS)
  measures the same on both pins.
- Mutation check: when the bounds comparison is removed from `canaryMismatch`, the bounds test
  fails.
- **Evo, frozen `ab95f3d`: the findings are unchanged, and 23 TSX files measure differently.** Both
  runs exit 0 with 207 identical findings and 0 unmeasured files. Measured function rows go from
  20,191 to 20,204. Every difference is in `apps/web` `.tsx`. The files I checked against the source
  are now more correct:
  - The old pin missed `BodyMetricsForm`, `SexField` and `Outcome` entirely.
  - It ran `unitButton` and `HeightFields` over neighbouring code.
  - It counted words in JSX prose ("if you want…") as branches. For example, `Bpc157SuppliersPage`
    was CCN 7 and is now 1; every conditional in that page sits in a `.map` callback.
  - **`BodyMetricsForm` now measures CCN 15**, exactly Evo's enforce limit. It still passes, but its
    next added branch fails. Appendix A has every delta.

## Known limits

- An element used directly as an attribute value without braces (`icon=<i />`) still loses the
  functions after it. This is rare syntax, and the contract kept it out of this repair. The runbook
  says so, and this change does not claim a perfect parser.
- The root's graph project predated the complexity modules, so I read the source directly.

## Open questions

- `BodyMetricsForm` in Evo is now at CCN 15. That is a pass today, but it gives no headroom. This is
  for Evo's owner to note; no change here.
