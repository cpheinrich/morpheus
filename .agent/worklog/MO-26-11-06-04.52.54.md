# Adopt the Lizard JSX attribute fix pin

## Ask

Move the shared analyzer pin from `484bbd0` to the root-verified build that fixes three JSX
attribute forms inside children. Extend the existing pin, canary, tests, docs and `dist/` only: no
new tool, catalog or gate. Keep the earlier canaries, the wheel hashes and the Python floor. The PR
first adopted `3b53c11` (spread and hyphenated attributes). The same PR then moved to the final
`541623c`, which also handles a valueless attribute after a braced one
(`margin={{ top: 6 }} accessibilityLayer`). Lakina reported over-15 rows that the root traced to
parser overruns, and fixing the consumer to suit the parser was rejected.

*Corrected after review (F1, N1).* An earlier version of this entry said that form made Lakina's
"`Portfolio/Company`" measure CCN 17 when the true value is 14. That conflated two functions and
claimed a fix that did not happen:

- `PortfolioValueChart` (`apps/web/app/hq/PortfolioValueChart.tsx`) is now bounded correctly.
- `CompanyDetail` (`apps/web/app/hq/SaasBottomUp.tsx`) still overruns at `541623c`, through a
  different, unidentified JSX form. See Known limits.

## Known limits

The parser is not perfect. These forms are still misread:

- An element used directly as an attribute value without braces (`icon=<i />`) loses the functions
  after it.
- A valueless attribute literally named `extends` is read as a TypeScript type parameter.
- A valueless attribute is recognised only where an expression is expected. After a name, `)` or
  `]`, `<` keeps its comparison or type-argument meaning.
- **Another JSX form is still unidentified.** It overruns Lakina's `SaasBottomUp.tsx`
  `CompanyDetail` (above), and the root is investigating it.
  - It is not the canary's valueless form. Measured alone, `CompanyDetail` is bounded correctly;
    the overrun appears only once the real `SaasBottomUp` body follows it. A stray `pct` row at line
    139 suggests the reader misreads an earlier construct.
  - These records describe what was measured at `541623c`. They do not claim the parser is
    correct everywhere.
- I read the source directly, because the root's graph project predated the complexity modules.

## Open questions

- Evo's `BodyMetricsForm` is at CCN 15 at `541623c`, exactly the enforce limit, so it has no
  headroom.
- Lakina's `CompanyDetail` false overrun needs the unidentified form found and fixed in the fork,
  followed by a later pin move. This PR does not fix it.
