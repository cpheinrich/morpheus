# MO-26-10-09-00.23.41 — Preview URL without a Deployments permission

## What happened

The first run after MO-26-10-08-22.58.06 shipped (ops run 37893093756, Morpheus 117e073) retried
Evo #378. The session did the work: merged trunk, re-verified the guide's labels and passed the
web suite. Then it escalated, because the brief told it to read the preview URL from GitHub
deployment records and the App token got `403 Resource not accessible by integration` on both
REST and GraphQL. It correctly refused the URL in Vercel's comment, which the brief forbade.

## Decisions

- **Not the Deployments permission.** Granting it needs a passkey re-authentication for the App
  settings and re-approval on each installation, and the session token would also need the
  workflow to request it. That blocks on Chris for something a sound read can do without.
- **Vercel's comment, bound by Vercel's status.** Vercel sets a `Vercel` commit status whose
  `target_url` is the deployment's inspector page, and keeps one PR comment whose first line,
  `[vc]: #<hash>:<base64 JSON>`, carries each project's `inspectorUrl` and `previewUrl`. The comment
  is read only when its author is the `vercel[bot]` App identity (no person can post as it). A
  project is used only when its `inspectorUrl` equals the target of the head commit's newest
  successful status from `vercel[bot]`. The author proves who wrote it; the matching inspector URL
  proves which commit it describes. On #378 the status target and the comment's `inspectorUrl`
  were both `…/7dM5zS3qrM7pwTFSwFD8t4WHgDJs`.
- **A command, not prompt instructions.** `morpheus gh-manager preview-url <repo> <pr> [sha]` does
  the lookup in tested code; the brief tells the session to use only its output. Exit 2 means
  "Vercel has not finished with this commit" (building, or the comment still describes the
  previous deployment), so a session that just pushed waits instead of capturing stale pages.
- The fallback gives the branch alias, which serves the branch's newest deployment. That is the
  head's once the head's status succeeded and the comment matches it, which is exactly the gate.

## Evidence

- Live, against #378 at 5a4b40d: with a token that reads deployments, `preview-url` printed
  `https://evo-ka034e069-darwin-health.vercel.app` from deployment records; with deployments forced
  to `forbidden` on the same real data, it printed
  `https://evo-git-cursor-dataset-collection-labels-f8a6-darwin-health.vercel.app`, which served
  `/dataset-collection/` with HTTP 200 signed out.
- `tests/gh-manager-preview.test.ts`: the #378 comment shape; deployment records preferred;
  deployments by another creator ignored; a comment by anyone but `vercel[bot]` (or not of type
  Bot) never read; a status by another creator ignored; a stale comment waits; building waits;
  a failed build refuses; the newest status per context wins; monorepo projects; non-https or
  credentialed URLs refused; no status refuses.
