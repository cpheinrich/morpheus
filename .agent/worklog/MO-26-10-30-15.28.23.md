# Simplicity first

## Outcome

Chris's rule now appears in five places. `architecture.md` §2 has it as principle 11. Morpheus's
`AGENTS.md` and the scaffold's `agents()` template carry it as the first working convention, with
the same words. The independent-review contract (`src/review/local-prompt.ts`) and its runbook
have it, and so does the rung-2 persona's "Look for" list. The persona is also what the GitHub
Manager reads in Morpheus. A new `INSTRUCTION_ANCHORS` entry makes `morpheus doctor` warn about
any existing project whose `AGENTS.md` lacks the rule.

Chris added the reviewer half mid-session. If the same behaviour can be had with fewer lines,
reviewers should prefer that. The reviewer contract used to say "find concrete defects, not
redesign opportunities", which ruled that out. It now asks for defects and unneeded complexity.
A simpler version with the same behaviour is a minor finding, so the author responds once and no
extra review turn is spent. A gate, approval step, state, option or mechanism that the
requirements do not need is substantive. That is the kind of complexity that stalled CD.

## What was deliberately not done

- **No CI check that a simplification pass happened.** A check that demands evidence gets
  ceremony; this is the same reasoning as the folder-README decision. `doctor` only reports
  whether the instruction is present, as a warning.
- **No existing gate was removed.** The rule says removing one is still a recorded decision.
  Otherwise agents could over-read this rule in the opposite direction and strip safeguards
  without a decision.
- **The agentic-CTO skill was not edited.** Its §2 already says "the simplest robust design" and
  "revise when you find something simpler", and `AGENTS.md` loads in every CTO session.

## Budgets

Both instruction files have byte caps, and both were close to them before this change.

- **Morpheus `AGENTS.md`** (20,000 bytes; it was 19,946). The worktree-cleanup sentences moved
  out, because `pm-workflow.md` already holds every one of those details. The skills-registry
  paragraph is said in fewer words with the same content. Result: 19,966 bytes.
- **Scaffolded `AGENTS.md`** (under 16,000 bytes for the test seed; it was ~15,920). The
  template's two-paragraph "Build vs. borrow" rule now uses the shorter wording Morpheus's own file
  already had. The phrases `tests/init.test.ts` asserts are kept, and so is the "60 lines"
  sentence. The rule itself was tightened twice. Result: 15,999 bytes, so this budget is now
  full. The next addition has to trim something. The review-timing sentences are the obvious
  candidate, since they restate the linked contract, but tests pin them on purpose (#281).

Raising either cap was considered and rejected, because widening a guard to stay green is the
failure `learned.md` records.

## Dead ends

- `pm claim` in the desktop app's worktree prepared a separate task worktree, as the runbook
  says. Read evidence carried across, so refreshing there needed no re-read. Main moving between
  the first read and the claim, though, required re-reading `AGENTS.md` and `decisions.md` in
  full.

## Independent review

A fresh reviewer subagent reviewed `c31b883..f3fb1d2` at normal risk. Runner duration:
384,453 ms. Outcome: complete. It found no rule lost in either trim, `dist/` matching `src/`, and
a doctor anchor that only warns and never changes the exit code. It raised three minor findings,
and all three were fixed in `53b57fd`.

- **F1.** "Prefer a warning to a block" was unqualified, and the spec did not record it. An agent
  could have turned a user-protecting check, such as a physical-device test gate, into a warning.
  The clause now reads "only a check that protects users blocks, others warn". It says that in the
  same words in `AGENTS.md`, the template, principle 11 and the decision, and all of them stay
  within budget.
- **F2.** The new reviewer wording was not pinned by a test. `local-review.test.ts` now asserts
  both sentences in the actual packet.
- **F3.** The rung-2 row in the §9 verifier stack did not mention complexity. It now lists
  "unneeded complexity", and principle 11 names the reviewer standard.
