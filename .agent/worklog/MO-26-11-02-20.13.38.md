# Normalize provider-neutral effort for Codex gateway workers

## Outcome in progress

The post-merge live qualification for PR #589 discovered the installed tools and reached the live
Codex gateway, but its first delegated run failed because the neutral `minimal` effort was passed
unchanged to a model whose supported floor is `low`. The root recovered and completed the marker
task with `low`; this follow-up moves that compatibility rule into the shared Codex worker boundary.

Both Codex-root and Claude-root handoffs now normalize `minimal` to `low` and `ultra` to `max`, even
when a saved pre-change `codexEffortMap` lacks those keys. Native Codex efforts and explicit saved
mappings remain unchanged.

Independent review found that the first implementation applied the configurable Claude-to-Codex
map to Codex-root native efforts as well. The correction separates those boundaries: Codex roots
translate only the two neutral edge aliases, while Claude roots retain the saved configurable map.
