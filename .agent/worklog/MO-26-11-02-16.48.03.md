# Factory dispatches delegated turns automatically while the coordinator manages

## Outcome

In `automatic` mode the prompt hook now launches the routed worker itself, through the existing
`start`/`codexStart`, and the coordinating Codex task or Claude Code session stays its manager.
`manual` stays advisory and `off` stays inert.

- **Launch.** `Manager.autoDispatch` runs on `UserPromptSubmit`. The worker gets the user's
  prompt, the previous bridge result for the same checkout, and its own saved session for that
  checkout and route. It gets no transcript and no coordinator instructions.
- **One launch per turn.** Codex's `turn_id`, or for Claude the prompt plus the transcript's
  path, size and mtime, identifies the turn. The turn is reserved in the task record before
  launch, and each run record carries `dispatch: <turn>`. A retry, a concurrent duplicate or a
  restart after launch therefore finds the same run (`reconcileDispatch`). A reservation with no
  run found is reported as `unknown`, and nothing is launched for it.
- **Held runs first.** An active run, or a terminal `needs_input`, is returned to the manager
  before any routing, opt-out or identity check. That holds even if quota reads now fail or the
  route changed. The next prompt is never sent to the run and is never treated as approval.
- **Truthful outcomes.** The coordinator stays local only on an existing route (quota,
  override, `off`) or the `local:` prefix. Missing identity and launch/preflight errors are
  explicit (`unknown`, `failed`) and come with next steps; they are not a local fallback.
- **Notice.** Each outcome is a deterministic `systemMessage`. The first prompt of an active
  session, automatic or manual, asks the coordinator to open its reply with that line once. It
  never claims delegation when there was none. `SessionStart` reports readiness only.
- **Edit guard.** A best-effort `PreToolUse` guard refuses the coordinator's native edits inside
  its own active worker's checkout. It is not a boundary and does not parse shell commands.
- **Unchanged.** Lease, grace, `maxConcurrent` and per-checkout ownership. Several sessions may
  share one gateway credential, and there is no per-credential lock or scheduler.
- **Timeout.** The prompt hook's timeout is 60 s: the client's 10 s bridge start plus its 40 s
  request deadline.

## Tests

`plugins/factory/tests/dispatch.test.mjs` has 14 tests: the in-process Manager with the real
guardian and a fake Claude worker behind a local sub2api stub, plus two end-to-end tests. The
end-to-end tests spawn the installed hook scripts, which start a separate bridge process. The
Codex one adds a minimal app-server over a Unix-socket WebSocket.

The tests cover:

- launch, sequential and concurrent dedupe, a repeated prompt on a new turn, and the handoff
  contents;
- active and waiting runs held under a failed quota read or a changed route, in both directions;
- manual mode's once-only notice, in both directions;
- off, quota fallback, overrides, `local:` and missing identity;
- restart after launch with a completed run, and a pre-launch reservation reported as unknown;
- one credential shared by two sessions, the `maxConcurrent` limit and checkout ownership;
- preflight failure;
- Codex Interrupt;
- the edit guard;
- lease lapse;
- the recursion marker.

The plugin suite has 154 tests, 154 passing.

## Dead ends and notes

- The first full run of the new file hung for more than five minutes and was stopped. Each test
  passed alone with `--test-timeout`, and the whole file now passes in about 24 s. The real
  defect was cleanup order: `t.after` runs first in, first out, so the temp home was deleted
  before the spawned bridge was stopped. That left a test bridge and a sleeping fake worker
  running. Two such stray services were stopped by exact PID after checking that their
  `FACTORY_HOME` was a test home; the real `~/.local/share/factory` guardians were left alone.
  Bridge shutdown now runs inside the harness cleanup, before the home is removed. The original
  hang itself was not reproduced, so its exact cause is unproven.
- The parent's source review found four defects before review, all fixed with tests:
  - the outcome was recorded only after launch, so a restart could relaunch;
  - quota was checked before held runs;
  - missing identity was reported as `local`;
  - manual mode got no notice.
- macOS has no `timeout(1)`; use node's `--test-timeout`.
- Codex `PreToolUse` coverage of `apply_patch`, and the payload shape (`tool_input.command`), are
  assumed from the documentation and are unverified live. The guard fails open on an unknown
  shape.
