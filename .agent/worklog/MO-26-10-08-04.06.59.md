# Rescue dirty trunk checkouts; report stale ones

Trigger: `~/code/lakina` main sat 188 commits behind for three weeks behind one Xcode-rewritten
`project.pbxproj`, and `~/code/morpheus` had orphaned `dist/` output that made a self-install
refuse with no list of paths. The item was first scoped as "print a prominent remediation block";
mid-task Chris changed it to automatic remediation: move the uncommitted changes to a branch and
push a WIP PR.

## What shipped

- `src/session/trunk-rescue.ts`: porcelain parsing, orphan-build-output detection, lag thresholds
  (`STALE_BEHIND_COMMITS = 20`, `STALE_BEHIND_DAYS = 3`), WIP branch naming, and
  `rescueDirtyTrunk`. The rescue builds the commit in a private index seeded from the real one
  (`add -u`, `write-tree`, `commit-tree`), so the user's index is never written; proves
  `git diff --quiet <commit>` before anything changes; creates the branch create-only; pushes;
  opens a draft PR through an injectable `gh` runner; then `reset --hard HEAD`. The reset only
  ever happens after the content is on a local ref.
- `prepareRepository` runs it when HEAD is the trunk branch, then fast-forwards whenever no tracked
  dirt remains. Untracked files no longer block the fast-forward: Git's `--ff-only` refuses on its
  own when one would be overwritten, and that refusal is now caught and printed instead of thrown.
- `doctor` gains a read-only `trunk-checkout` check (so `doctor --all` is the fleet view), measured
  against the remote tip when it is already local and otherwise the cached ref, saying so.
- `self install`'s dirty-source refusal lists tracked edits, orphaned build output (with `rm`
  lines) and other untracked files. `status` now uses `--untracked-files=all` so an untracked
  `dist/old/` directory is seen file by file.
- GitHub Manager: an unreviewed `wip/trunk-*` draft past the 48h draft quiet period routes to a
  human escalation, never a session that could review, repair or merge it.

## Decisions made in passing

- **Tracked edits only.** Untracked files are listed in the PR body and left alone.
- **Push failure still resets.** The commit is on a local branch, so resetting loses nothing and
  leaves trunk able to advance; the brief prints the push command.
- **Suffix rather than extra commit** for a second rescue the same day: `-2`, `-3`. Simpler and
  never moves a branch someone may have adopted.
- **`self ensure` / `self update` have nothing to rescue.** They clone into a disposable directory;
  the only command that reads a working checkout is `self install <path>`, which is explicit and
  may name a non-trunk checkout, so it reports and does not push.
- **Doctor reports, brief acts.** `doctor --all` reaches checkouts no session is in.
- Branch date is Pacific, matching roadmap ids.

active work in the main checkout; the next session started there will move them to a draft PR.
