Host setup now accepts an operator-approved existing Tailscale tag. Fresh tagged enrollment
uses the provider's default with key expiry disabled. The helper checks local device status
before proceeding. An already-connected device keeps its identity and reports a manual
admin step if its existing policy still expires.

Factory worker and gateway setup share the helper. CI/CD uses the same script from a reviewed
checkout or installed Factory package. New enrollment is explicit, so ordinary worker setup and
ephemeral CI guests keep their previous network provisioning.

Focused Python fixtures use isolated mock Homebrew, sudo and Tailscale commands. They verify
fresh enrollment, existing identities, read-only checks, key-file references and failed expiry
or tag verification. The gateway fixture verifies network setup is checked before deployment.
A read-only invocation on an existing managed Mac confirmed local no-expiry status.
The fresh enrolled path was exercised with fixtures and was not run on enrolled machines.

[Tailscale documents the tagged-device default](https://tailscale.com/docs/features/tags#key-expiry).
The [host package README](../../plugins/factory/src/host/README.md) documents the operator path.

Independent review identified two risks around retained Tailscale identity and tag validation. Both conditions were satisfied with targeted fixes and passing tests. The CI host wrapper also cleared independent review.
