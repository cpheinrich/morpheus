# Audit the test suite and what it costs in CI

Chris asked for the prune-tests audit to be run on Morpheus, with the suite kept broadly intact.
The report is [`qa/audits/2026-11-18-test-suite.md`](../../qa/audits/2026-11-18-test-suite.md); the
inventory script and its tables sit beside it in `qa/audits/2026-11-18-test-suite/`.

## Result

Pruning does not shorten CI here. Of 240 test files none rated below 3, one case met the bar for
removal and six are ranked for a human decision; together they cost under half a second.

The wait comes from the browser lane. Its browser install took 17 to 23 minutes in 4 of the last
35 runs that ran it, against 30 to 100 seconds normally. And twelve WebKit cases stall about 10
seconds per pin capture, about 166 seconds a run, where Chromium needs under 1.5 seconds.

One test changed. `plugins/factory/tests/mcp.test.mjs` asserted that removed `pool_*` tools stay
removed, which three other cases already cover. It now asserts that a delegated worker cannot
delegate again through either MCP server. That guard had no test: disabling it failed nothing
that loads those servers.

## Dead ends and things that bit

- The first set of timing receipts skipped two runs because they looked like outliers. They
  were the finding: both were slow browser installs. Sampling 35 runs replaced the hand pick.
- The first version of the rewritten test closed its MCP client after the assertions. When a
  fault check made an assertion fail, the server child kept the test file alive until it was
  stopped by hand. The client is now closed from `t.after`, registered before any assertion.
- `unattended-worker.test.mjs` fails 2 of 30 cases on this developer machine on unmodified code
  and passes in CI. It made the first fault check look like it had caught something. It had not;
  that file loads neither MCP server.
- A zero-assertion scan over test bodies produced 13 hits and no real ones. One-line cases and
  shared assertion helpers defeat a line-based scan.
- The method's "asserts the past" category and this repository's rule that a written "never do
  X" needs a failing test point opposite ways on the old `hq/inbox` path cases. They were left
  in place for a human to decide.

## Not done

- No CI lane, workflow or product code was changed.
- 214 files were rated from scans and metrics rather than read case by case.
- The WebKit stall and the slow installs were measured, not root-caused.
