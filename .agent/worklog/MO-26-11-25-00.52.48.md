# Scope Infra phone probes to the enrolled device

A USB-connected, enrolled phone reported a source error. The host's full CoreDevice
inventory was slightly larger than the reporter's 256 KiB subprocess output bound, so Node
rejected it with `ERR_CHILD_PROCESS_STDIO_MAXBUFFER`. The
`devicectl list devices --filter "properties.hardware.udid = '…' OR hardwareProperties.udid = '…'"`
query returns only the enrolled phone, well within the same bound. Independent review (F1)
rejected filtering on the display `Identifier`, because some rows report a CoreDevice UUID
there. The controller ran this literal predicate with the real enrolled phone on Xcode 27.2
(one exact row, within bound) and validated the legacy-only key separately.

Both passive inventory reads in `phone.mjs` now use that exact filter, and neither falls back
to an unfiltered query. Lease bracketing, exact UDID and identity validation, the read-only
command set and the time/output bounds are unchanged. The identifier is checked against
the configured canonical pattern again before it goes into the predicate. A malformed value
fails closed without running any device command.

A focused regression checks the exact predicate on both filtered reads, for both the modern
and the legacy response fixtures, and that no argument names `Identifier`. It also covers an
inventory failure with no broad retry and a predicate-injection-shaped identifier that issues
no calls. Phone tests: 9/9 pass. Three other reporting test files fail on the unchanged base
too, because `zod` is not installed in this worktree.

The controller owns independent review, the installed-bundle dry run and the host rollout.
