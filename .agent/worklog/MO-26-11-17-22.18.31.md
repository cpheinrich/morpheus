# Keep Fleet control requests alive on slow worker links

An authenticated worker read reproduced the eight-second timeout on an affected host.
The same request returned HTTP 200 in 8.5 and 8.6 seconds under a longer bound.
Other public HTTPS endpoints were also slow on the host while its LAN gateway remained
reachable. Cloud Run continued to serve other callers. An interrupted invocation left a
detached Xcode process behind and could only settle after exact process cleanup and the
existing verified census. A later claim lost its acknowledgement and settled before launch.

The Fleet client now gives supervisory calls 20 seconds, below the server's existing
120-second lease. Transfers and controller calls use their existing limits. The supervisor
still aborts at its last acknowledged deadline during a stalled RPC. No new dependency,
retries, or authority are required.

- Focused Fleet client, runner and claim tests cover the request budgets,
  verified cleanup and cancellation between grant and reply.
- Typecheck, compile, roadmap index and diff checks passed.
- Complexity passed with the existing CCN limit of 15.
- The reopened implementation ran on the already-enrolled alternate worker while this
  transport change was verified. Live rollout and a normal task on the affected slot
  remain separate from source verification.
