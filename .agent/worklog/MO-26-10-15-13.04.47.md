# QA comment placement reliability

## Cause and historical review

Chris's Safari screenshot shows the second pin accepted into the editor but rejected by
the iOS overlay's later placement check. The exact moving element cannot be identified
from the screenshot alone. Source establishes the failure path: a right-click takes the
latest asynchronous accessibility sample; `/api/placement` then obtains two more native
accessibility trees around a simulator screenshot; `stablePlacementAnchor` rejects any
change in chosen element ID, label or offset over two points. Normal navigation, scroll
settling, chart changes and AX polling skew can violate that comparison. The pin remains
in the list without a placement PNG, so Send rejects it. Three extra native AX reads per
pin also enlarge the exposure to the serve-sim AX crash tracked in Morpheus #397/#409.

Reviewed Morpheus worklogs for the October 9 pin redesign, October 4 touch pacing and
draft persistence, October 6 shared preview, October 7 web pin placement and Esc behavior,
and October 9 queue/responder work. Reviewed Evo worklogs for October 4 interactive QA,
the simulator input bridge and simulator cleanup. The repeated pattern is a boundary
between independently timed browser video, native accessibility, simulator input, and
background queue ownership. Earlier tests exercised the parts separately. October 9's
live placement check only read one endpoint on one screen; it did not perform the user's
pin → navigate → pin → Send workflow. Web QA had strong proxy, schema and DOM tests but
no real-browser multi-pin workflow gate.

## Change

Freeze the frame already displayed in the browser at each iOS right-click and retain it
per pin. Refuse an attempted pin if that frame is unavailable. Native accessibility still
helps a marker follow scrolling and hide on another screen, but never invalidates its
captured image or blocks Send. Remove the now-unused native placement endpoint and
capture function. Update the operator guide and decisions record. Add a Playwright gate
for both overlays in Chromium and WebKit: iOS pin → scroll/navigation → second pin →
reload → Send, and web pin → page scroll → second pin → Send through the proxy.
