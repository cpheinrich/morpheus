# Copyable section links on every HQ heading

## What was built

`src/section-links/index.ts` holds the framework-free part: GitHub's heading slug, `-1`/`-2`
deduplication, the shareable address, fragment decoding, and `assignHeadingIds`, which gives
every eligible `h2`–`h4` an id and re-derives only the ids it generated itself.
`src/section-links/react.tsx` is `<SectionLinks />`: one pass on mount plus a `MutationObserver`
for ids, and one floating icon placed beside the hovered heading's first line. Clicking it
`replaceState`s and copies the address, and a status region announces the result. The `web init`
HQ layout template mounts it; `package.json` exports both subpaths. Docs:
`src/section-links/README.md`, `architecture.md` (HQ → Section links), `README.md`.

## Decisions while building

- **A floating icon, not a node injected into each heading.** `anchor-js` and
  `rehype-autolink-headings` inject a link into the heading. React owns heading children. A
  string-child update calls `textContent =` and erases the injected node. An injected node inside a
  Suspense boundary that has not hydrated yet is a hydration mismatch, and React re-renders that
  boundary on the client. The only write into a heading is a missing `id` attribute. React does not
  remove attributes it did not set, and a mismatched attribute during hydration only produces a
  development warning.
- **The gutter is hit-tested by probing 40px to the pointer's right.** That way, moving from the
  heading to the icon, or hovering the gutter first, both count as being on the heading, and no
  per-heading listeners or hover boxes are needed. Hovering the icon itself keeps the current target.
- **Generated ids follow their heading's text; authored ids never move.** A heading that renders
  "Loading…" before its data would otherwise be addressed as `loading` for good.
- **`replaceState`, not `pushState`, with Next's `__NA` marker removed.** Copying a link should
  not add a Back step. The first version passed `history.state` through, which made Next forward
  the call without adopting the URL, so a later router refresh dropped the fragment (review SL-001).
  Without the marker, Next copies its internal entries back itself and updates its canonical URL.
- **The template's layout wrapper stays a `div`.** Changing it to `<main>` would nest it around the
  template page's own `<main>`. The default scope is `main`, falling back to the body, so either works.

## Dead ends

- **`fireEvent.pointerMove` in jsdom loses `clientX` and `pointerType`.** jsdom 26 has no
  `PointerEvent`, and testing-library's fallback `Event` drops unknown init fields. The tests
  dispatch a `MouseEvent` named `pointermove` with `pointerType` defined on it.
- **Playwright 1.63 expects `chromium_headless_shell-1243`, and this host has only 1234/1248.**
  The browser check launches the installed 1248 shell through `executablePath`, rather than
  downloading a browser.
