# Reduce Morpheus pull request CI latency

## The ask

Chris wanted proof of which of five ideas from a tweet (a faster type checker, Oxlint,
time-balanced test shards, diff-reachable tests, parallel lint/typecheck/build/test) speed up
Morpheus CI, and a staged path to other projects. This handoff covered Morpheus only.

## What was built

`node-ci.yml` gained `parallel-static-checks`, off by default. With it on, typecheck, lint, the
context-runtime install and the verified build run at once in the existing required job, before
the tests. Each runs the serial step's own script through a YAML alias. Morpheus's `ci.yml`
opts in. `tests/node-ci-parallel.test.ts` executes the real step script in a throwaway
repository with stand-in `pnpm` and `sudo`.

## Result

The required `node / check` is the whole wait, and the tests are two thirds of it. The steps
around the tests dropped from 43 seconds to 25 across four real runs, about a tenth of the
wait, using one runner. GitHub reported `node / check` on every run. The unlabelled draft
left `pr / conventions` unreported.
[`docs/ci-speed.md`](../../docs/ci-speed.md) has the verdict on all five ideas, run ids,
commands, the rollout decision and the revert.

In short: the two tool swaps work but save seconds that no longer matter once the checks run
together; two native test shards measured a real gain but need a second runner and a
restructured required check, so they are a separate item; time-balanced shards and
diff-reachable test selection are rejected.

## Dead ends and surprises

- The step-level numbers are the trustworthy comparison. The test step swings 89 to 135 seconds
  with the machine GitHub assigns, which is larger than the saving, so whole-job medians from
  a few runs are noisy.
- Running the checks alongside the tests instead was considered and dropped: the tests already
  saturate four cores, and 21 test files read `dist/`, which the verified build deletes first.
- Splitting into separate jobs was dropped: each new job repeats 30 to 50 seconds of setup and
  would change what `node / check` means.
- `vitest list --shard` ignores the shard flag, so shard balance was first estimated by
  replaying Vitest's path-hash split against per-file times from a CI log, then measured with
  one temporary job (run 44025455712), removed in the next commit.
- A downstream pilot kept the web build separate from parallel typecheck, lint and unit
  tests because the build writes generated inputs they read. The parallel variant was
  slower in the paired Actions run, so it stops at the pilot.
- `morpheus codebase-memory install` could not index this checkout: the upstream installer
  refused to modify `~/.codex/config.toml`. Source reads were used; the change is workflow YAML
  and one test file.

## Open questions

- Further experiments could test ripgrep setup or two shards behind the required
  `check` job.
- In the new mode a stale `dist/` fails before the tests run, so that run has no test results.
  Faster feedback for the common mistake, one more round trip when both are wrong.

## Appendix: commands run

```sh
pnpm typecheck
pnpm lint
pnpm exec vitest run tests/node-ci-parallel.test.ts tests/workflows.test.ts \
  tests/workflow-expressions.test.ts tests/ci-scope.test.ts
actionlint -shellcheck= -pyflakes=
pnpm compile
pnpm morpheus pm index
morpheus complexity check
```

Focused scope because the change is two workflow files, one new test file and documentation;
those four suites are the ones that read `node-ci.yml` and `ci.yml`. The full suite ran in CI
on every push. Five hand mutations of the step script (serial instead of concurrent, swallowed
failures, skipped verification, unconditional lint, dropped early return) were checked against
the new tests; four were caught and the fifth is equivalent under `bash -e`.
