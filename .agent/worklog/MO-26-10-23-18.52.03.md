# MO-26-10-23-18.52.03 — isoDate accepts a UTC timestamp string

Author session: d337407a-fd39-41cc-84db-3723a5ef8741 (Claude, Chris's Mac), found while landing
darwin-health/darwin#117 behind a red Darwin trunk. Issue #468, PR #469.

## What was found

#376 (`gray-matter` → `@11ty/gray-matter`) was described as behaviour-free. js-yaml 3 turned an
unquoted `date: 2026-08-18T13:15:00.000Z` into a Date, which `isoDate` sliced to its day; the new
parser hands the string over and `z.iso.date()` refuses it. Darwin's two inboxes are written that
way, so `inbox validate` and Darwin's `Project records CI` failed on trunk and every PR from
2026-10-24 01:47Z.

## What was built

`isoDate` also slices a UTC timestamp string (`YYYY-MM-DDT…Z`) to its day; a timestamp with an
offset is still refused. `dist/pm/schema.*` regenerated. Two tests in `tests/inbox.test.ts`.

## Validation

Focused: `pnpm vitest run tests/inbox.test.ts tests/pm.test.ts tests/team.test.ts` → 111 pass.
`pnpm typecheck`, `pnpm lint` clean. `node dist/cli/index.js inbox validate --dir
~/code/darwin/hq/team` → both inboxes valid (they fail on main). Full `pnpm test` once:  Test Files 97 passed (97) Tests 2793 passed (2793)
