# Run portable repository-owned schedules

## Outcome

`src/scheduler/` adds `morpheus scheduler tick | status | admit`, the
`.github/actions/scheduler-admit` composite action, an empty `.morpheus/schedules.json` for
Morpheus, and the contract in `docs/runbooks/scheduler.md` and `architecture.md` §7.15.
`.github/workflows/schedule.yml` lost its hourly cron on Chris's instruction and stays manual.
Croner 11.0.0 is the one new runtime dependency (exact pin, zero dependencies).

## Design choices made while building

- **Activation baseline** is the committer date of the last commit touching
  `.morpheus/schedules.json`. Simplest available fact; the cost is that editing the registry forgoes
  catch-up of slots due before the edit. Documented.
- **Backup probes from the newest slot past grace**, not the latest slot. First test run showed the
  naive "latest slot older than grace" rule can never fire for a `*/5` schedule.
- **Backup within grace reports `waiting`**, not `accepted`: an earlier draft said "accepted" when
  only an older slot had a run, which misdescribed the due slot.
- **Primary keeps its last submission in the status file.** Without it, a confirmed dispatch whose
  run is not yet listed would be resubmitted a minute later. A lost response waits five minutes,
  then resubmits; the receiver guard absorbs the duplicate.
- **Workflow source check before dispatch.** The tick refuses a workflow file with no
  `run-name:` line containing `[schedule:` or lacking either input name, because such runs are
  invisible to history and would be dispatched every minute.
- **Admission marker is a consumer step named `Scheduler admission`.** Steps inside a composite
  action are not listed by the jobs API, so the action cannot mint its own marker; the guard
  refuses to run if its own (in-progress) step carries the marker name.
- Croner's `previousRuns` is exclusive of its reference; `slotAtOrBefore` adds one second to make
  "a slot at exactly now is due" true. Mutating that away fails two tests.

## Real-environment probes (read-only)

- Disposable copy of the tracked tree, `npx --yes pnpm@11.9.0 install --prod --frozen-lockfile
  --ignore-scripts` → exit 0, `node_modules` held only the nine production packages including
  croner. `scheduler status` printed `no tick has written a status yet`; `scheduler tick
  --dry-run` against `cpheinrich/morpheus` (no registry on main yet → isolated error) and a
  nonexistent repository (404 → isolated error) used the injected `GH_TOKEN`, wrote no status file.
- Direct client reads against `cpheinrich/morpheus`: workflow-runs pagination with the `created`
  filter (0 dispatch runs in 6h), `schedule.yml` workflow state `disabled_manually` (already off in
  GitHub), commit-date lookup, and the jobs API shape (`run_attempt`, step `name/status/conclusion`).
- No dispatch was submitted anywhere.
