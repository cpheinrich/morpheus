# Shrink shared HQ search payload

## Outcome in progress

MiniSearch still indexes every normalized document token, but new payloads retain only title,
route metadata and one hard-bounded 190-character excerpt as result fields. The browser renders
that build-time excerpt without receiving the full raw document text a second time. Earlier
version-1 payloads remain loadable and use their stored raw text through the compatibility path.

The design stays inside the existing MiniSearch index and payload version. It adds no provider,
service, dependency, runtime fetch or state.

## Payload evidence

The representative three-document fixture contains 55,827 bytes of normalized source text. Its
legacy stored-text payload is 61,548 bytes; the excerpt payload is 6,309 bytes, an 89.75% reduction.
The same test searches for a token beyond the stored excerpt after serialize/reload and finds the
document, proving the reduction does not truncate indexed coverage.

## Independent review finding HQS-001

The initial normal-risk review found that `createHqSearchIndex` derived a bounded excerpt only when
the caller omitted one. A custom catalogue could supply a valid 500-character excerpt, which the
index stored verbatim and exposed as the result snippet, contradicting the hard-bound contract.
The core index boundary now sends both supplied excerpts and text-derived fallbacks through
`searchExcerpt`, so every newly serialized display field is normalized and capped at 191 characters for
the default 190-character content bound plus ellipsis. A regression fixture supplies an oversized,
irregularly spaced excerpt and verifies the stored field and reloaded result use the same bounded
value while the document's full text remains searchable.

Correction verification: the focused search suites pass 26 tests; `pnpm typecheck`, `pnpm lint`,
and `pnpm compile` pass. Compilation refreshed the committed `dist/hq-search/index.js` and source
map; the public declaration shape is unchanged.

The fresh normal-risk reviewer blocked the initial implementation on HQS-001: createHqSearchIndex stored caller-supplied excerpts verbatim, so a valid 500-character value bypassed the promised hard bound. The core boundary now normalizes and bounds supplied and derived excerpts alike, with a focused oversized-input regression and regenerated distribution output. The same reviewer cleared the corrected SHA with no remaining findings.
