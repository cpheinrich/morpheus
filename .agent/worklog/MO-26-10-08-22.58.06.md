# MO-26-10-08-22.58.06 — The GitHub Manager captures web screenshots as PR evidence

## Why

Auditing the manager's eight flags, seven were right and one was avoidable: Evo #378 was escalated
for missing screenshots of `/dataset-collection/`, a public page the PR's Vercel preview serves to
anyone (verified: HTTP 200 with no session).

## Design

- **Capture in the session, publish in apply.** The session already has network and a browser
  can be installed before any credential enters the job; it has no upload credential and should
  not get one. Apply has contents write, so it pushes the files.
- **Where the images live: tagged orphan commits, not a branch.** Evo accepts evidence only from
  its GCP bucket, and the manager holds no GCP credential. The first design pushed to an orphan
  `gh-manager-evidence` branch. Review pointed out that Evo's Vercel Git integration builds every
  pushed branch (a `vercel[bot]` Preview deployment exists for each head), so every screenshot
  would have produced a failed build, and that anyone with write access could replace a file on a
  shared branch. Each publish is now one orphan commit tagged `gh-manager-evidence/<commit>`; tags
  start no deployment, and the link names the exact commit. Verified on the private operations
  repository: `https://github.com/<repo>/raw/gh-manager-evidence/<commit>/pr-0/probe.png` served
  the 1337x6858 PNG to a signed-in browser. A repository opts in by approving
  `https://github.com/<repo>/raw/gh-manager-evidence/`.
- **Preview URL from deployment records, not comments.** `vercel[bot]` creates a GitHub deployment
  per head commit whose status carries `environment_url` (checked on Evo); a comment can name any
  URL.
- **Evidence only on a merge.** Publishing happens only for a `merge` on the head the session
  finished on, after checking the body can place every image; other actions keep their own
  message. This logic lives in `applyEvidence`, tested with a stubbed publisher.
- **Placeholders, not URLs, from the model.** The session writes
  `{{gh-manager-evidence:<file>}}`; apply substitutes. A placeholder with no file, a file never
  placed, a non-image, or a failed upload escalates instead of merging.
- **Playwright's own CLI** (`playwright screenshot`), pinned to 1.63.0 (published 2026-09-04;
  1.64.0 was a day old). No Morpheus dependency: it is installed globally in the session job only.
  Considered adding it as a package dependency; rejected because every consumer of morpheus-kit
  would download it for a capability only this job uses.

## Evidence

- Ran the exact session command against Evo #378's real preview:
  `playwright screenshot --full-page --viewport-size=1280,900 '<preview>/dataset-collection/' out.png`
  produced a correct 1337x6858 PNG of the page.
- `tests/gh-manager-evidence.test.ts`: URL shape; PNG/JPEG detected by content; refusal of
  non-images, empty files, missing files, unsafe names, duplicates and more than ten files;
  placeholder substitution with caption sanitising; refusal of an unknown placeholder and of an
  unplaced image; the decision field; the brief's instructions.
- `tests/workflows.test.ts`: pinned Playwright installed before the session step with no secret in
  its environment; the evidence directory uploaded beside the decision.
- `applyEvidence`: publish and placement on a merge; escalation on a publish failure, a missing
  file, an unplaceable body or a stray placeholder; nothing published in a dry run, for another
  action, a moved head or a closed PR.
- **Not yet verified live:** publishing through the App token in a real run. Evo #378 is the first
  case.
