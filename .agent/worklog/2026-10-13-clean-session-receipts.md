# Clean generated receipts from completed task worktrees

Roadmap: MO-26-10-13-16.10.47. Issue: #391.

After PR #390 merged, a live dry run against its own worktree refused deletion
because `local/` contained a generated context receipt. Of twelve merged Evo
worktrees with ignored `local/` data, ten had only that receipt under `local/`;
two also held visual evidence that must remain protected. This surfaced a
routine path the first cleanup PR did not test.

The cleanup guard now accepts `local/` only when it contains one `sessions`
directory, that directory contains only the filename generated by `sessionId`
for this exact worktree, the file is regular rather than a symlink, and
`readLease` validates a receipt naming the same worktree. All other ignored
data remains protected. This uses the existing session schema and filesystem
APIs; no generic parsing package is needed.

Focused real-Git cleanup tests exercise successful removal of a generated
receipt and preservation of unrelated or mismatched local data. The first test
run caught a fixture gap: its temporary repository did not ignore `local/` as
real Morpheus projects do. After setting that test fixture's Git exclude,
all thirteen focused tests passed, including malformed and symlink receipts.
TypeScript checking, lint, compile, the fourteen agent-instruction tests,
`pm index`, `pm validate`, and `git diff --check` passed. A live dry run of
the compiled branch CLI on merged Evo PR #221 reported `Safe to remove` for
its receipt-only worktree; it still refused Evo's merged loading worktree,
whose `local/` also contains visual evidence. The exact new worktree has no
codebase-memory index; source and focused tests supplied the structural evidence.
