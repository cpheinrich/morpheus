# MO-26-10-02-12.27.23 — QA comment batches

Cross-project stand-in for Codex's right-panel "comment" tool: tap a preview,
leave one or more text comments, Send, and any Morpheus agent can read the batch.

Contract: [`docs/runbooks/qa-comments.md`](../../docs/runbooks/qa-comments.md).
Schema: [`src/qa/comments.ts`](../../src/qa/comments.ts).

## Why it lives in Morpheus

Evo's ios-qa skill already launches serve-sim; Lakinacapital and Kairos will want
the same loop without copying an Evo-only overlay. The batch format, on-disk root
(`local/qa-comments/`), and `morpheus qa comments …` CLI belong here so every
`kind: company` project inherits them. Project-specific launchers (Evo
`preview.sh`, future web preview helpers) only emit the preview URL and optional
metadata; they do not invent the batch schema.

## First slice (this claim)

1. Design + on-disk layout + Zod schema.
2. CLI surface: `morpheus qa comments pending|resolve|show` reading
   `local/qa-comments/` in the current checkout.
3. No overlay UI yet — the writer side can arrive as a tiny local web app in a
   follow-up commit on this branch or a child item once the agent-side contract
   is stable.

## Open design calls (do not guess past these)

- **Coordinate space.** Serve-sim streams pixels; Codex annotations are on the
  streamed frame, not SwiftUI DOM. Batches store normalized 0–1 coordinates
  relative to the captured frame, plus optional pixel `x`/`y` and frame size, so
  a later viewer can redraw markers without assuming a fixed device size.
- **Where the overlay runs.** Preferred: a Morpheus-served local page that
  iframes/proxies the preview URL and captures taps. Alternative: a bookmarklet
  / userscript on the serve-sim page. Prefer the first so projects do not depend
  on browser extension state.
- **Notification vs poll.** Agents poll `pending` (and optionally `watch`). No
  push channel in v1 — keeps the surface offline-friendly and secret-free.
