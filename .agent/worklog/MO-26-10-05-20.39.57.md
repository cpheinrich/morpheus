# MO-26-10-05-20.39.57 — Retry failed tests in the same process again

## Why

#318 (2026-10-04) added `-test-repetition-relaunch-enabled YES` beside the retry flags. The
first consumer run with a real failure under it, Evo release run 37394836077 on 2026-10-06,
re-executed the whole UI bundle after the first pass: pass 1 (158 cases, 2 failures) ended at
01:52:55 UTC, pass 2 ran all 158 cases again until 03:03:12, pass 3 was 80 cases in at the job's
three-hour limit, and no result was finalised or exported. The recovery controller got a
cancelled reservation instead of evidence.

## Change

The flag is removed; `-retry-tests-on-failure -test-iterations "$TEST_ITERATIONS"` stays.
`tests/ios-evidence-workflow.test.ts` pins the pair at `TEST_ITERATIONS=3` and asserts the
relaunch flag is absent anywhere in argv.

## Evidence

- `pnpm exec vitest run tests/ios-evidence-workflow.test.ts`: 7 passed. `pnpm lint`, `pnpm typecheck` clean. `ruby -ryaml` parses the workflow.
- Consumer proof is the next failing Evo release finishing its test stage in the usual 60 to 80 minutes with evidence exported; recorded on the Evo incident when it happens.

## Independent review

A fresh Claude review at small risk checked the YAML and shell array, the test that now pins the flag's absence and the retry pair, the absence of any other live reference to the flag, and the consumer run's own log, which shows the UI bundle's 158 cases executed in full on the second pass and a third pass under way at the three-hour cut-off. No findings.
