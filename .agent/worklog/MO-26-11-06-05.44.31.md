# Adopt the Lizard JSX text-slash fix pin

## Ask

Move the shared analyzer pin from `541623c` (adopted in #630) to `b57041b`, the fork build that
fixes the JSX form #630 disclosed as unidentified. That form made Lakina's `CompanyDetail` measure
99–184 at CCN 17 and dropped `SaasBottomUp`. Change only the pin, canary, tests, runbook, `dist/`
and records. Keep every earlier canary, the wheel hashes, the Python floor and the older tags. Add
no policy, gate, catalog or analyzer.

## What the fault was

Lizard's regex pre-scan runs on raw source and does not know about JSX. In `<th>At 9% / 11%</th>`
it marks the slash after `9%` as the start of a regex literal. A `for` anywhere in the file
(`like-for-like` in the repro) or a preceding `(` is enough to trigger it. The literal ran on to the
slash of the next closing tag (`/ 11%</th`). Before PR 560, JSX children were tokenised as code and
the stray token did no harm. Once PR 560 read children as text, the swallowed `</th>` unbalanced the
elements, and the enclosing function ran on past its end. So this is a regression introduced by
PR 560 itself: plain upstream master reads the minimal case correctly.

Upstream PR 560 at `d2d52d9` fixes it in about 20 source lines, for JSX only. In `.jsx` and `.tsx`
a regex literal may not end at an unescaped `<` whose slash starts closing-tag syntax (`</name>` or
`</>`). `/</g` is still a literal, and the JavaScript and TypeScript token patterns are byte-for-byte
unchanged. The fork merged it as `b57041b`, a fast-forward of `541623c`. The worker's contract is
`/tmp/lizard-jsx-text-slash-contract.json`.

## Known limits

These remain at `b57041b` and are documented in the runbook, not claimed fixed:

- An element used directly as an attribute value without braces (`icon=<i />`) loses the
  functions after it.
- A `key={...}` attribute ends an enclosing expression-bodied arrow early. The canary's
  `rows.map` arrow is measured as one line at CCN 1 for this reason, so it is not asserted.
- The pre-scan itself is still not JSX-aware. The fix only stops a mis-read literal from crossing a
  closing tag. A literal that opens and closes inside the same text (`( / a / b`) stays one token,
  inside the text, and does not change bounds or CCN.
- In `.jsx`/`.tsx`, an unescaped `/a</b>/` is not read as a regex. A valid literal has to escape
  that slash anyway (`/a<\/b>/`).
- On Lakina, `marketCells` still absorbs six DCF helpers and one `ResearchCharts` function has an
  odd span (all ≤ CCN 15 standalone).
- A valueless attribute literally named `extends`, and valueless attributes outside an expression
  position, are misread as before.

The list is what has been found so far, not proof that nothing else misreads.
