# Section links reveal closed details and fit narrow gutters

## What was built

Two fixes to `morpheus-kit/section-links`, both found by Lakina's independent review of its
adoption (lakinacapital#593):

- `revealAncestors` (in `src/section-links/index.ts`) opens every closed ancestor `<details>` before
  the component scrolls to a generated fragment. This matches what browser fragment navigation does
  for an id present in the HTML. Before the fix, a link into "Show N more" left the reader at the top.
- `measure` keeps the icon wholly in the margin. On a narrow layout the gap shrinks from 6px to 2px,
  then the icon from its font-derived size down to 12px. Where even that would overlap, no icon is
  shown. Previously it was clamped to x=4 and covered the first letter in Lakina's ≤900px single
  column. README updated.

## Verification

- `pnpm exec vitest run tests/section-links.test.ts tests/section-links-react.test.tsx tests/web-scaffold.test.ts`:
  55 passed. Typecheck and eslint are clean. The React tests now stub `getBoundingClientRect`,
  because jsdom has no layout and the gutter rule needs a measured text edge.
- Mutation check: removing the reveal, the minimum size, or the gap shrink each fails one test. The
  first version of the narrow-gutter test let the gap mutant survive, because it re-read a link React
  had already detached, and that link still reported its old position. It now re-queries inside
  `waitFor` and asserts the exact 2px gap.
- Chromium, Lakina's `globals.css` and shell markup:
  - At 1360px the text starts at x=300 and the icon spans 274–294 (20px).
  - At 860px the text starts at x=20 and the icon spans 2–18 (16px).
  - At 600px the text starts at x=16 and the icon spans 2–14 (12px).
  - Loading `/#folded-experiment` opened the `<details>` and scrolled to the heading.
