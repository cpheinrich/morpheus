# Fix `self ensure` failing inside Git hooks

Trigger: after a trunk merge in a Lakina worktree under `~/code/.morpheus-worktrees/`, the managed
`post-merge` block printed "Could not update Morpheus: The source checkout has local changes;
install from clean main." with `~/code/morpheus` clean, and `morpheus self update` by hand
immediately afterwards succeeded.

## Root cause — confirmed

Git exports `GIT_DIR` and `GIT_PREFIX` into hooks. `self ensure` → `updateMorpheus` clones current
main into a temp directory and `installCurrentMorpheus` runs `git rev-parse --show-toplevel` and
`git status --porcelain` there. With the hook's `GIT_DIR` inherited, `--show-toplevel` reported the
clone (cwd becomes the work tree when `GIT_DIR` is set without `GIT_WORK_TREE`), so the exact-root
check passed, and `status` compared the *project's* index against the clone's files: every project
path showed as a tracked deletion and every Morpheus file as untracked. Reproduced in
`tests/git-env.test.ts` with real `git merge`, `git pull` and `git rebase` in a linked worktree with
real `post-merge`/`post-rewrite` hooks: the old runner's status came back `" D tracked.txt\n?? package.json"`.

Measured on Git 2.54 (Apple Git-157), the variables each hook received:

| Operation | Linked worktree | Main checkout |
|---|---|---|
| merge / pull / rebase / commit --amend at top level | `GIT_DIR=<abs>/.git/worktrees/<name>`, `GIT_PREFIX=` | `GIT_PREFIX=` only |
| merge from a subdirectory | — | `GIT_PREFIX=sub/` |

So the main-checkout observation was **not reproduced** on this Git: a top-level merge, pull,
`pull --rebase`, rebase or amend in a main checkout exports no `GIT_DIR`. It may have come from an
invocation that does export one (a GUI or agent tool running `git --git-dir=…`, or an older Git).
The fix covers it either way, because it removes the variables regardless of who set them.

`git clone` ignores the inherited `GIT_DIR` — pinned by a test that checks the project's refs are
unchanged — so the failure never wrote into a project's repository.

## What shipped

- `src/git-env.ts`: `gitSubprocessEnv()` strips Git's repository-local set
  (`git rev-parse --local-env-vars`) except `GIT_CONFIG`, `GIT_CONFIG_COUNT`,
  `GIT_CONFIG_PARAMETERS`, plus `GIT_NAMESPACE`. Config is kept deliberately: CI injects
  credentials and `safe.directory` through it, and config cannot redirect a command to another
  repository. A test fails if the installed Git knows a local variable the helper does not handle.
- Used by every git runner that targets an explicit repository and could run under a hook or
  across repositories: `self` (install/update/status runner, including `pnpm`/`npm` there),
  auto-update hook path lookup, `session/git.ts`, `session/start.ts`, `trunk-health`,
  `trunk-rescue` (its private-index override now layers on a scrubbed base, so an inherited
  `GIT_INDEX_FILE`/`GIT_DIR` can never aim its `reset --hard` elsewhere), `doctor`, `pm claim`.
- The dirty-source refusal names the checkout: `The source checkout <path> has local changes`,
  followed by the existing per-path listing.

Not changed: other `execFile("git")` sites (`pm ship`, `git-sha`, review, check, iOS, QA) run on
the invoking repository from an interactive command, not from a hook; the managed hook block
itself, since fixing the source avoids re-writing hooks in every registered project.
