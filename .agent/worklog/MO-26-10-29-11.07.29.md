# Audit and standardize HQ product design

## Outcome

The cross-project audit is now a durable HQ product/design standard, migration sequence, three
follow-up roadmap items and first-draft Chief Product Officer and VP Design skills. The standard
separates shared presentation behavior from project meaning and preserves detailed evidence behind
an executive-first path instead of treating concision as deletion.

No Lakina, Darwin or Evo page was changed or deployed. Those migrations remain separate reviewed
project work. No paid service was added. Factory routing stayed disabled because Chris did not opt
in; three ordinary read-only audit agents covered the project repositories in parallel.

## Audit method

- Rendered authenticated HQ pages in Brave and inspected desktop and 390px mobile behavior:
  Lakina home and EXP-031 DCF report/table; Darwin home, nutrition instruction, Evo hub, Feature Lab
  and algorithms notebook; and the standalone Evo `/hq` route.
- Saved baseline captures outside the repository under the session visualization directory.
- Inspected accessibility trees, computed page/table dimensions and counted document structure
  where useful. The Lakina table is 2,194px wide inside a 1,055px scroll region; the report is over
  44,000px tall. Darwin's nutrition instruction is 2,739 words, 18 headings and has no authored
  same-page links or local outline.
- Audited `origin/main` source and relevant history in Lakina, Darwin and Evo. Each bounded agent
  distinguished shared-system causes from project-local content/data responsibilities and returned
  exact source evidence and migration canaries.
- Reviewed current external baselines from W3C WCAG 2.2, GOV.UK Design System and U.S. Web Design
  System. No dependency or generic module was needed for the guidance.

The Morpheus codebase-memory MCP transport closed on both parent attempts after installation, so the
parent stopped retrying under the loop-break rule and used direct source reads. The repository audit
agents independently used graph evidence where available, checked coverage and fell back to exact
source for stale or partial paths. This limits no source-backed finding, but the parent makes no
exhaustive graph-completeness claim.

## Material findings

1. **Shared hierarchy, not isolated polish, is the primary gap.** Strong pages already exist:
   Darwin's Evo hub and algorithms notebook lead with purpose, current focus, evidence and action.
   Weak pages make metadata, tentative internal context or exhaustive prose compete with the task.
2. **The Lakina screenshot is an integrated component-boundary failure.** Page CSS removes the
   shared Filter button's border; 14 narrow headers compete with 44px help controls. The shared
   table does not own its complete control, scroll, responsive and accessibility boundary.
3. **Long documents need a presentation contract.** All three projects have legitimate detailed
   records, but authored summaries, active outlines, stable fragments, bounded related navigation
   and appendices are inconsistent or absent. Darwin's generic renderer also opens bare fragments
   as external links and gives large directories an unbounded sibling footer.
4. **Brand parity is stronger than component parity.** Colors are generally recognizable, while
   typography, semantic tokens, shells, breadcrumbs, cards, tables and chart frames are frequently
   local. HQ should share product character and semantic roles without copying product density.
5. **HQ content changes can be visual changes.** Current process often excludes `hq/**` from visual
   evidence even though source order, headings and tables render directly. The new standard uses
   structural triggers rather than requiring screenshots for every typo.
6. **Evo HQ ownership is ambiguous.** Darwin is the recorded canonical Evo HQ, but Evo still
   exposes an `/hq` scaffold and navigation. Resolve the name/owner before migrating both surfaces.

## Design and implementation

- `docs/runbooks/hq-product-design.md` defines the 5-second / 30-second / deliberate-study reading
  contract, four page templates, navigation/disclosure rules, brand/layout/accessibility rules,
  shared component ownership, table/chart contracts, visual review, phased migration and metrics.
- Architecture and agent instructions now point HQ work to the standard.
- `chief-product-officer` owns product outcomes, evidence, prioritization, the product brief and
  adoption evidence. `vp-design` sits beneath it and owns experience audits, hierarchy, interaction,
  design-system reuse and final-build validation. Both are canonical agent/Claude mirrors printed by
  `morpheus product guide`, while managed projects receive drift-resistant one-file pointers.
- `src/project-skills.ts` remains the sole reusable-skill registry. New tests pin canonical mirrors,
  links/references, hierarchy, CLI topics, descriptions and scaffolding for all project kinds.
- Follow-ups: MO-26-10-29-11.15.17 (shared document shell), MO-26-10-29-11.15.20 (data tables and
  charts), and MO-26-10-29-11.15.23 (cross-project canaries and Evo HQ ownership).
