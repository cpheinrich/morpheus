# Qualify Xcode access for an isolated Fleet worker

The operator authorized worker build access and host rollout while keeping capacity and CI budgets as configured. Existing review, source admission, lease and cleanup continue to own the job lifecycle. The repair is bounded to Xcode worker execution. See #707 for the wider Fleet workspace work.

An iOS execution account reproduced the missing cache write under the stock Codex workspace sandbox. Explicitly permitting the cache and device-set paths restored the cache write but CoreSimulator still could not connect. The same account outside that sandbox wrote its own cache, passed two SwiftPM test runs with its own scratch and cache, and booted and deleted a disposable iOS simulator. Enroll only this mode through a root-protected config, a private dedicated account and a Git-pinned checkout.

The exact candidate config reader was also run as the execution account with a root-owned, group-readable file. It recognized the file as operator-controlled and the account could not write it. The same contents copied to the worker's workspace did not confer operator authority. This is pre-rollout qualification, distinct from a Fleet receipt.

Validation covered the unattended-worker suite (27 passed), the three directly affected config and executor tests after the final path check, repository typecheck and compile, Factory source checks, PM index and diff check. Morpheus complexity passes at CCN 15 for ten checked functions across three measured files.
