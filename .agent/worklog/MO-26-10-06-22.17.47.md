# MO-26-10-06-22.17.47 — web QA overlay takes the site's own address

- Symptom: Google sign-in in Lakina's overlay (localhost:4342) failed with
  `auth/requests-from-referer-http://localhost:4342/-are-blocked`; the Firebase browser key allows
  `http://localhost:5173/*` only. Not fixable in the proxy: the browser calls Google directly.
- Rejected: widening the GCP key's referrer allowlist (a security setting per project, and every
  checkout gets a different overlay port).
- Built: `{port}` placeholder in `qa.web.command`. When the preview starts the dev server it runs it
  on the first free port above the site's and the overlay listens on the site's own port. Attach
  mode keeps the separate port and `start` explains the sign-in consequence.
- Verified for real on Lakina main with `["npx","next","dev","--port","{port}"]`: overlay on 5173,
  dev on 5174, `/hq/sign-in` -> Continue with Google reached the firebaseapp.com popup with no
  referer error. (The Browser pane blocks agent-initiated popups; the human completes sign-in.)
