# Adopt the Lizard TypeScript fix pin

## Ask

Move the shared analyzer pin to the root-verified Lizard build that fixes template literal types
inside TypeScript interface and object-type bodies, with a mandatory canary that fails the old pin.
Keep advisory Morpheus/Lakina, the cognitive warning and Evo's enforcement unchanged. Budget:
existing gateway capacity only.

## What changed

- `src/complexity/pin.ts`: commit `484bbd057c126bdb3c7a18e83e98d5114aa9a7ee`, reachable from the
  annotated tag `morpheus-analyzer-2026-11-06-ts` (object `288f6dc3…`). Requirements (Pygments
  2.21.0, pathspec 1.1.1, same hashes) and the Python floor are unchanged. The old tag
  `morpheus-analyzer-2026-11-06` → `7f14ea5` is untouched; it is the new commit's first parent.
- `src/complexity/lizard_runner.py`: a fourth canary file, `canary.ts`, byte-identical to the
  root's strict-`tsc`-valid repro (`sha256 1a4826fd…`). `CANARY_EXPECTED` gains its three rows.
- `tests/complexity-check.test.ts`: the canary list, and a test that installs `7f14ea5` through
  the real installer and asserts the exact refusal ("canary.ts choose measured no such function").
- `docs/runbooks/complexity.md`: the current pin, PR 562 and the old-pin test. `dist/` recompiled.

## Result

- The new pin installs and passes `complexity install --check`; the canary measures exactly the
  contract's rows. On `7f14ea5` the same file is one `*global*` row (CCN 6, cognitive 3).
- Removing the TS rows from `CANARY_EXPECTED` makes the old-pin test fail (`ok: true`), so the
  guard is wired to the canary rather than passing by accident.
- **Evo, frozen `ab95f3d`: no deltas.** `complexity check --all --json` with main's CLI (`7f14ea5`)
  and with this branch (`484bbd0`) produced byte-identical 5.6 MB reports. Evo has no field whose
  type is a template literal with an interpolation, so the bug never fired there. See Appendix A
  for why the totals differ from the expected 776/11,627.
