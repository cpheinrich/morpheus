## Context

Morpheus had nowhere to keep context produced by collaboration *between people*. Everything captured
was either agent↔human (inboxes) or work state (`hq/product/`). Meetings, chat, and who the
collaborators even are had no home.

Chris's intent, restated: **every piece of context that can be digitally captured should be captured
or referenced in the repo**, so an agent starting cold can reconstruct not just what the state is
but why.

## The two things that decided the design

**`hq/` is organised by business function; this material is a medium.** Product, brand, marketing,
finance, ops are *what work is about*. A meeting is not a function — one covers three. The tell that
a second category already existed: `hq/inbox/` always sat at the top of `hq/` rather than under a
function, because it records communication rather than holding work. So `hq/team/` does not invent a
category; it gives the existing one-member category three more members.

**Raw versus distilled.** §7.5 pairs each raw log with one distillation. A transcript is raw — high
volume, low signal, irrelevant within a week — and storing transcripts would make an agent's context
*worse*: it would read more and know less.

Settled: **notes are always summaries**, written by whoever is in the meeting into a canonical format
with a redaction pass. The valuable half is the edges out — decisions to `decisions.md`, action items
to the roadmap.

## What shipped

```
hq/team/
├── README.md                 what lives here
├── members.md                the roster
├── cpheinrich.md             the inbox, at the root
└── meeting-notes/
    ├── README.md             canonical format + the redaction rules
    └── MO-26-08-03-09.30.00-sample-note.md   ← sample, to be stripped
```

- **`morpheus team validate`** — roster shape, note frontmatter, and the cross-check that matters:
  **an attendee must resolve to a member**. A handle resolving to nobody is either a typo or a
  collaborator nobody wrote down, and the second is how a roster goes stale unnoticed.
- **`redacted:` is a schema field**, so CI refuses a note that skipped the pass. A convention gets
  forgotten; a parse error does not.
- **The heartbeat reports the gap, never fetches.** Granola is a claude.ai connector and iMessage is
  a local database — neither is reachable from a CI runner, so a beat that tried to pull would either
  need credentials it should not have or find nothing and report a clean sweep. It surfaces how stale
  the record is and which notes produced no roadmap items; an interactive session does the ingestion.

## Decisions inside the build

**A note's timestamp is the meeting's wall clock, not a fixed zone.** Roadmap ids pin Pacific so ids
from different machines are comparable. A meeting is different: 09:30 in Berlin should read
`09.30.00`, because that is what everyone in the room calls it, and the offset in `occurred` keeps
the instant recoverable. A deliberate divergence from the rule directly above it, stated because an
unstated difference between identical-looking things is how they rot.

**The roster is `members.md`, not `.yaml`.** YAML needed a new runtime dependency in `morpheus-kit`,
which ships to every project, for one file. `gray-matter` already parses frontmatter, and it keeps
`hq/` uniform.

**One `INBOX_DIR` constant.** Nine modules held the literal `"hq/inbox"`. Three bugs in one week came
from a value written twice and drifting — the branch-id pattern, the fetch arguments, the `today()`
zone — and a tenth copy was not going to be the one that held. A test now asserts no reader
hand-writes the exclusion, after the roster was misread as an inbox by three of them in one
afternoon.

## What is deliberately not here

- **Group chat.** The privacy decision comes first: chat contains other people's words, git is
  append-only in practice, and "one chat per project" will not survive iMessage threads that follow
  people. Opt-in per project and an explicit refusal on public repos, before any adapter.
- **The other five repos.** Chris: Morpheus first, then the same move once it settles.

## Test plan

- `pnpm test` — **587 passed**, 26 new in `tests/team.test.ts`.
- Schemas both ways: a note missing `redacted` is refused; a timestamp YAML already turned into a
  Date is tolerated (the trap `isoDate` exists for, one layer up); a timestamp with no offset is
  refused, since the id depends on one.
- `validateTeam`: attendee resolution, a **missing** roster treated as absent rather than an error, a
  malformed one reported, duplicates caught, and an id disagreeing with `occurred` caught.
- `meetingContext`: `null` rather than zero when a project keeps no notes; staleness from the most
  recent; unpromoted notes oldest-first.
- Exercised end to end — `team validate`, `inbox validate`, `pm validate` and `doctor` all clean on
  this repo after the move.
