## Context

Chris asked whether it is clear that the complexity toolkit only needs the analyzer on changed
functions, not the whole codebase. The default `morpheus complexity check` is targeted, but the
canonical refactoring prompt (v1.5) and `docs/runbooks/complexity.md` told agents to get the
"before" family metrics from `check --all --json` in a detached worktree at the base: a routine
whole-repository scan, and one that labels pre-feature trunk code as "before the refactor".

## Approach

Documentation and prompt only; no analyzer, CLI, policy or CI change. The before side is the
targeted `check --json` that found the candidate, saved with its commit and analyzer pin before
editing; the after side is the same command on the final source. `--all` stays for a baseline
inventory, enrolment in `enforce` and pin moves, and enforcing CI keeps measuring every in-scope
file as the backstop. A missing row is unmeasured, not zero; a cleanup of untouched code uses the
supplied candidate report or reports the before metrics as unavailable. Prompt bumped to v1.6 and
`dist/` recompiled.
