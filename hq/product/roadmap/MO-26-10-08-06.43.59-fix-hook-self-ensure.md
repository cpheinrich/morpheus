## Context

The managed `post-merge`/`post-rewrite` blocks run `morpheus self ensure`. Inside a hook it failed
with "The source checkout has local changes; install from clean main." even though every Morpheus
checkout was clean, while a manual `morpheus self update` straight afterwards succeeded. Observed
2026-10-08 after a trunk merge in a Lakina worktree under `~/code/.morpheus-worktrees/`, and
earlier in Lakina's main checkout. Auto-update therefore silently never worked from worktrees.

## Approach

Git exports `GIT_DIR` (absolute, in a linked worktree) and `GIT_PREFIX` into hooks. Every git
subprocess Morpheus spawned inherited them, so `git status` inside the disposable Morpheus clone
read the project's repository and index and reported the project's files as the clone's local
changes. Fix at the source: one helper, `src/git-env.ts`, strips Git's repository-local variables
(`git rev-parse --local-env-vars`, minus the config ones) and is used by `self`, auto-update hook
repair, the session/context git runners, trunk rescue, `doctor` and `pm claim`. The dirty-source
error now names the checkout path. Tests run real merges, pulls and rebases with real hooks and
assert the inspection targets the intended checkout; they fail without the scrub.
