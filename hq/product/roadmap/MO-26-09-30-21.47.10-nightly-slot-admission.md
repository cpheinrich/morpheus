## Context

Evo's nightly admission reserves one automated release per Pacific calendar day in a morning
window. With PR CI no longer running the iOS unit suite and the Mac mini's capacity moving to
ephemeral VMs, Chris wants the full release pipeline to run more often, about every six hours,
as a no-op when `main` has no iOS changes, and to skip a slot while the recovery agent still
owns an incident from the previous run rather than piling up. The admission core is shared
(`src/ios/nightly-core.ts`, vendored into each app), so the schedule shape belongs here.

## Approach

Add an optional `slotMinutes` to `AdmissionConfig`: the local day divides into slots of that
size, `window` becomes relative to the slot start, and one automated release is admitted per
slot. Slot keys append the local start time (`2026-10-01T0600`) so day-long state and run titles
are unchanged; the existing per-day behaviour is the default. An open incident, an active run or
an unchanged `main` spends or skips the slot as the day version does, and the next slot retries.
Apps opt in by setting `slotMinutes` and re-vendoring the core.
