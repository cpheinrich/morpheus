## Context

#226 made `pr-check.yml` read the live pull request with `gh api repos/<repo>/pulls/<n>`
through the job token, so reruns see current labels and body. In a consuming repository
whose default workflow token is GitHub's "read" setting (contents and packages only), that
read answers `Resource not accessible by integration (HTTP 403)` and the required check
fails on every pull request. Evo hit this within minutes of the release: every
`pr / conventions` run since 02:19 UTC on 2026-09-11 failed the same way, on every open PR.

## Approach

Declare `contents: read` and `pull-requests: read` on the reusable job and document in the
header that the caller must grant the same. A called workflow can only narrow what its
caller grants, so the declaration cannot fix a consumer by itself; it makes a caller that
omits the grant fail at workflow validation with a clear message instead of at runtime with
a 403, and the header shows the caller shape that works. Evo's caller is updated in
darwin-health/evo EV-26-09-10-19.43.46.
