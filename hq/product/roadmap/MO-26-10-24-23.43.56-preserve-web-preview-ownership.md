## Context

Issue #494: renaming the manifest project from cpheinrich.com to cpheinrich left the checkout root unchanged but changed both the web preview cache namespace and launchd label. Status missed the original session; stop reported success while the original supervisor and owned dev server remained alive. The operator independently stopped those processes before this task.

## Approach

Keep new web preview state/labels independent of display names, discover matching legacy namespaces, and validate exact checkout/dev directory plus registered supervisor/state-file arguments before acting. Refuse foreign, ambiguous, malformed, locked or unverifiable records. Confirm shutdown or report that no termination was established. Preserve legacy leases in place until their verified registration stops.

## Acceptance

- New and legacy sessions survive a manifest/namespace rename through start/status/stop without losing the original log/state or leaving owned fixture children/listeners alive.
- Different checkouts, wrong supervisor arguments, ambiguous registrations, unknown inspection errors and answering orphan services cannot trigger an arbitrary bootout or false successful stop.
- Focused lifecycle/readiness/preview tests, typecheck, lint, compile, indexes, independent review and CI pass.
- Existing user previews, responders, website files and installed CLI are not mutated by this task.
