## Context

Evo built consumer accounts in about a day (darwin-health/evo#58, E2E suite in #62), including two
agent-review rounds that surfaced fifteen real security and correctness issues — login CSRF, an
enumeration oracle from a shared Response body, a backslash open redirect, a cross-device
verification lockout, a burned action link from generate-before-deliver. The next Morpheus project
should get all of it in hours, with those mistakes impossible-by-construction. Scope is web apps on
the Morpheus stack contract — Next.js App Router on Vercel, WIF in production and a scoped key on
staging, Spark, two Firebase projects, emulator-tested with no secrets — not any Firebase app.
cpheinrich/morpheus#135 is the umbrella; #136 landed the reusable CI workflow and the manifest
staging fields.

## Approach

`morpheus web add-consumer-auth`, same command family and mechanics as `web init`. Templates are
Evo's actual files with project values lifted into a context — 47 of 52 reproduce Evo
byte-identically, the other five differ only where an Evo-only fact in a comment was generalised.
Four layers: verbatim plumbing, codified policy routes, starter pages the project owns, and the
three emulator-backed suites as the contract, wired into CI via `firebase-tests.yml`. Never
overwrites; `--check` reports drift of the shared plumbing/policy files against the current
templates. The staging project's SDK config comes from the same provisioning path `web init` uses,
pointed at `accounts.firebaseStaging`. The console half is a human runbook,
`docs/runbooks/consumer-auth.md`.
