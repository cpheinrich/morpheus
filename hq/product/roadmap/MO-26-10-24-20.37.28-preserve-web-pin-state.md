## Context

Chris found web QA pins detached from their original dialogs and screenshots captured only at Send, after the relevant view had changed. Issue #482 tracks compact placement HTML/hierarchy and observable state as primary evidence, supplemented by one capped quality-0.5 JPEG of the visible application viewport per pin.

## Approach

Freeze allowlisted semantic context and an inert styled viewport clone synchronously at placement, then render only that frozen clone. Keep original timestamps, coordinates and image scale; retain drafts and pending frozen snapshots across reload. Markers require the same route, view/entity identity and target fingerprint; sidebar comments stay available. Support element/view/page scope, bounded storage and explicit image failures without losing HTML evidence. Preserve legacy PNG and draft compatibility.

## Acceptance

- Real Chromium and WebKit overlays preserve distinct placement HTML/state and JPEGs through immediate modal changes, nested scroll, resize, navigation, reload and Send.
- Different artist dialogs and recycled targets hide old markers; returning to the original view restores them.
- Images cover the viewport, longest edge at most 1600 pixels, JPEG quality 0.5; explicit viewport coordinate/scale metadata maps the original click.
- Sensitive query parameters, private/hidden/password/file values and unrestricted stores/attributes are excluded from semantic evidence.
- Bounded clone work, IndexedDB records and payload limits fail honestly while comments remain editable/sendable.
- Focused tests, typecheck, generated dist, documentation, final visual captures and independent review pass before merge.
