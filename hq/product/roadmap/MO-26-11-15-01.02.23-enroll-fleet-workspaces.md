## Context

Fleet attempts currently bind one source revision. A project that needs changes across related repositories or needs a pinned comparison base cannot complete the same work as an interactive Factory workspace.

## Approach

Define an operator-enrolled workspace policy and bind permitted repositories, base revisions, execution profile and credential references to a single attempt. Keep checkout and credential authority explicit and preserve backward compatibility for single-repository tasks.

## Acceptance

- Both Fleet submission routes authorize the exact repository set and revisions before launch.
- Related checkouts are isolated and the operator-approved comparison refs support normal validation.
- Undeclared repositories, credentials and profile changes are refused.
- Receipts distinguish source, prepare and invocation failures and attest the immutable workspace binding.
- Synthetic qualification exercises the supported flow without requiring real credentials or changing live enrollment.


## Implementation evidence

The source binds an operator-declared repository set, profile, comparison snapshots and
credential-companion manifest/revision references before placement. The dedicated account
verifies protected authority, materializes writable checkouts, and retains the binding through
continuation, reporting and receipts. Fixed prelaunch diagnostics distinguish fetch, checkout
and executor invocation without weakening indeterminate cleanup holds.
