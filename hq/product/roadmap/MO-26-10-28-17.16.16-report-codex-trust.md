## Context

Codex runs a repository's `.codex/hooks.json` only after the user trusts each hook with `/hooks`,
and says nothing when it declines. Since the read hook (#547) and the poll guard (#545), an
untrusted hook silently returns `context refresh` to the bare assertion and lets polling through.
On this machine Morpheus and Kairos had no trusted Codex hooks, and Lakina's one trusted hook had
gone stale when its command changed — none of which any command reported.

## Approach

`morpheus doctor` reads `~/.codex/config.toml` (or `$CODEX_HOME`) **read-only** and reports every
hook in the `.codex/hooks.json` Codex actually runs that has no trust entry, a stale `trusted_hash`,
is switched off, or sits in an untrusted project, with the exact instruction: open Codex in the main
checkout and run `/hooks`, trusting the named hooks. The trust key and hash are reproduced from
Codex's source (0.163.0–0.165.0) and pinned by tests against hashes Codex itself computed. In a
linked worktree it reports the main checkout's file, which is what Codex runs there, and warns when
the worktree's own file differs. It never writes Codex's config.

## Acceptance

- Run in `~/code/morpheus`, `~/code/evo`, `~/code/lakina` and `~/code/kairos`, `doctor` lists the
  same untrusted and stale hooks that `codex app-server`'s `hooks/list` reports for those paths.
- Run in a task worktree, it points at the main checkout's `.codex/hooks.json` and path.
- An unreadable config reports trust as unknown, never as untrusted.
