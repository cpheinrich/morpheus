## Context

Claude's stored five-hour utilization could remain full after its window reset because the
Factory read account-list snapshots and assigned no reset time to that value. Inspect the
existing gateway API and make a small freshness correction without another refresh service.

## Approach

Read Claude usage through the gateway's existing active usage endpoint on each inspection,
start and doctor. Honor its reset times, preserve unknown on a failed read, expose the
gateway-reported update timestamp, and retain Codex's stored snapshot/expiry behavior.
Codex's force-refresh endpoint can run a model probe and stamp old data as current, so it
is deliberately excluded. No new dependency, polling loop, age gate or configuration.

## Acceptance

- Stale full Claude account-list values cannot override a current usage response or be reused
  after a failed usage read; repeated inspection reads the endpoint again.
- Reset boundaries are evaluated when responses arrive. Failed Claude reads leave Codex's
  existing snapshot behavior intact, and never request a Codex model probe.
- Inspection and doctor expose reported timestamps with documented upstream cache limits.
- Focused tests, required root checks, independent review and CI pass before merge; verify
  the live read path and update the installed plugin after merge.
