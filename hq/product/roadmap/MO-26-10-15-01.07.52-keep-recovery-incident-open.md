## Context

Evo incident `ios-38526111310` was linked as `issues: [493]` on repair
roadmap items. That made `check pr` require `Closes #493`. GitHub closed the
incident when repair PR #496 merged, before the recovery controller's reserved
release could enter admission. The controller reopened the issue, but the
release had already failed before TestFlight upload.

## Approach

Allow a roadmap item to list controller-owned issues in `issuesToKeepOpen`, a
subset of its linked `issues`. Require `Refs #N` and reject closing keywords
for those issues, while retaining `Closes #N` for normal linked issues. Update
the PR template and runbook so repair workers name the release controller as
the closure owner. The controller closes the incident only after verifying
the exact build's upload, Apple receipt, and ledger.
