## Context

Transcripts from 2026-09-24 to 2026-10-28 show CI polling (`gh run view|run watch|pr checks`)
rising in Claude sessions after `morpheus wait-ci` shipped — 4.0 per session before, 4.6–7.8
after — with `wait-ci` itself almost never run by Claude. Codex adopted it in the last week
(5.4 per session) yet still polls 4.4 times per session. The most repeated polls watch
TestFlight, release and nightly runs by **run id** (`gh run view <id> --json
status,conclusion,jobs`, 75 times in two weeks), which `wait-ci` could not do: it took only a
pull request. Evo's `AGENTS.md` never received the `wait-ci` line, because the 2026-10-07
rollout merged in parallel with `wait-ci`, and nothing reported the gap.

## Approach

1. `morpheus wait-ci --run <id>` and `--workflow <name|file> [--branch <b>] [--sha <s>]`,
   reusing `src/wait-ci/`: same quiet backoff, digest with failing-step logs, exit codes and
   timeout. By workflow, every poll re-selects the newest matching run, following a newer one.
2. A PreToolUse poll guard (Claude Code and Codex, `matcher: Bash`) that refuses the third poll
   of one target in a session and prints the exact `wait-ci` command. Wired by
   `morpheus context install` and `init`; state in the primary checkout's ignored
   `local/sessions/`, so `pm cleanup` of a task worktree is unaffected. Fails open.
3. `morpheus doctor` names missing template guidance in a consumer `AGENTS.md` (wait-ci, wait-ci
   for runs, break loops, focused tests, refresh on refusal) and an unwired poll guard. Then
   one PR per consumer (Evo, Lakina, Kairos) adding the guidance and the hook wiring.
