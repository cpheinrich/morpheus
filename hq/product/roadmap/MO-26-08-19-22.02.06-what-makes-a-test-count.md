## Context

`AGENTS.md` requires "tests for anything testable". That requirement is fully satisfied by a test
which would pass whatever the code did, and nothing anywhere says otherwise — so an agent that
writes one has followed the instructions.

This is not hypothetical. Lakina audited its Python suite (LK-26-08-19-16.42.42) and found the
module its own documentation listed under *working and tested* was covered at 90% by:

```python
assert sharpe_ratio(rising_curve) > 0
assert sortino_ratio(falling_curve) != 0.0
```

Mutation testing showed that adding the risk-free rate instead of subtracting it, dividing by the
annualization factor instead of multiplying, and counting flat periods as downside all passed. The
one test in the file that pinned a number was the one whose mutant died. Sharpe and Sortino are how
a trading strategy gets selected.

Three details argue for fixing this here rather than there:

**The agent that wrote those tests was following the rule.** A convention that is satisfiable by
the failure mode is a convention that produces the failure mode, and no amount of care at the
individual PR fixes that.

**It recurred under maximum attention.** Fixing the finding introduced the same defect: every
pinned Sortino test used a curve with exactly one downside period, where dividing by
`len(downside)` and multiplying by it give the same answer, so the denominator was untested by
tests written to test it. Caught only by re-running the harness.

**A coverage gate cannot catch it.** The same repository, at 87% line coverage, passes all 876
tests after a change its own documentation explicitly forbids.

## Approach

A **What makes a test count** section in `AGENTS.md`, next to the PR requirements rather than in a
separate document, since the requirement is what people read.

Four rules, each stated as a property rather than a metric: assert the value not the sign; test a
guard at its boundary; back a "never do X" comment with a test that fails when X is done; treat
coverage as a floor against deletion and not as evidence of quality.

Then how to check rather than assume — mutation testing, explicitly **not** in CI, with the
three reasons a mutant survives, because "count the survivors" is how this turns into another
number to chase. Plus assertions-per-test as a proxy that costs one AST walk.

The Lakina audit and its harness are linked as a worked example, including the two mistakes made
while fixing it. A convention with a real counterexample behind it is one people believe.

Scaffolded project instructions carry the concise property-level rule and link back to the full
Morpheus section. The failure occurred in a consumer repository, so documenting it only in
Morpheus would leave the rule an agent actually reads unchanged.

**Deliberately not shipped:** a check in `check pr`. Every mechanical form of this rule —
assertion density, mutation score, a coverage floor — is a number, and this item exists because
numbers get satisfied instead of met. Prose that an agent reads before writing the test is the
intervention that fits the failure.
