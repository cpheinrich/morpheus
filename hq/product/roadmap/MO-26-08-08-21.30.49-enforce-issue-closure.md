## Context

The open-issue audit found two completed issues still open: #90 had shipped in PR #102 and #94 had
shipped across PR #97 and the downstream migration PRs. GitHub already closes issues on merge, but
only when the pull request uses a supported closing keyword. Nothing in Morpheus recorded that an
item promised to resolve an issue, and nothing in `check pr` could detect the missing link.

A heuristic over issue mentions is unsafe. “Related to #70” and “Closes #70” are different claims;
automating the first silently retires work that may remain. Closure intent needs a structured home.

## Approach

- Add `issues: number[]` to roadmap frontmatter, defaulting to an empty list.
- Add `--issue <number>` to `pm new roadmap`; reject invalid numbers and use the singular CLI flag
  for the common one-issue item while the schema can represent consolidation work.
- Have `check pr` require a GitHub-supported same-repository closing keyword for every declared
  issue. Report every missing number and the exact `Closes #…` remedy.
- Put the closing line in the PR template and the convention in `AGENTS.md` and the architecture.

## Acceptance checks

- A roadmap item without `issues:` behaves exactly as before.
- An item declaring issue 70 fails `check pr` on a mere mention and passes on `Closes #70`.
- Multiple declared issues must each carry a closing keyword; one does not cover the other.
- `pm new roadmap --issue 70` emits valid `issues: [70]` frontmatter.
- Zero, negative, non-numeric, and non-roadmap uses of `--issue` are refused before writing.

## Implementation outcome

- Roadmap items now parse `issues: number[]`, defaulting to `[]`; `pm new roadmap --issue 70`
  writes the structured intent and rejects invalid or non-roadmap uses before allocation. Existing
  work can add the same intent with `pm link-issue <ID> 70`, and the generated board shows it.
- `check pr` requires a supported closing keyword for every declared issue. It strips HTML
  comments and Markdown code before matching, while accepting ordinary emphasis around a closing
  line, so examples cannot satisfy the rule and real prose still can.
- `AGENTS.md`, the architecture, and the pull-request template carry the workflow at the point it
  is used.
- The PR template no longer pre-satisfies Test plan or Open questions: comment-only guidance is
  invisible to the section check, just as it is to the rendered PR body.
- 773 tests pass, including positive, negative, multiple-issue, numeric-boundary, CLI-boundary,
  existing-item, index-visibility, Markdown-code, and hidden-template coverage. TypeScript, build,
  PM validation, generated-index checks, and `git diff --check` are clean.
