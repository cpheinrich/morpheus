## Context

Found as incidental RV-CHK in the independent review of MO-26-10-07-21.32.39. `pr-check.yml`
checks the Morpheus CLI out into `.morpheus/` inside the consumer's workspace. The new `pr-head`
block runs `git checkout --detach <head>` in that workspace when the checkout is not the PR's merge
commit; if the consumer repository tracks files under `.morpheus/` (Morpheus projects do, e.g.
`.morpheus/session-start.sh`), the checkout can refuse to overwrite them or mix them with the CLI
tree. Before this change the same collision could already occur for the initial checkout, so the
failure mode is pre-existing.

## Approach

Check the CLI out outside the consumer workspace (for example `$RUNNER_TEMP/morpheus`) and invoke it
from there, or check out the consumer into a subdirectory; then a test that a consumer tracking
`.morpheus/` files survives both checkouts.
