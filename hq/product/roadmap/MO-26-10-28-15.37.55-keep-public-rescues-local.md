## Context

`context brief`'s dirty-trunk rescue (#362, refined by #542) commits tracked edits on the trunk
branch to `wip/trunk-<date>-<host>`, pushes the branch to `origin` and opens a draft PR
(`rescueDirtyTrunk` in `src/session/trunk-rescue.ts`). On a public repository that publishes the
edits. The commit message and PR body also carry the checkout's absolute path and the machine's
short hostname. #362 listed this as an open question: on a public repository the rescued tracked
edits become public, and nothing guards it beyond leaving untracked files out.

The first real case is morpheus #452, a draft opened 2026-10-22. It replaced `README.md` with an
agent's private CD execution template, which exposed a Tailscale hostname and local paths. Closing
it does not unpublish anything. A closed PR's diff and commits stay readable on a public
repository, and so does the branch until it is deleted. #542's seven-day age-out closes such a
draft and deliberately keeps the branch, so it keeps the content public too. #542 left #452 open
for Chris.

Morpheus is public by decision ("Public repo, and staying public" in `.agent/decisions.md`). Any
public project repository that runs `context brief` has the same exposure.

## Approach

1. **Read the visibility.** `gh repo view <owner/repo> --json visibility` for the push remote's
   repository, and also for the base repository on a fork. Either one public means local. Cache
   the answer per repository in the primary checkout's ignored `local/` with a short expiry (about
   a day). A repository can be made public, so a cached `PRIVATE` must not outlive that expiry.
   **Unknown is public**: missing `gh`, offline, an error or an unparseable answer all mean local.
   This is the unsafe-direction rule from `learned.md` ("never let an unanswerable question render
   as a confident answer").
2. **On public, rescue locally only.** Commit to the local `wip/trunk-*` branch with the same
   private index, content proofs and reset as today. Never push it and never open a PR. Never
   delete a local rescue branch automatically, because it is the only copy of those edits.
3. **Report it.** `context brief` prints the branch, the diffstat, why it was not pushed, and how
   to recover the edits (`git switch` or `git cherry-pick`). `morpheus doctor` and `doctor --all`
   list unpushed local rescue branches per project. No PR and no manager age-out will ever surface
   them otherwise.
4. **Keep churn and dedupe.** The churn reset is unchanged. Replay dedupe already reads the local
   rescue branches, but today a match also needs the branch's open draft PR (see the comment on
   `DUPLICATE_CANDIDATES`). In local mode the local branch is the match on its own, so a second
   identical dirty trunk does not create a second branch.
5. **Private repositories are unchanged**, PR body included.
6. **Records.** Add a decisions entry that supersedes the publishing half of the 2026-10-08 and
   2026-10-28 rescue entries. Update the `context-freshness` runbook, the `AGENTS.md` line
   "moves tracked edits to a `wip/trunk-*` draft PR" and its mirror in `src/init/templates.ts`.

## Acceptance

- Visibility `PUBLIC`, and a visibility read that fails, each produce a local branch and a reset.
  The fixture remote has no `wip/trunk-*` ref and the runner recorded no `gh pr create`. `PRIVATE`
  still pushes and opens the draft. Tests assert all three by value.
- A cached `PRIVATE` past its expiry is read again.
- `context brief` and `doctor` name the local branch and the recovery command. Tests assert the
  text.
- In local mode a second identical dirty trunk reports `duplicate` against the existing local
  branch.
- The decisions entry, runbook, `AGENTS.md` and template are updated together.
