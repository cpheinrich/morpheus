## Context

Kairos migration review reproduced two holes in the reusable HQ postbuild contract. A populated
generated route was exempted merely because one concrete slug existed, even when its fallback was
not false; and an undeclared exact HQ route, including ISR, was not compared with the declared
static inventory. Both cases violate the deploy-time-only boundary while the current application
can still appear healthy.

## Approach

Require exact `fallback === false` before an emitted source pattern is treated as closed, inventory
every exact prerendered HQ route, compare it with the declared explicit routes, and run the ISR
check across the actual inventory. Encode both reproduced counterexamples in the scaffold test and
refresh committed distribution output.

## Acceptance checks

- A populated generated route with non-false fallback is classified dynamic.
- An undeclared exact or ISR HQ route changes the static inventory and fails the generated checker.
- Source, compiled dist, focused tests, architecture, and website guidance agree.
