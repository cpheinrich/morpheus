## Context

`morpheus wait-ci` reduces the head commit's `statusCheckRollup` contexts to a verdict. The rollup
lists only checks that have reported. A required check that has never reported, which GitHub shows
as "Expected — waiting for status to be reported", is absent from that list. In that state
`wait-ci` can say `green` while branch protection still blocks the merge.

There are two known ways to get there:

- a draft whose caller skips `pr / conventions` (`PR_CHECK_CALLER_IF`);
- since MO-26-10-28-14.08.43, a head returned to a SHA whose only conventions result is
  `pr / superseded`.

`wait-ci` over-reports green; it never opens the gate. The independent review of #544 recorded this
as incidental finding I1.

## Approach

Read the base branch's required check names (branch protection or rulesets) once per wait. Treat a
required name that is missing from the head's rollup as `pending`, and report it by name. If the
required set cannot be read, say so rather than calling the head green. Coordinate with
MO-26-10-28-14.09.01, which is already extending `wait-ci`.
