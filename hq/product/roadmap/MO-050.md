## Context

Morpheus has no heartbeat. Everything starts because a human opened a session, which means the
board only advances when Chris is at a keyboard, and §7.6's ingestion loops — six of them, all
scheduled — describe a cadence nothing produces.

The heartbeat is a **dispatcher, not a doer**. It reads state, decides what should happen next,
raises it, and stops. Doing the work in the beat would put an unattended agent on a timer, which
is a different and much larger decision.

Decided at intake on 2026-08-01: **propose now, dispatch behind an off-by-default flag.**

## The design decision that matters: assess is a ranking function, not a prompt

The handoff spec framed the assess step as a prompt — *given the roadmap, goals, and what is in
flight, identify the highest-leverage unblocked aligned work.* Building it that way makes the
heartbeat unrunnable without a model credential, untestable in CI, and dead at the first billing
failure. It also makes a cron job non-deterministic, which is a bad property in something that
runs unattended twice a day.

So: **the beat is deterministic, and the model is an optional second opinion.**

Everything the spec asks for in step 2 is computable from files already in git:

| Question | Answered from |
|---|---|
| What is in flight? | live claim branches, minus blocked ones (MO-049) |
| What is unblocked? | `status` not in `blocked / shipped / dropped`, and unclaimed |
| What is aligned? | `goal` resolves to a goal that is not `achieved` or `missed` |
| What is highest-leverage? | priority, then goal status, then age of `updated` |
| Should anything happen at all? | in-flight count against the ceiling |

`--assess` later lets a model reorder or veto the ranking. Absent a credential the ranking stands
on its own, which means the heartbeat ships and runs **today** rather than after a secret exists.

## Approach

`morpheus heartbeat [--ceiling N] [--json] [--dispatch]`, plus `.github/workflows/heartbeat.yml`
on a schedule.

**Read.** Board via `parseArtifact`, goals likewise, live claims via `listClaims`.

**Assess.** Produce a `Beat`: in-flight list, blocked list, the ranked candidates, the pick, and
the reason. Pure function over parsed inputs — no I/O, so it is directly testable.

**Propose.** The default. Prints the beat, writes a GitHub Actions job summary, exits 0. **It
writes nothing to the repo.** A scheduled job that commits would have to push to protected `main`,
which agents may not do; the job summary is durable enough and has no such problem.

**Dispatch.** `--dispatch`, off by default, config-gated by `heartbeat.dispatch` in
`morpheus.json`. With no model credential present it **refuses with a named reason** rather than
degrading quietly — the seam is real and tested, the far side is empty until a key exists.

**Record.** Nothing new. The board is already the completion record and `pm claim` already
reconciles it.

### Guards

- **Concurrency ceiling** (default 3). At or above it the beat picks nothing and says why. This is
  the guard against a runaway queue, and it is the one thing that must not be advisory.
- **Blocked is not in-flight.** A blocked claim holds a branch but consumes no lane. Without this,
  one unanswered question permanently costs a slot — the failure mode that makes ceilings useless.
- **Nothing is a valid answer.** An empty beat exits 0 with a reason. The heartbeat has to be
  comfortable doing nothing, or it will invent work to justify itself.
- **Blocked-but-actionable** items are re-surfaced in the beat, not re-raised in the inbox —
  MO-049 already filed them, and a nagging cron that duplicates items trains people to ignore it.

## Non-goals

Not a project-management tool. It does not create roadmap items, split them, or reprioritise — it
picks from what exists. An empty board is a real answer and the right one is a human filing work.

## Test plan

- The ranker is a pure function, so it gets the bulk of the tests: priority order, goal alignment
  as a tiebreak, `updated` age as the final tiebreak, and stability given equal inputs.
- Ceiling: in-flight at the ceiling picks nothing; one under picks one; blocked claims are excluded
  from the count — asserted directly, since this is the guard that makes the whole thing safe.
- Empty board, all-shipped board, and all-blocked board each exit 0 with a stated reason rather
  than a crash or an empty pick presented as success.
- `--dispatch` with no credential refuses and names why; the exit code distinguishes "refused"
  from "nothing to do".
- `--json` output validates against the `Beat` schema.
- The workflow is exercised by running the CLI locally against this repo's real board and
  comparing the pick against what a human would choose.

## Open questions

**Cadence.** The spec says twice daily, matching the inbox rhythm. Left at `0 9,17 * * 1-5` in the
