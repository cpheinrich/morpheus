## Context

Morpheus carries reusable skills, but older managed projects receive a new pointer only when an
agent knows to re-run the whole scaffold. That made the newer CTO, research and DevOps personas
effectively invisible in several registered projects. A separate per-project JSON index would make
discovery explicit but would duplicate the names and routing descriptions already loaded from
`SKILL.md` frontmatter.

## Approach

Treat loader-native skill entrypoints as the project index. Add one typed distribution registry in
Morpheus that drives new scaffolds, human and JSON catalog output, and an idempotent sync/check for
established projects. Parse catalog descriptions from the rendered skill frontmatter, preserve
every existing project-owned file, and make tests fail when a canonical skill directory is not
classified or its provider entrypoints diverge from the registry.

## Acceptance

- `morpheus skills list --json` returns the reusable project catalog from one source of truth.
- `morpheus skills sync [--check]` adds or reports missing loader-native entrypoints without
  overwriting an existing file.
- `morpheus init` and sync consume the same registry for company, personal and internal projects.
- A future canonical skill must be classified project-facing or Morpheus-only for tests to pass.
- Every registered Morpheus-managed project is synced through its normal reviewed PR lifecycle.
