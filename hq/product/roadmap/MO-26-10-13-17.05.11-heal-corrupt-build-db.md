## Context

A job cancelled mid-build (a PR's cancel-in-progress, a VM torn down) leaves the build
service's SQLite database `XCBuildData/build.db` half-written on the shared per-slot cache
disk; every later job on that slot fails before compiling with "no more rows available",
"database disk image is malformed" and "internal inconsistency error". darwin-health/evo lost
runs 38486255994 and 38487005844 this way on 2026-10-13 (#394), and the slot stays poisoned
until a person deletes the image on the host.

## Approach

In `ios-ci.yml`: "Prepare isolated build directories" runs `sqlite3 -readonly ... 'PRAGMA
quick_check'` on a cached build database and discards only `DerivedData/Build` when it is not
`ok`; "Build for testing" and "Build" retry once cold when `xcodebuild` fails with a build
service message. Package checkouts and the module cache are kept; warm builds are kept; a
poisoned slot costs one cold build. Step-level tests run the real step scripts against stub
`sqlite3` and `xcodebuild` binaries.
