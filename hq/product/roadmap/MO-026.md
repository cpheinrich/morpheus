## Context

Found by running the generator end to end against Evo's actual answers before handing it over.

`generateBrand` deliberately does not scaffold `tokens.json` when `visualSource` is set — the
existing system is canonical, and a second token file is the worst failure the command can cause.
But MO-022 then added `tokens.json` to the required set unconditionally, so `brand status` reported
it **missing** on exactly those projects.

The two halves disagreed: the generator refused to create the file and the checker demanded it.
Following the checker means creating the second canonical source that architecture §15.1a exists to
prevent.

## Shipped

A fourth state, `delegated` — required, and satisfied elsewhere on purpose. Rendered `→ tokens.json
— canonical at apps/web/app/brand`, and it counts toward completeness.

## Why this and not "drop the requirement"

Dropping `tokens.json` from the required set when `visualSource` is set would report the same
package as complete while saying nothing about where the tokens actually are. `delegated` states
the location, which is the thing a reader needs.
