## Context

Chris asked for a reusable DevOps skill that owns timely CI/CD delivery and recovery,
with durable memory and event/deadline-driven supervision rather than a forever chat.
He also requested multiple tags on Morpheus's own tickets and corresponding worklogs,
independent of the separate Paperclip workforce exploration.

## Approach

Add optional validated `tags` to roadmap/worklog frontmatter, repeated `pm new --tag`
intake and read-only `pm tagged` retrieval. Existing untagged records remain valid;
new DevOps work uses both `engineering` and `devops`, and generated blocked worklogs
keep the item's tags. Tags describe subject matter, never authority or ownership.

Distribute `devops-engineer` through the existing canonical skill, Claude mirror,
`morpheus cto guide` and scaffold-pointer path. Define deadline eligibility, incident
ownership, evidence-based closure, resumable context and escalation. The skill does
not activate another scheduler/controller or replace V2's fenced effects owner.

Acceptance: real parser/CLI tests retain and retrieve multiple tags, reject malformed
metadata, preserve legacy files, and keep blocked-record tags. Both provider skills,
installed guide and consumer pointers agree. Independent scenario evaluation must
exercise healthy/no-change, missed eligible delivery, artifact failure, unknown
provider outcome, existing repair ownership and budget/credential limits.

Implementation is local until the coordinating CTO allocates publication funding;
no new live supervisor or provider action is part of this source change.
