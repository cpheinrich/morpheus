## Context

MO-26-10-28-15.37.55 stops new trunk rescues from being pushed to public repositories. Its
independent review (finding R-5, incidental) found two rescue branches that older rescues had
already pushed to public `cpheinrich/morpheus`. Neither branch has an open PR:

- the `wip/trunk-2026-10-08-*` branch at `fbf69e3b`, which changes one roadmap item
  (`MO-26-09-16-04.21.12-isolate-release-simulator.md`);
- the `wip/trunk-2026-10-25-*` branch at `990d0136`, which changes `docs/paperclip-overview.md`.

Their commit messages were written before that change, so they still carry the absolute checkout
path, and the branch names carry machine hostnames. `git ls-remote origin 'refs/heads/wip/trunk-*'`
lists them. #452's branch, the first case, was deleted on 2026-10-28 at Chris's request.

Deleting a remote branch cannot be undone from the remote. A branch may be the only copy of its
edits, unless a clone still holds a local branch of the same name.

## Approach

Ask Chris, then act on his answer:

- **A — save, then delete (recommended).** Keep a private copy of each branch, for example a bundle
  under the ignored `local/rescued/`, verify the copy, then delete both remote branches. This is
  what #452 received.
- **B — adopt or close by content.** Inspect each diff first. Move anything still wanted onto a
  roadmap item's branch, then do A for the rest.
- **C — leave them.** Treat the paths and hostnames as low sensitivity.

Verify with `git ls-remote origin 'refs/heads/wip/trunk-*'` afterwards.
