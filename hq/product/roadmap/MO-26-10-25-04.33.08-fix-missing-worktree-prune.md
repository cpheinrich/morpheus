## Context

Chris reported `pm worktrees prune` aborting with `git rev-parse --show-toplevel` after a task directory had been deleted. The CLI inventories every registration before pruning; a surviving registered directory without its `.git` file triggers that exact error and prevents removal of unrelated absent registrations. A wholly absent directory alone already works.

## Approach

Prune from the caller using Git registration paths, without checkout inventory. Remove only absent, unlocked registrations from Git’s administrative metadata; never invoke directory-removing operations. Preserve branches and surviving directories, including a checkout restored immediately before metadata removal.

## Acceptance

- Regression reproduces the reported Git error before the fix and passes after it.
- Missing-directory, surviving broken checkout, locked registration, and dry-run cases preserve all branch refs and surviving data.
- Focused tests, full suite, typecheck and compilation pass.
- Independently reviewed PR with green CI; Chris owns merge.

## Scope decision

Branch-only cleanup is not included: the existing roadmap and session proofs depend on a worktree identity. A safe extension needs commit-based item validation, session association policy and guarded branch deletion. Record this as an open question rather than weaken those checks.
