## Context

The cross-repository `ios-nightly-build.yml` upload job cannot read environment secrets from the
calling repository. Evo run 33670770997 passed change detection, exact-main preflight, and its full
iOS suite, then every Apple credential resolved empty even though all six remain present in Evo's
`testflight-internal` environment. GitHub explicitly does not pass caller environment secrets
through `workflow_call`, so the current contract promises a boundary the platform cannot provide.

Upstream issue: https://github.com/cpheinrich/morpheus/issues/192

## Approach

Expose the shared workflow's build decision and verified main SHA, and add an input that lets a
cross-repository caller disable the called workflow's upload job. The caller can then keep the
generic change/preflight/test gate in Morpheus while performing signing locally in its own protected
environment. Preserve the existing upload path by default for compatible same-repository callers,
document the platform boundary, and cover the outputs and opt-out in parsed-workflow tests.
