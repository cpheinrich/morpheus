## Context

`plugins/codex-claude` launched Claude only with a model named in `subscriptionModels`,
which defaulted to `opus`, `sonnet` and `haiku`. The list existed to stop a moving `best`
alias selecting a paid-credit-only model, but it also refused every model the Claude CLI
gained after the plugin shipped: delegating to Claude Fable 5.1 (`claude-fable-5-1`) on
2026-10-08 failed with "No approved subscription model mapping" until the host's bridge
configuration was hand-edited. Issue
[#368](https://github.com/cpheinrich/morpheus/issues/368).

## Approach

- Remove the fixed allowlist. Any explicit, syntactically safe model id or family alias
  (`^[a-zA-Z0-9][a-zA-Z0-9_.-]*$`, so never flag-shaped) from an override or `modelMap`
  is passed to `claude --model`; the CLI is the availability authority and refuses an
  unknown id at the first request with its own `unrecognized_model` error at no cost,
  which the bridge already surfaces as a failed run.
- Keep refusing moving aliases (`best`, `latest`, `default`, `newest`, `auto`), which is
  the only part of the allowlist worth keeping.
- Subscription-auth verification, provider-env stripping, the paid-overage stop and
  explicit override/fallback authorization are unchanged.
- A saved `subscriptionModels` key still parses (deprecated, ignored) so an installed
  configuration survives the upgrade; `doctor` reports it.
- Tests, README and the delegate skill updated.
