## Context

Chris approved early visual planning across Morpheus projects. Relationship-heavy work benefits
from a sketch while design choices can still change; installing a skill alone does not teach
existing project sessions when to use it. This bounded phase changes Morpheus only.

## Approach

Add a small canonical visual-design skill, Claude mirror and installed CLI guide using the
existing distribution registry and provider pointers. Carry the early trigger into Morpheus and
new scaffold instructions and expose an advisory doctor warning for older instructions. Keep
review's usefulness/accuracy question advisory and document existing-project adoption.

## Acceptance

- Both providers and all project kinds discover the skill through scaffold and missing-entrypoint
  sync; existing authored entrypoints remain untouched and CLI bytes match the canonical guide.
- Instructions create/show useful diagrams before implementation for architecture/pipeline/state/
  ownership/async or substantial alternative work, and skip trivial self-contained edits.
- Guidance distinguishes current/proposed and assumptions, uses fenced Mermaid for durable docs,
  and updates retained diagrams after material design changes, without approval pauses or new gates.
- Distribution checks and representative cases are reported separately from actual agent behavior
  measurement; a fresh independent reviewer, CI and merge remain required.
- Inventory registered consumers read-only and report project-specific adoption needs privately.
