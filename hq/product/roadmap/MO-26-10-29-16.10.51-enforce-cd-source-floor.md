## Context

CD V2 enforced the physical-device test policy only when test evidence and the upload claim
arrived, after a build number (and, for production, the 24-hour soak) was spent. Repair adoption
only required that a source not move backwards from the intent's current source, so a repair could
re-adopt the source that had just failed. On 2026-10-29 Evo's repair agent returned an older merged
PR whose source predated the `EvoStagingDeviceGate` scheme; the attempt's device job failed at
once, and the ledger's generic failure did not tell the next agent why (#562).

## Approach

- `tests.physicalDevice.sourceFloor`: optional full SHA of the first main commit carrying the test
  plan. Absent keeps every existing configuration's bytes and digest.
- `assertSourceAdmissible` refuses a source older than the floor, and refuses an unknown floor.
  `planAttempt` calls it, so the controller routes the intent to repair with that message before
  reserving a build number.
- `assertRepairAdmissible` adds strict descent past every attempted source; `adoptRepair` calls it
  before mutating, and the worker calls it after `verifyRepair` so a refusal becomes a checkpoint.
- The repair prompt gets a separate admissibility line (`lastMain`, attempted sources, policy
  profile/test IDs/floor), outside the capability-context digest.

Consumer adoption (setting the floor in Evo's config, migrating the ledger and bumping the worker
pin) is a separate follow-up owned in the Evo repository.
