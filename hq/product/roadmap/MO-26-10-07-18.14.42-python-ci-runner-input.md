## Context

`python-ci.yml` hardcodes `runs-on: ubuntu-latest`. Lakina wants its backend CI on a
self-hosted Linux VM runner (label `linux-vm`) with GitHub-hosted `ubuntu-latest` as the
fallback, and the caller, not the shared workflow, owns that choice (see the decision on
isolated repo-scoped self-hosted runners). `ios-ci.yml` already takes a `runner` input.

## Approach

Add a `runner` string input (default `ubuntu-latest`, a single label, not JSON) to
`python-ci.yml` and use `runs-on: ${{ inputs.runner }}`. Do the same in `node-ci.yml` and
`web-ci.yml` where the change is identical. Pin the default and the wiring in
`tests/workflows.test.ts`.
