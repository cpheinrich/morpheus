## Context

The `ANTHROPIC_API_KEY` secret landed on 2026-08-02 and rung 2 ran for the first time, on
[#68](https://github.com/cpheinrich/morpheus/pull/68). It reported **pass** in 3m48s, up from ~20s
while it was skipping, so it plainly executed. It posted nothing.

The job log says why:

```
"num_turns": 20,
"total_cost_usd": 0.86167775,
"permission_denials_count": 9
```

It did the review. It was then denied, nine times, every means of delivering it — and exited green.

**This is precisely the failure the rung was built not to have.** MO-051's whole argument was that an
unconfigured verifier must not report success, because a green check is read as evidence. The skip
path handles that correctly. Nobody considered the case where it *runs* and cannot speak, which is
indistinguishable from finding nothing and looks healthier, since the annotation is absent too.

### Why

Supplying `prompt` puts `claude-code-action` into **automation mode**. Its own documentation:

> In v1, automation mode intentionally does not create tracking comments by default to reduce noise
> in automated workflows. If you need progress tracking, use the `track_progress: true` input.

Automation mode grants the base GitHub tools but not the ones that *write* to a pull request. The
action's canonical review example passes both `track_progress: true` and an explicit
`--allowedTools` list; the workflow passed neither, because it was written against the interface
without a key to exercise it.

## Approach

Two lines, both taken from the action's own `examples/pr-review-comprehensive.yml` rather than
guessed:

- `track_progress: true` — forces tag mode, creating the tracking comment and preserving PR context.
- `--allowedTools` for `mcp__github_inline_comment__create_inline_comment` and `Bash(gh pr comment:*)`.
  Inline findings and the top-level comment are separate paths; granting one would silently halve
  what a review can say.

`--max-turns 40` is added as a runaway backstop rather than a budget. 20 turns was the observed cost
of a PR containing **no code at all**, so a cap near that would truncate a real review moments before
it posts — trading this bug for a subtler one.

## What this does not fix

**Cost is now a real number and nobody has decided on it.** $0.86 for a records-only pull request,
on `claude-opus-5[1m]` because that is the action's default and no model was pinned. A code PR will
cost more. Left deliberately for a separate decision — pinning a cheaper model is one line, but it is
a quality-for-money trade that is Chris's to make, and making it silently inside a bug fix would bury
it.

## Test plan

- Three guards in `tests/workflows.test.ts`: `track_progress` is true, both delivery tools are
  granted, and the turn cap stays above observed usage.
- Verified by removing `track_progress` and confirming the guard fails.
- **The real test is the `agent-review` job on this pull request**, which either posts a review or
  does not. A pass alone is not evidence — that is the whole bug.

## Open questions

None blocking. The model/cost decision is raised in the inbox rather than settled here.
