## Context

Chris authorized a branch-first group-CD pipeline for Evo: a release branch R
(`release/ios-<A12>`) is cut from `main` when staging starts, fixes merge only into R,
and R merges back into `main` after CD completes. The supported PM path only prepares
`main`: `pm claim` prepares a worktree at fetched `main`, and `assertCurrentSource`,
`context refresh` and the gate all require the checkout to contain current `main`. Once
unrelated work lands on `main`, a release fix author is refused and told to integrate
`main`, which is exactly what a frozen release must not receive. Release fix authors must
not be told to bypass the guard, hand-create branches, merge `main` into R or go offline.

## Approach

Add an explicit task base: `morpheus pm claim <ID> --base <branch>`. Without the option
nothing changes. With it, the claim verifies the branch is protected on GitHub and
exists on the trunk remote, prepares the task worktree at that branch's fetched head,
and writes `base:` into the claimed item's frontmatter. Session code that measures
"current source" (claim, context refresh/check, context brief lag, cleanup) resolves the
task's base from that item instead of the project trunk, so a release task is measured
against R and never asked to contain `main`. `review prepare`/`validate` default
`--base` to the task base. CI already validates against `origin/<PR base>`.
