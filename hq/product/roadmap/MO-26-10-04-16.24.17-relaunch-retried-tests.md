## Context

The shared iOS lane retries a failed test with `-retry-tests-on-failure -test-iterations N`,
which re-runs the failed cases inside the same test-host process. Evo's release lane lost two
of its last seven runs to a StoreKit purchase that the simulator's ledger daemon stopped
answering for that process: once the first purchase failed, every retry failed within
milliseconds, so three executions were one data point and the release was blocked for a day
each time. A flake that lives in the process, or in a daemon's view of that process, cannot be
retried without a new process.

## Approach

Pass `-test-repetition-relaunch-enabled YES` alongside the existing retry flags, so each retry
relaunches the test host. The gate is unchanged: a test that fails every attempt still fails
the run. The cost is one app launch per retried attempt.
