## Context

The shared native workflow places `failure()` in a step environment expression.
GitHub rejects that context before allocating a job, so the normal iOS workflow
cannot run. Existing string assertions accepted the same invalid expression.

## Requirements

- GitHub Actions expression validation accepts every shipped workflow.
- Snapshot native failure before any artifact stage using a supported status
  conditional. Only a failed native job selects failure diagnostics; success,
  allowed continue-on-error, skipped work, cancellation and scope bypass do not.
- A later artifact failure cannot create a native failure selection. The complete
  all-selected artifact admission barrier and upload guards remain enforced.
- Real actionlint validation rejects the original defect and unsupported sibling
  contexts; focused behavior checks exercise the status/output boundaries.
- Source qualification, protected merge, consumer adoption and real delivery are
  separate evidence. This task owns only the shared source correction.

## Approach

Use `failure()` only in the capture step's `if` and write a literal true output
when selected. Existing exact-true consumers treat a skipped capture's absent
output as false. Enable checksummed, pinned actionlint in Morpheus's existing
required Node check through a default-off reusable input; retain its expression
and workflow checks while leaving optional shell/Python linters disabled.

## Operating mandate

The delegated incident scope authorizes local source preparation and the normal
claim, with initial implementation publication and independent review held for
the coordinating owner's qualified-packet release. Preserve unrelated tasks and
private evidence. No host, runner, service, credentials, controller ledger,
provider mutation, native dispatch or consumer adoption is authorized here.
The owner retains the finite source-CI budget and event ledger outside this
public repository. No CI spend or reviewer invocation occurs during preparation.
