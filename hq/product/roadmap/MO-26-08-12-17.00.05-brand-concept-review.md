## Context

Kairos established that a written questionnaire and a final token file are not
enough to preserve a brand decision. The useful work happened in one HTML
comparison page: five comparable directions, live mock surfaces, type studies,
and a serious Compare All view. When the selected direction became canonical,
much of its imagery, materiality, and composition disappeared; the first site
then used only a small portion of what had actually been approved.

Morpheus needs to make that visual review the default input-to-decision path,
then make a site-facing imagery handoff part of the package rather than an
optional afterthought.

## Approach

Replace the new-project `answers.md` questionnaire with a free-form
`vibes.txt` brief and a moodboard folder. Generate an agent handoff that asks
for one durable `research/brand.html` with five genuinely distinct named
packages and common Brand System, Home, Marketing, Typography, and Compare All
views.

Retain the exploration after selection, then add final `moodboards.md`,
`imagery.json`, and `application.md` records. The final checker will require
both a valid review surface and an image-to-surface mapping, so an approved
diagram or illustration is actually used by the initial website or product.

## Acceptance

- `morpheus init` automatically creates `vibes.txt`, the durable exploration
  handoff, and a local Git-ignored `moodboard/` input folder for company and
  personal projects, without creating `answers.md`; `morpheus brand init`
  remains a safe retrofit for older or partial projects.
- The handoff requires five distinct concepts with comparable Brand System,
  Home, Marketing, Typography, and substantial Compare All views, and the
  review page exposes a portable contract that can be checked.
- `morpheus brand finalize --selection` refuses an incomplete review and
  writes a canonical-package handoff that preserves imagery and moodboard
  provenance.
- Brand status is not complete without valid strategy, voice, messaging,
  tokens, visual system, selected moodboards, imagery manifest, application
  mapping, logo, and decision record.
- Onboarding, CLI help, architecture, and agent guidance describe the new
  path; legacy projects can copy existing answers into `vibes.txt` without
  deleting their source file.
- Focused tests prove the workflow and its imagery application guard.
