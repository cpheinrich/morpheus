## Context

Issue #248 found that an honestly recorded incomplete independent review can leave a PR blocked
even when Chris explicitly accepts the remaining review risk. The existing `review-waived:`
marker covers only legacy delivery, and changing the review record to `complete` would falsify it.

## Approach

Add a distinct `review-override` GitHub label and require an authenticated PR comment from a
configured human approver naming the exact PR head and a specific reason. Read approver authority
from protected trunk, preserve the incomplete record and all provenance, finding and coverage
checks, and report the exception visibly. Document the steps in the runbook and scaffolded
instructions, and exercise authorization, stale-head and record-boundary cases in focused tests.

## Acceptance

- An incomplete review with a measured budget overrun can pass conventions only with a current
  head-specific comment from a configured human and the override label.
- The author cannot grant themselves approver status in the same PR; stale, missing or vague
  comments do not authorize a merge.
- Blocked reviews, unresolved substantive findings and uncovered code remain blocked.
- The contract and automated check distinguish override from completed independent review.
