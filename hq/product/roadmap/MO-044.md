## Context

`hq/onboarding.md` is committed with the heading `# T — setup`. It read `# Morpheus — setup` when
first generated in PR #21 and was changed by PR #23, which was about detectors and had no reason
to touch it.

The heading came from `name ?? basename(root)` in `src/cli/onboarding.ts` — a `--name` flag
falling back to the directory name, never consulting `morpheus.json`, which declares both
`name: morpheus` and `displayName: Morpheus`. So a stray flag wrote a wrong heading into a
committed file, and nothing regenerated it for two more commits.

`basename(root)` is wrong even without the stray flag. The directory is incidental: a worktree for
this item sits in `morpheus-mo-044`, and AGENTS.md asks for one worktree per parallel session, so
regenerating from one would rewrite the heading again. `.agent/decisions.md` already settles the
principle — *the registry indexes; the manifest is authoritative*.

Found while staging MO-040, as an unexplained modification from having run `init status`.

## Approach

`projectLabel(root)` beside the existing `projectKind(root)`, reading `displayName`, then `name`,
then the basename. An explicit `--name` still wins, since that is a deliberate override rather
than a guess.
