## Context

Issues #564 and #577 show a complete green check rollup rejected because the run census still includes a cancelled duplicate. The Evo #734 census confirms an empty cancelled run preceding a successful replacement in the same second.

## Approach

Use stable workflow ID and creation time, with run ID as the tie-breaker, to identify a later same-head replacement. Ignore only a superseded cancellation; wait for a pending replacement, preserve genuine failures and unmatched cancellations, and confirm the check rollup after the complete census.

## Acceptance

- Both published failure shapes return green once the matching replacement succeeds.
- Pending successors wait; sole/newest cancellations, other workflows, failures and malformed or truncated evidence cannot return green.
- A cancelled job still present in the final rollup remains a failure.
