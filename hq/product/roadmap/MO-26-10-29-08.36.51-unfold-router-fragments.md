## Context

Found by the independent review of MO-26-10-29-08.24.29 (finding FSL-001, incidental and
pre-existing). `SectionLinks` unfolds closed `<details>` only when it creates the target id
itself. A fragment that names an id that already exists is treated as handled, on the assumption
that the browser has scrolled to it. That holds for document loads, because the browser unfolds
`<details>` itself. It does not hold for client-side navigation. A Next.js `<Link href="/hq/page#id">`
makes the App Router call `scrollIntoView()`, which does not unfold `<details>`. So a section
inside "Show more" stays folded when a reader follows an in-app link to it.

## Approach

In the existing-id branch of the per-navigation pass, if the target is inside a closed
`<details>`, call `revealAncestors` and scroll to it. A target that is already visible keeps
being left to the browser and the router.

## Acceptance

- Following a client-side link to an authored or previously generated id inside closed `<details>`
  unfolds it and scrolls to the section.
- A target that is already visible is not scrolled a second time.
