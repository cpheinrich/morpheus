## Context

Implement the reusable controller described by `docs/cd-pipeline-v2.md`, with
Evo as its first consumer. The controller owns durable delivery obligations,
recovery, immutable source/build identity and exact internal delivery receipts.
The design item MO-26-10-18-06.52.29 must merge before implementation begins.

## Approach

Use a versioned GitHub state branch, pure domain transitions, existing `gh` and
`jose` primitives, and replaceable native/agent executors. Add the `morpheus cd`
CLI for reconciliation, evidence, upload claims and durable repair workers.
Keep consumer identities, paths and hooks in the consumer configuration.

Focused tests must challenge CAS contention/lost acknowledgment, original debt,
production source age, uncertain upload ownership, receipt substitution and
global budget reservations. Real delivery acceptance belongs to the consumer
campaign and is not implied by passing model or adapter tests.
