## Context

The rollout exposed lost submit acknowledgements, unclear queue waits, and review packets that exceeded tool output limits. Chris authorized fixing those failures and adding Claude workers to both enrolled Macs for all enrolled project routes. Continue the existing staged rollout with both subscription pools. Use existing subscriptions at Standard speed and $0 additional spend.

## Approach

Reuse the task queue, per-slot and per-workspace leases, gateway quota reader, process guardian, and receipts. Select a provider and model at admission. Preserve the project and host boundaries already enforced by Fleet, the existing Codex default, and the ordinary review and delivery gates.

## Acceptance

- An uncertain submission resolves to the original task using its stable message ID.
- Existing Fleet status explains a queued task's earliest actionable wait reason.
- The review packet carries exact-commit evidence in bounded, independently verifiable sections.
- Existing Codex tasks and configuration keep their routing. Claude uses the same admission, artifact, result and cleanup contract with its enrolled gateway. Unknown quota holds the run.
- Protected CI and independent review approve the change. Both worker hosts return a live Claude launch, result and cleanup receipt and remain eligible for Codex. Record the resulting global provider enrollment and continue the existing rollout schedule.
