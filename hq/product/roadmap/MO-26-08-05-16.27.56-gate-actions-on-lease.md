## Context

[MO-26-08-05-12.24.47](MO-26-08-05-12.24.47-enforce-context-freshness.md)
landed the freshness *policy* — receipts, five-minute leases, a fail-closed
`requireFresh`. Nothing calls it. Until something does, a session can still
start without loading project state and run for hours past a change another
agent pushed; the policy just means the answer is now computable.

This item is the wiring, split out so the policy could merge without the board
recording enforcement that does not exist.

## Approach

- `morpheus context refresh | check | status | brief`. Session start does not
  take a receipt — see acceptance 3.
- Gates on PM, deployment, data, and broker actions, inside the CLI rather
  than in per-project config, so the check reaches every project on a
  dependency bump. A remote-drift watcher on the lease term is still open.
- An **offline exception**: an explicit mode that may work locally but cannot
  push or operate external controls. `MORPHEUS_OFFLINE=1` or `--offline`, and
  it must be *declared* — inferring it from an unreachable remote would make
  every network blip an unlocked gate.
- PM/PR status that distinguishes claimed, context-current, and
  substantive-started, with CI validating the PR's receipt against the pushed
  SHA.
- Codex app-server and Claude lifecycle/tool hook adapters, with contract
  tests, sharing one lease format and writing no raw session data. Codex
  steering needs a channel of its own: `SessionAdapter` has `requestRefresh`
  and `requestRepair`, and `interrupt?` was removed rather than carried
  unreachable, so *stop what you are doing* has no home yet.
- A **receipt store** — `writeReceipt`/`readReceipt`, and whatever produces `id`, `createdAt`,
  `branch` and `worktree`. The policy consumes receipts; nothing builds one yet. `branch` and
  `worktree` are the last two fields written and read by nothing: either the guard uses them —
  a receipt taken in another worktree is not this session's — or they come out. Whatever populates
  `advisoryMemorySources` writes `source:key` labels; the schema now refuses anything else, on
  write as well as read.
- Initializer, registry, and managed-project rollout with adoption reporting.

## Acceptance

1. ~~A stale, expired, or unknown lease blocks commit, push,~~ **and governed
   Morpheus actions.** Commit and push are **not** blocked, by decision: a
   human typing `git commit` has no session and cannot have one, so a
   pre-commit hook is either agent-only detection that does not exist or a
   thing people learn to `--no-verify` past. The CLI gate covers the four
   actions where stale context does identifiable harm, and reaches every
   project with no per-project wiring.
2. Offline is an explicit, named exception that permits local work and refuses
   anything that leaves the machine.
3. ~~Session start/resume refreshes~~ **before PM work begins, and drift
   inside a session names the smallest relevant canonical delta.** Session
   start deliberately does *not* refresh: a hook taking a receipt would
   certify the records were read by the act of not reading them. It runs
   `context brief`, which names what is missing and takes nothing, and the
   gate refuses PM work until the agent refreshes for itself.
4. ~~Codex and Claude adapters have contract tests~~ — **not started, and
   neither provider is hooked through `SessionAdapter`.** The scaffolded
   Claude hook runs `morpheus context brief`, a CLI command; Codex reads
   `AGENTS.md`. Both are covered by the CLI gate, which is the argument for
   having put it there — but `notifyAdapter` still has no production caller,
   and steering and interruption have no channel. Recorded rather than left
   reading as half-done.
5. ~~CI validates the PR's receipt against the pushed SHA~~ — **unbuildable as
   written.** A receipt is local and gitignored, and is one machine's
   observation by construction, so no workflow can see one. Replaced by the
   question CI *can* answer: `check pr` warns when canonical records moved on
   the base branch while the PR was open. Generated projects receive the
   scaffolded hook, the manifest block, and `doctor` adoption reporting.
6. A project policy file that is missing, blank, or unparseable falls back to
   the default required set. It must never resolve to `[]`, which is the one
   value that switches coverage off — the check would then pass for a session
   that read nothing, silently, in every generated project at once.
7. ~~One lease is read the same way by everything that reads it~~ — **done for
   the readers that exist.** `check` resolves the project policy once and hands
   it to both `leaseAt` and `observeLease`. `requireFresh` and `notifyAdapter`
   still take their own, which stays a trap for whatever adds a per-project
   term.
8. The CLI, the hooks and CI act on `unresolvableInputs` the way
   `notifyAdapter` and `ContextFreshnessError` already do — a record that
   re-reading cannot fix is reported as *repair this*, never as a refresh to
   retry. That is the half of this the policy could not do for itself.
9. ~~A caller that gets `written: false` does not proceed~~ — **done for
   `context refresh`**, which exits non-zero rather than printing a ✓ for a
   receipt that never reached disk. Nothing else consumes the flag yet.
   Originally: This is the one fail-open path in the module:
   the previous lease survives, and a `fresh` one inside its term still passes
   `requireFresh`, so a stale lease does not look stale. Blocking on it is
   acceptance 1's job and nothing enforces it yet.
10. `hq/team/<handle>.md` is verified, which needs the handle the policy has no
   way to know. Outside the declared required set the receipt is best-effort by
   design, so the answer is that a project declares its inbox required once a
   handle is available — not that the default set grows a per-person path.
