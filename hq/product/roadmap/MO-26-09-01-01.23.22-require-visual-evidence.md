## Context

Front-end changes need reviewable screen captures, but CI cannot infer semantic pixel changes with
perfect accuracy. The blocking condition therefore has to be an explicit repository-owned path
contract rather than a heuristic UI classifier.

## Approach

Add a default-on `review.visualEvidence` manifest policy for React and Swift/SwiftUI paths. Block
matching changes unless the PR carries a GitHub-attached recording or screenshots; keep recording
as a preference and unclassified legacy paths as warnings. Permit a repo-level opt-out only with a
substantive reason, and stage existing repositories one at a time so Evo can prove the rollout.
