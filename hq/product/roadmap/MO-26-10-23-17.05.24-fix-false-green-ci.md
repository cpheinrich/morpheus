## Context

`morpheus wait-ci` has reported green after only the first four check rows finished,
while current-head Actions workflows were pending or running. This happened on a stable
head as well as after a head change. A CI receipt must describe completed checks, even
when the repository separately permits auto-merge under its protected-branch rules.

Acceptance:
- [x] A current-head workflow that is pending, queued, or running prevents a green receipt
      even when every check row currently registered in the rollup has passed.
- [x] The wait follows head changes and checks the replacement head's workflow runs.
- [x] An Actions read failure or incomplete run census cannot produce green.
- [x] Existing auto-merge, branch protection, and review policy remain unchanged.

## Approach

In the default all-checks mode, at the point where the rollup appears green, read the head commit's Actions run
census and wait for every current-head run to finish. Keep the rollup as the
source of job outcomes and the digest; rerun the rollup after the census before
returning green. Cover the stable-head and moved-head reproductions with
scripted API fixtures, including the early four-check snapshot.
