## Context

Found from Darwin, which moved its goals to `hq/strategy/goals/` on 2026-08-02 — a company has
goals that are not product goals, and Chris wanted `/hq`'s sections to mirror the folders under
`hq/`. That left `hq/product/goals/` absent.

`parseDir` already treats a missing directory as zero items, so `pm validate` was perfectly happy:
`✓ Goals — 0 item(s)`. `pm index` then walked the same kinds and called `writeIndex` on every one
of them, and `writeFile` cannot create a parent directory:

```
ENOENT: no such file or directory, open '…/hq/product/goals/README.md'
```

Exit code `1`, from `pm index` **and** `pm index --check` — which is the step `pm-check.yml` runs,
so it took Darwin's CI down with it.

Two halves disagreed about whether a kind must exist. Reading tolerated absence; writing assumed
presence.

## Approach

Skip a kind whose directory is not there, and say so.

Deliberately **skip rather than `mkdir -p`**. Creating the directory would make the command pass by
materialising something nobody asked for — an empty `goals/` reappearing after every index run,
which is a second bug wearing the first one's clothes. A project that does not use a kind should
not acquire it by running an index.

Two tests, both of which fail with a bare ENOENT before the change: `index` resolves to `0` over a
product directory holding only `roadmap/`, without creating `goals/`; and `--check` still reports
stale correctly rather than crashing before it can.

## Not in scope

Darwin's goals are now unvalidated by `pm validate`, because they live outside the product
directory. That is the larger question this exposed — **whether goals belong under `hq/product/`
at all**, given every `kind: company` project has company-level goals — and it wants its own item
rather than being smuggled in behind a crash fix. Darwin has covered the gap locally with a test
asserting goal frontmatter against the same shape.
