## Context

The `inbox` onboarding task filters the directory with `f.toLowerCase() !== "readme.md"` and then
requires every remaining file to parse as an inbox. `hq/team/` now holds `members.md` too, which is
not an inbox and does not parse as one — so the moment a project writes a roster, a setup step that
was complete flips back to **not done** in `hq/onboarding.md`.

Caught while migrating heinrichbros.com: the inbox moved, the roster landed, and `init status`
unticked the box for a file that was correct all along.

This is the third module to decide for itself what counts as an inbox, and `TEAM_RESERVED` exists
precisely so there is only one answer — `hq/team/` is a folder where non-inbox files are expected,
so an ad-hoc filter here is not a smaller version of the same rule, it is a different one. Four
bugs in a fortnight have now had the same shape: a value written twice, and the second copy not
updated.

## Approach

Import `TEAM_RESERVED` in `src/onboarding/tasks.ts` and filter with it, the way
`src/cli/inbox.ts` already does. Add a test that seeds a roster beside an inbox and asserts the
task detects as done — written against the *class* (a reserved file), not the instance, so adding
a fourth reserved name cannot silently reintroduce this.
