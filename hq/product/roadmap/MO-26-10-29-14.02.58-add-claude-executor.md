## Context

CD V2's local repair executor is hard-wired to Codex: the quota reader speaks `codex app-server`,
the login check expects a ChatGPT sign-in and the invocation is `codex exec`. Claude exists only as
the hosted executor, whose quota readback needs an OAuth token with `user:profile` that consumers do
not hold. Evo's repair intents are stuck while its only native worker cannot read quota, and Chris
asked for repair work to run on his own Claude Max subscription on the MacBook Pro.

## Approach

Design first: `docs/cd-v2-claude-executor.md`. An explicitly selected, optional `agents.claude`
executor that a consumer opts into per host; Codex stays the default and byte-identical. It binds an
exact native claude.ai account and subscription, reads plan usage through the CLI's own
`get_usage` control request (no token export, no new scope), fails closed on unknown, stale or
paid-overage telemetry, and records outcomes only through the existing worker CAS paths so
`verifyRepair` still decides adoption. Consumer adoption (config migration, host profile) is separate.
