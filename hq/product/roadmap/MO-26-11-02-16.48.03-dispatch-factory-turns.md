## Context

Factory's hooks only advise: a coordinator in `automatic` mode is told the route and may ignore
it. Chris authorized automatic dispatch with the coordinating Codex or Claude session staying the
manager, and asked that an activated session's first reply say briefly that Factory is
delegating. A gateway is a credential that many delegated sessions share; host capacity
(`maxConcurrent`, one writer per checkout) and subscription quota are separate limits.

## Approach

- UserPromptSubmit, in `automatic` mode only, launches the routed worker through the existing
  `start`/`codexStart` with a bounded handoff: the user's prompt, the previous bridge result
  summary, and the worker's saved session for the same checkout and route. No transcript.
- Turns are deduplicated (Codex `turn_id`; Claude prompt plus transcript metadata, refused when
  unreadable). An active or `needs_input` run is returned to the manager, never answered.
- Launch errors are explicit, with next steps; only the existing quota route stays local.
  `off` stays inert, `manual` advisory, overrides and a `local:` per-turn prefix opt out.
- A once-only first-reply instruction plus a deterministic `systemMessage`; SessionStart reports
  readiness only. A native edit guard stops the manager racing its own worker (not a security
  boundary). Existing lease, grace and concurrency limits are unchanged.
- Focused tests drive the real hook scripts through the bridge and guardian with fake CLIs in
  both directions.
