## Context

Measured on Evo's last thirty `ios-ci.yml` runs: roughly five hundred billed macOS minutes, while
every Linux workflow in the repository together costs a couple of dollars a month. One successful
run took 28m13s against the reusable job's thirty-minute ceiling, and several runs already report
as cancelled at exactly thirty-one minutes — the ceiling firing. The iOS workflow is where both
the money and the reliability problem live.

Three costs inside that run are the reusable workflow's to fix rather than a caller's. Xcode
writes an index store on every build that no CI runner ever reads. The SwiftPM cache has an exact
key and no prefix restore, so bumping a single dependency in `Package.resolved` re-clones every
package from scratch. And the test job's concurrency group is keyed on repository, ref and scheme
alone, so a release workflow calling this job on `refs/heads/main` shares a group with a
push-to-main CI run.

Separately, none of `web-ci.yml`, `pm-check.yml`, `pr-check.yml` or the `emulators` job in
`firebase-tests.yml` sets `timeout-minutes`. A hung step in any of them runs to GitHub's six-hour
default on billed minutes. This repository's own comments record a Playwright install that hung
for forty minutes, so the failure mode is observed rather than theoretical.

## Approach

In `ios-ci.yml`: pass `COMPILER_INDEX_STORE_ENABLE=NO` to the two build actions, add prefix
`restore-keys` to the SwiftPM cache, and include `github.workflow` in the test job's concurrency
group so a caller's CI run and a caller's release run cannot cancel one another. The index-store
override stays off `test-without-building`, which compiles nothing and re-quotes its arguments
into the emulator exec string.

In the four Linux workflows: add a `timeout-minutes` ceiling well above each job's honest runtime,
and give the three that lacked one a job-level concurrency group so a superseded push cancels
rather than running beside its replacement. Job-level rather than workflow-level, matching the
reasoning already recorded in `firebase-tests.yml`.
