## Context

Profiling round 2 ([worklog](../../../.agent/worklog/2026-10-28-profiling-round-2.md)) proposed a scheduled "PR shepherd" for CI, TestFlight and
nightly failures. Checked against what already exists, most of that is owned:

| Failure | Owner today |
|---|---|
| Failing checks, stalled review or conflicts on an open PR | GitHub Manager (`docs/runbooks/gh-manager.md`), opted-in repositories |
| Quiet draft and WIP PRs | Manager triage (MO-26-10-20-17.24.49) |
| Evo staging and production TestFlight delivery, including test failures, repair and Apple processing | CD V2 controller (`docs/cd-pipeline-v2.md`) |
| An incident handed to an agent | DevOps persona (`devops-engineer` skill) — judgment only; it installs no watcher |

What nobody watches is the remainder filed here: a **failed run on `main`** (push CI after merge,
which no PR carries any more) and a **failed scheduled workflow outside CD V2** — Morpheus's own
`heartbeat.yml` and `schedule.yml`, and nightly or TestFlight lanes in consumers not migrated to CD
V2 (which ones is the first thing to establish). Those stay red in the Actions tab until someone
happens to look. The roughly 19 unadopted trunk-rescue PRs of the same period show that "an
artifact exists" is not attention; MO-26-10-28-14.08.53 handles that class.

## Approach

- **Deterministic first.** A scheduled reconciler lists, per opted-in repository, the latest
  conclusion of every workflow on the default branch and every scheduled workflow, and keeps a
  small known-red state (first seen, last seen, run URL). New red: one notice. Still red after N
  days: escalate. Green again: close. Lanes owned by CD V2 or the GitHub Manager are excluded by
  configuration, so this never becomes a second dispatcher (the devops-engineer rule).
- Notices go to one issue per failing workflow in the affected repository and into the needs-human
  digest (MO-26-10-28-14.10.59), not a new channel. Reuse `wait-ci`'s failed-log digest.
- Home: beside the GitHub Manager in the private operations repository and its App, to avoid a new
  credential.
- **Optional second stage**, only after two weeks of the deterministic version: wake one bounded
  devops-engineer session to diagnose a new red, under the manager's existing budget rules.

## Needs from Chris

Nothing for the deterministic stage. The model-backed second stage spends subscription quota on a
schedule and needs his yes before it is enabled.

## Acceptance

- A deliberately failed scheduled workflow in a test repository produces exactly one notice within
  one cycle, and the notice closes when the workflow is green again.
- Excluded CD V2 and manager lanes produce no notice.
