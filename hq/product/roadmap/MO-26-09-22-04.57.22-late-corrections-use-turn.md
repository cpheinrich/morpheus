## Context

After an independent review cleared a PR, a late full-CI run could still show that a fix was
needed (Evo #244: two legacy UI tests assumed the old action-bar layout). Any code commit after
`covered` invalidated the review, and a follow-up after a `cleared` turn was refused, so the
correction had no path except a human. #247 asked whether the "explicit scope decision" the
runbook names could be the author's, and how to serialize it. Chris decided on 2026-09-22 that a
late correction after clearance may spend one of the remaining review turns.

## Approach

A non-final follow-up may be `cleared` when the next turn carries a `scopeReason`, the same field
a trunk-integration turn already uses for its scope decision; the first follow-up after an
initial review with no substantive findings is the same shape. A non-final `blocked` turn still
needs no reason on its successor, and an `incomplete` turn never has one. The three-turn cap,
the follow-up ceiling, the same-reviewer rule and the final `cleared`-on-`covered` rule are
unchanged, so a clean review has two correction slots and one that used a fix follow-up has one;
once spent, the PR stays open for the human. The commits between the previous clearance and the
correction turn are covered by that turn's clearance. The runbook, the reviewer prompt, AGENTS.md
and its scaffold twin, and `architecture.md` say the same thing.

## Acceptance

- A clean initial review, a code commit after `covered`, then a `cleared` follow-up carrying a
  `scopeReason` passes `check pr`; the same follow-up without one fails.
- `[cleared, cleared]` passes when the second carries a `scopeReason` and fails with the existing
  "only after" message when it does not.
- `[incomplete, cleared]` still fails regardless of `scopeReason`.
- A third follow-up entry is refused by the schema.
- A code commit after `covered` with no follow-up still invalidates the review.
