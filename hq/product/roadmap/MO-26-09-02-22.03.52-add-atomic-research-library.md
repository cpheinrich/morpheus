## Context

The first shared release can synchronize books after a project owns a valid catalog manifest, but
new projects should not have to fabricate placeholder hashes before their first upload. The local
Babel output must remain read-only while publishing, and the catalog must never point at a partial
remote publish.

## Approach

Add a `research-library publish` command that accepts descriptive metadata, builds both artifacts
from a named canonical local directory, performs create-only uploads, verifies the remote metadata,
then atomically creates the catalog entry. Document and integration-test the full boundary.

## Acceptance checks

- Publishing creates both immutable remote artifacts and a valid v2 manifest.
- No catalog manifest is created when an upload fails.
- Existing local source and existing catalog entries are never replaced.
