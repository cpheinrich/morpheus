## Context

Chris authorized moving the reusable contents of the public `cpheinrich/morpheus-factory`
repository (TypeScript placement/admission/broker core, Python/shell host and fleet Xcode
controllers, worker setup, cleanup and sub2api install) into the optional Factory plugin, and
sanitizing what is imported. The source repository carries personal fleet metadata in
`worker/updates.json` (hostnames, home paths, runner labels, Apple team, device UDID), and its
docs, fixtures and executable defaults carry real paths, emails, accounts and Evo excerpts.
Firestore is the future authoritative fleet store; for now private configuration stays local.

## Approach

- **One self-contained host package** at `plugins/factory/src/host/` with its own
  `package.json`, lockfile and tsconfig: `core/` (the TypeScript core, unchanged in behaviour),
  `worker/`, `fleet/`, `scripts/`, `tests/`, `docs/`, `examples/`. Languages and behaviour are
  retained; only configuration location, defaults and fixtures change. No git history is
  imported; provenance is the source repository and commit only.
- **Private config boundary.** `worker/host_config.py` validates one owner-only JSON manifest
  (absolute path, regular file, owned by the caller, no group/other bits, schema version,
  references rather than secrets) and returns data; every reader (update controller, fleet
  controller, installer, runner) consumes it. Default location `$FACTORY_HOME/hosts.json`
  (`~/.local/share/factory`). A later Firestore reader produces the same dict and calls the
  same validator. `host_config.py import` copies an existing manifest with exclusive creation
  and mode 600, never overwriting.
- **No personal defaults.** `--github-user` is required where it was defaulted; manifests and
  fixtures are synthetic; docs become generic operator docs.
- **Opt-in only.** The plugin installer copies the host package but never builds it, installs
  software or loads services. Heavy setup (Xcode, runner, sub2api Docker, Colima/Tart, provider
  CLIs) runs only from the explicit host setup commands. Normal Morpheus install never names it.
- **Service migration with rollback.** The LaunchAgent installer verifies package paths, keeps
  the previous plist, refuses to replace a running job, and `--rollback` restores the previous
  service. Live services are not migrated by this change; the consumer migration is documented.
- **agent-host-setup unchanged.** Its reviewed build/verify/activate/prune scripts stay
  referenced by path from the private manifest; a contract test pins the argv.
- **CI.** The Factory CI job also installs the host package, typechecks, runs its vitest and
  Python suites and builds it. Root typecheck/lint/compile do not see it.
