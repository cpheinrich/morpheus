## Context

Factory binds a root session's primary worker conversation to one canonical checkout, and
`start`/`codexStart` refuse any target whose project identity differs from the task's. A
task that spans repositories therefore loses its worker context at the repo boundary, and
the root's starting repository silently limits which authorized repositories it can reach.
Chris approved (2026-11-04) one task/session = one persistent worker conversation owning a
set of per-repo worktrees.

## Approach

- Task metadata maps canonical repo identity → task-owned worktree, plus the one native
  session ref. Adding a repo extends the map; resume keeps the same conversation.
- Explicit multi-repo targets in the delegation API; no silent repo inference. The root's
  starting repo no longer restricts additional authorized repos.
- Reuse Git/`pm claim` worktree lifecycle per repo. An independent task in the same repos
  gets distinct worktrees and cannot borrow another task's checkout.
- Preserve per-target `off`, permission ceiling, sticky gateway binding, native memory
  ownership and one writer across every checkout; migrate existing single-cwd records.
- Fresh review keeps its own session and workspace. Document that full-access mode is not
  OS confinement against a malicious shell.
- Out of scope: a coordinator, repo-per-worker, Paperclip or fleet onboarding.
