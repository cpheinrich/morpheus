## Context

Requests received in Messages, Slack, email or voice can look like an alternate execution lane even
when they came from a trusted person. That caused an unreviewed dirty-checkout TestFlight upload,
while a separate console handoff mutated the wrong Google Cloud project because its target and
verification lived only in prose. In both cases delivery was mistaken for acceptance.

## Approach

Use one external-action contract for both failures: conversational requests enter the normal
roadmap and PR lifecycle; manual mutations use explicit one-shot commands plus caller-perspective
verification; and releases depend on a secret-free reusable preflight that proves the source is the
clean current `main` commit associated with a merged PR. Completion requires user-visible evidence,
not an archive, upload or deploy receipt. Keep recurring production probes project-local until a
second project needs the same probe.
