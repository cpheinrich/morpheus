## Context

The October 9 iOS pin change added a native screenshot and three accessibility
snapshots around placement. Normal scrolling or navigation between those reads
can reject a valid second pin with “Content moved during placement capture.”
This blocks Chris's main QA workflow. The related web overlay needs a browser
regression gate so iOS repairs do not break website commenting.

## Approach

Freeze the visible simulator frame synchronously on each right-click. Keep
accessibility data only for optional marker following; require the frame for
Send. Remove the unused native placement endpoint and update the operator
guide. Add real browser tests for iOS pin → navigate → pin → reload → send and
web pin → scroll → pin → send, in Chromium and WebKit CI.

## Acceptance

- Two iOS comments made on different screens each retain their clicked image
  and can be sent together without an accessibility placement error.
- An unavailable frame never creates an unsendable pin; accessibility failure
  does not block a pin with a captured frame.
- The web overlay still anchors and queues multiple comments after scrolling.
- Focused unit and browser tests, typecheck, lint, build, independent review,
  and required CI pass before merge.
