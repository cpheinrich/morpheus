## Context

An accepted upload can already be installable in TestFlight while a later Actions
artifact download fails. The controller currently downloads the complete test
artifacts again before each Apple observation, so a provider egress outage blocks
the ordinary receipt and creates unnecessary repair work after upload acceptance.

## Approach

Reuse only the immutable full-test proof previously downloaded and verified for the
current latest active attempt, after its exact bound workflow completes and its
durable upload is accepted. Retain the complete fresh effect/run sweep, duplicate
controls, pinned validator check, upload identity/fence, current configuration,
ordinary Apple observation and receipt guards. Missing proof uses the existing
artifact path; a conflicting or malformed reusable proof refuses before Apple.

The compact proof is not full test evidence: never pass it to `recordTests`, invent
results, reset a claim or reupload bytes. Use the existing workflow observation CAS
with zero newly downloaded artifacts, then the unchanged upload reconciliation.
No state/schema/store/worker/Apple/action interface or consumer rollout changes.

## Qualification

Focused controller and adapter tests cover exact accepted recovery, absent proof,
identity and malformed-proof boundaries, failed post-upload cleanup, expired upload
lease, current pause/attempt races, the real pinned Git validator and the original
artifact path. A private regression uses a copy of the retained affected ledger;
providers are synthetic and artifact access throws. Inspect targeted mutants.

Phase A ends with local committed implementation, records, focused results,
typecheck, compile and PM index. Source publication, CI, independent review and
operational adoption require their separate releases; no live effect is part of
this source task.
