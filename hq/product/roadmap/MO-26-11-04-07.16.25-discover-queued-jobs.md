## Context

The host CI VM dispatcher (agent-host-setup `ci-vm/`) found demand only through GitHub's
status-filtered run lists (`queued`, `pending`, `in_progress`). On 2026-11-04 those lists omitted
a run whose exact-label job was queued, while the unfiltered recent-runs list showed it. An idle,
healthy dispatcher therefore never booted a VM for it. Private incident evidence stays in an
ignored local handoff.

## Approach

Host-only change in cpheinrich/agent-host-setup#23; no Morpheus source changes. `queuedJobs` keeps
the three filtered queries and also reconciles one unfiltered page of the 30 most recent runs,
deduplicating run ids and inspecting only runs not `completed`. A failed unfiltered read keeps the
filtered demand; a failed filtered read still fails that repository's poll. Labels, ownership and
fairness are unchanged. Limit: an omitted run older than the 30 most recent runs is still missed.

Acceptance is the host PR's focused tests plus, after its reviewed merge and install, a queued
exact-label job that a status filter omits being served by a new owned VM. Installation and that
production observation belong to the root operator.
