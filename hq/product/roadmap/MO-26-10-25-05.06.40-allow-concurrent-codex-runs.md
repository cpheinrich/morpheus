## Context

A Claude session could previously remember only one bridge `runId`, so a live Codex delegation
blocked every other delegation from that session even when each writer had its own worktree.
This prevented independent work from using the bridge concurrently and made a global session
pointer ambiguous once more than one run existed.

## Approach

Keep the global concurrency limit and make working-directory ownership the collision boundary.
Persist run history on the Claude task, list active and recent terminal runs during inspection,
and resolve wait/status/view/stop by explicit run id whenever multiple runs are active. Resume
native Codex sessions and supervision budgets per working directory, retain the single-run
shortcut, lower only the new-config automatic-routing default to 20%, and cover the behavior in
the package tests and documentation.
