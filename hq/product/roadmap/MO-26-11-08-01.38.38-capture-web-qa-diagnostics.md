## Context

A screenshot and DOM pin can locate a web QA issue but cannot establish which build or app view state produced it. Capture enough evidence at placement to separate stale builds, stale data and UI bugs.

## Approach

Extend the existing web pin schema with versioned browser and operator-declared build diagnostics plus bounded, explicit state from an opted-in active view. Retain legacy comments and existing DOM and screenshot behavior.
