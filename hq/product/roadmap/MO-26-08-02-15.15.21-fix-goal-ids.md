## Context

Found while scaffolding Heinrich LLC — the second project this quarter's goal counts, so the
first thing a fresh project does hit it.

`morpheus pm new goals "..."` emits `HL-G-001`. `GOAL_ID` in `pm/schema.ts` requires
`HL-G-2026-Q3-01`. So `morpheus pm validate` fails on the file the CLI just wrote, in CI, on the
first push, in a repo that has done nothing wrong. Six identical errors on one file, because the
validator reports per-check rather than per-file.

The second defect is in the same three lines: `period` was `` `${date.slice(0, 4)}-Q1` ``, a
hardcoded Q1. A goal written on 2 August called itself a Q1 goal.

**Why the tests did not catch it.** `tests/pm.test.ts` asserted `MO-G-039`, `MO-G-041`,
`MO-G-001` — the generator's output, restated. Nothing in the suite ran a generated goal through
`parseArtifact`, so the generator and the schema were each internally consistent and never
introduced. Morpheus's own `hq/product/goals/MO-G-2026-Q3-01.md` is correctly shaped because it
was written by hand; `pm new goals` has, as far as the git history shows, never produced a usable
goal.

## Approach

The period belongs *in* the id, so id and `period:` become two renderings of one value:

- `periodInZone(d)` in `pm/id.ts`, beside `isoDateInZone` so there is still one `ZONE`. Deriving
  the period anywhere else is how the hardcoded `Q1` happened.
- `nextId` scopes the goal sequence to the period — `MO-G-2026-Q3-` — so Q4 starts at `01` rather
  than continuing Q3's run and leaving a gap that reads as a deleted goal. Local ids are filtered
  by that prefix instead of "trailing digits of anything in this directory".
- `SEQ_DIGITS`: two for goals (the schema spells `\d{2}`), three for requests, unchanged.
- `createItem` reads the clock **once** and threads it, so the id cannot land in a different
  quarter from the field beside it. `now` is injectable, which is what lets a test pin the period.
- `claimedNumbers` needs no change: the longer prefix lowercases into `mo-g-2026-q3-` and the
  existing `^prefix(\d+)-` branch pattern still separates goals from requests.

Tests assert through `parseArtifact` rather than against the generator, since that is the join
that was never exercised, plus a quarter-rollover case.

**Not done here:** requests keep `FR-\d{3}`, which its schema already accepts.
