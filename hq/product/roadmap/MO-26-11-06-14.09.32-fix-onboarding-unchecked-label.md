## Context

A live check of the installed CLI after #629 found this. `morpheus init`, run twice on a project
with no GitHub remote, rewrote `hq/onboarding.md` the second time, and the line changed from
"could not check" to "detected". Two steps were affected: branch protection and the Actions secrets.
Both still could not be checked.

The first run writes the unknown step as `[ ]`. The next run reads that box back as `todo`, so the
merge keeps that state with `detected: true`, and the renderer then labels it "detected". The
pre-refactor base CLI (70c297bc) behaves the same way, so this is not a regression from #629.

`learned.md` already warns against this pattern: *never let an unanswerable question render as a
confident answer*.

## Approach

Mark a status that detection could not answer as `unchecked`. It keeps the recorded box, but the
checklist, the terminal status and the unknown count all still say "could not check". The
detector-merge step becomes a small exported `detectedStatus`, so it can be tested without a
network.
