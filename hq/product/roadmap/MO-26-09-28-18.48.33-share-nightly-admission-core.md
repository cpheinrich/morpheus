## Context

Chris asked for iOS CI/CD improvements that generalize to be lifted into Morpheus
and adopted by the apps. The one that does: Evo's host-side nightly release
controller (darwin-health/evo #307, #309). It admits at most one automated
TestFlight release per local day, even after a failure. It persists the
reservation before dispatch, so a lost response never buys a second attempt. It
also judges the last upload from the upload step itself across every attempt, and
refuses to admit anything while an upload's outcome is unknown.

Lakina still runs the older shell watchdog Evo replaced. That watchdog matches
runs by `headSha == main`, so it dispatches again whenever main advances. It
re-dispatches every half hour after a failure, and it cannot tell whether a failed
run already reached App Store Connect.

## Approach

Extract only the generic part: local-day admission and reconciliation, and upload
evidence over GitHub job and step records. Put it in one self-contained,
dependency-free module, `src/ios/nightly-core.ts`. `morpheus ios nightly-core
--write <file>` vendors the compiled module into an app with its source version,
because the controller runs from a pinned runtime copy on the Mac mini where no
app `node_modules` is reachable. Notification delivery, incident hooks, the host
installer and each app's names and time window stay in thin app adapters. Evo
adopts it without changing behaviour; Lakina replaces its shell watchdog with it.
