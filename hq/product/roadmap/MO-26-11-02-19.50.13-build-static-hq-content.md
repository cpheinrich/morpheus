## Context

Morpheus currently scaffolds an HQ layout that reads the session cookie to render identity in the
shared chrome. Projects then commonly discover and parse `hq/` Markdown from request-serving code.
That makes immutable repository content dynamic, repeats work as repositories grow, and traces the
content corpus into server functions. Lakina measured 320–453 ms median authenticated response time
across representative HQ pages while scanning roughly 732 repository documents; Darwin's build
marks ordinary HQ routes dynamic and traces 208 Markdown files into five route bundles.

The permanent contract is static by default: repository content is consumed during the deployment
build, the existing request gate protects the generated HTML, and only explicitly live fields use a
request-time path. Existing projects need a migration route as well as corrected scaffolding.

## Approach

1. Specify the HQ rendering classes and security boundary in `architecture.md` and the website
   runbook: build-time repository content, immutable artifact handling, and explicit live islands.
2. Remove request identity from the scaffolded content shell, make new HQ pages statically
   renderable by default, and provide the smallest reusable build-time content primitive needed by
   existing projects.
3. Add deterministic tests/guards that fail when a generated HQ regresses to runtime repository
   reads or undeclared dynamic rendering.
4. Prove the contract in Lakina through a real production Vercel deployment, incorporate the
   measured production lessons here, then document the downstream migration for Darwin, Evo,
   morpheus-enterprises, and Kairos.

## Lakina production proof

Lakina PR #618 merged as `ae8e8a6f995ae406ad6ef975dd138e0e1f5a868c` and deployed normally to
Vercel production as `dpl_3n36gH8TeKs65inuDySaCTxPDmpv`. The deployment generated 781 pages,
including 733 repository-content routes; its contract allowed exactly eight dynamic routes and
found no Markdown in their runtime traces. Product HTML fell from 787,801 bytes to about 160 KB.

Seven-sample production medians changed as follows: Product 453.0 → 107.3 ms, Research 346.5 →
109.7 ms, Library 433.2 → 113.4 ms, Inbox 328.2 → 85.1 ms, the mixed live overview 438.7 → 264.9
ms, and live Portfolio 320.6 → 247.2 ms. Static pages were Vercel cache hits; the two portfolio-
backed pages remained intentional misses. The deleted theme endpoint returns 404, and signed-out,
forged-cookie, middleware-subrequest-spoof and RSC-prefetch probes all redirect to sign-in.

The reusable lesson is to keep the authenticated proxy in front of static HTML, not to move auth
into every page. A live panel should be isolated when practical; private immutable artifacts keep
their verified loader; and a postbuild check must use Next's manifests rather than paths Vercel's
adapter may move before `postbuild` runs.

## Fleet migration order

Darwin is next because it has the same measured runtime catalogue pattern. Evo,
morpheus-enterprises and Kairos follow under separate repository items, independent review, CI and
normal deployment. Each migration uses the runbook inventory and records its own declared dynamic
routes, build evidence and production verification rather than assuming Lakina's route set.
