## Context

Morpheus currently scaffolds an HQ layout that reads the session cookie to render identity in the
shared chrome. Projects then commonly discover and parse `hq/` Markdown from request-serving code.
That makes immutable repository content dynamic, repeats work as repositories grow, and traces the
content corpus into server functions. Lakina measured 320–453 ms median authenticated response time
across representative HQ pages while scanning roughly 732 repository documents; Darwin's build
marks ordinary HQ routes dynamic and traces 208 Markdown files into five route bundles.

The permanent contract is static by default: repository content is consumed during the deployment
build, the existing request gate protects the generated HTML, and only explicitly live fields use a
request-time path. Existing projects need a migration route as well as corrected scaffolding.

## Approach

1. Specify the HQ rendering classes and security boundary in `architecture.md` and the website
   runbook: build-time repository content, immutable artifact handling, and explicit live islands.
2. Remove request identity from the scaffolded content shell, make new HQ pages statically
   renderable by default, and provide the smallest reusable build-time content primitive needed by
   existing projects.
3. Add deterministic tests/guards that fail when a generated HQ regresses to runtime repository
   reads or undeclared dynamic rendering.
4. Prove the contract in Lakina through a real production Vercel deployment, incorporate the
   measured production lessons here, then document the downstream migration for Darwin, Evo,
   morpheus-enterprises, and Kairos.
