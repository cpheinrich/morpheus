## Context

The maintainer reads required checks through the REST check-runs and combined-status endpoints.
GitHub grants those endpoints under separate `checks: read` and `statuses: read` scopes. The first
cloud run proved check-run access worked, then the combined-status request failed with `403
Resource not accessible by integration` because the reusable jobs declared only the first scope.

## Approach

Grant `statuses: read` only to the inspection and delivery jobs that perform live revalidation, and
extend the workflow contract test so both sources of branch-protection evidence remain explicit.
The Codex job keeps its existing `contents: read` permission and receives no additional GitHub
authority.
