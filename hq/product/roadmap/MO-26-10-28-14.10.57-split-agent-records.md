## Context

`.agent/decisions.md` is 139,433 bytes (about 35k tokens) and `.agent/learned.md` 40,111 bytes;
`AGENTS.md` tells every session to read both, plus the inbox, before `morpheus context refresh`.
Profiling round 2 ([worklog](../../../.agent/worklog/2026-10-28-profiling-round-2.md)) found agents certifying receipts without reading —
`cat … >/dev/null && morpheus context refresh` — which is the failure the protocol says it cannot
detect. A mandatory read of about 45k tokens before any work starts is the incentive to fake it.

The file has also lost its shape: entries are appended at both ends, use `##`, `###` and bold-lead
paragraphs interchangeably, and the preamble ("Choices Chris made and why") sits below three newer
entries.

Lakina split its records by hand on 2026-09-22 (cpheinrich/lakinacapital#383): an index plus one
file per entry. Its index grew 51% in 15 days, because the index was hand-written prose that every
new entry extended — the size problem moved into the index instead of going away.

`AGENTS.md` went through the same cut on 2026-10-07 (MO-26-10-07-21.31.01): invariants stay,
detail moves to runbooks read on demand, and a test holds the budget. That held (≤ 20KB, enforced)
and is the model here.

## Approach

- One file per entry under `.agent/decisions/` and `.agent/learned/`, with frontmatter: `date`,
  `title`, one-line `summary`, `tags`, `scope` (`core`, or a subject such as `cd`, `review`, `ios`,
  `paperclip`), optional `supersedes` and `roadmap`.
- The index is **generated** from that frontmatter — never hand-edited — so it grows one line per
  entry and no faster. A `--check` mode fails CI when it drifts.
- A **byte budget** test for the generated index plus the `core` set, the same shape as the
  `AGENTS.md` budget test.
- Read protocol: a session reads the index and every `core` entry; others on demand when the task's
  subject matches (`pm tagged` already retrieves by subject). The context receipt fingerprints the
  index and core set rather than every entry, so a new non-core entry does not invalidate every
  receipt. Coordinate with MO-26-10-28-14.08.05, which is changing what a receipt proves.
- Superseded entries stay as files — history is not rewritten — but leave the core set and render
  in the index as superseded.
- **Roll out through `morpheus`:** a deterministic migration command that converts an existing
  monolithic file with entry text preserved verbatim, and `init` scaffolding the new layout.
  Morpheus first, then Evo, Lakina (reconciling its hand split), Darwin and Kairos.
- Which existing entries are `core` is a judgment pass, done once in the migration PR and checked
  by its reviewer.

## Research milestone authorized November 7

Chris requested the agentic CTO and research-engineer workflow to design, benchmark and refine
task-specific context retrieval, then present preliminary results before adoption. The milestone
mandate and draft preregistration are in
[the research worklog](../../../.agent/worklog/2026-11-07-benchmark-task-context.md).

Measure required-context recall, search time, context tokens and supported task outcomes. Compare
the current full-read contract, split records with ordinary search, the existing HQ MiniSearch core,
and broad tag/link-assisted retrieval; QMD is an optional comparator. Tags must guide, never wall
off knowledge. Reuse prior benchmark PR265 as evidence, preserving its negative and mixed results.

This expands the earlier index-only approach: a complete catalog may grow on disk, while the
startup brief stays bounded and task-selected. A selected body change or newly applicable record
must prompt relevant re-reading. The first consumer migration is Evo, after reusable Morpheus
mechanics and this preliminary-results review; that replaces the earlier Morpheus-corpus-first
rollout order. No production protocol, CI requirement or historical migration is activated during
the research milestone. Chris approved included-quota Factory trials and suggested GPT-6 Luna.
Pilot tags cover a subset of historical records. Include section-tagged canonical business meeting
notes and related repository-qualified PR links. After design acceptance, update the existing
Google Meet intake and its catalog projection. Live service lookups remain a separate future phase.

## Acceptance

- Generated index plus core set within the budget (proposal: 20KB, as for `AGENTS.md`); CI fails
  above it, and `--check` fails on a hand edit.
- The migration test proves no entry text was lost (concatenated bodies compared before and after).
- The profiling re-run (MO-26-10-28-14.11.08) shows mandatory records tokens down and no faked
  receipts.
