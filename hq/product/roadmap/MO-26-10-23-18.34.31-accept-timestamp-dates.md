## Context

Since #376 moved frontmatter parsing to `@11ty/gray-matter` (js-yaml 5), an unquoted YAML
timestamp such as `date: 2026-08-18T13:15:00.000Z` arrives as a string rather than a `Date`.
`isoDate` only normalised `Date` values, so `morpheus inbox validate` rejected files that passed
before with "Invalid ISO date". That fails the `pm` job on every Darwin pull request and on its
`main`, through `hq/team/cpheinrich.md` and `hq/team/robbie-del.md` (#466).

## Approach

`isoDate` also accepts a complete ISO timestamp string (`z.iso.datetime` with offsets or local
time) and keeps its date part as written. The whole value is checked, so `2026-08-18Tnonsense`
still fails. Every frontmatter date field (`created`, `updated`, inbox and journal `date`) goes
through `isoDate`, so the one change covers them all. Regression tests cover the parser path
through `parseInbox` and the schema directly. Verified end to end with the built CLI against
Darwin's real `hq/team` and `hq/product`, read-only.
