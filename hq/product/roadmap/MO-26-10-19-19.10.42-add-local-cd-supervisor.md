## Context

The shared Morpheus CD V2 controller can reconcile delivery state and run a local repair worker, but a consumer still needs safe, reviewable host wakeups on its signing-capable Mac. A prototype exists from Evo's recovery work; it is not in Morpheus and is not a supported integration. It exposed concrete defects: the CLI's real path is `dist/cli/index.js`, the command requires `cd tick|worker`, both source and config must be explicit, the credential helper must `exec` the child, and the repair worker needs its own recurring wakeup.

## Approach

Add platform-specific macOS templates beside the shared CD controller, with digest and path guards, separate launchd jobs for reconciliation and repair, a synthetic test that renders and runs them, and a consumer-facing runbook. Keep all credential values, app identity, environment rules, state initialization, service activation and delivery/cutover decisions in consumers. This is a source asset copied from an exact reviewed Morpheus commit, not a hidden installer or claim that a real host has been activated.

## Acceptance

- A consumer can identify the reviewed source templates and safely render their paths/digests.
- Tick and worker jobs wake independently every five minutes and invoke the correct CLI grammar with explicit source and config.
- Unrendered or changed templates fail before controller invocation; synthetic credentials reach only the controller child and never appear in logs.
- Documentation explains observe-first setup, launchd inspection and rollback, plus the boundary between shared wiring and consumer-specific cutover evidence.
- No consumer credentials or private RCA data appear in Morpheus.
