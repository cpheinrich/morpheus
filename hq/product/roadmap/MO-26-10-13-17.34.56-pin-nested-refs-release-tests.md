## Context

Issue #393. A consumer that pins these reusable workflows to a reviewed commit (darwin-health/evo
since 2026-10-13) still ran floating code: `ios-ci.yml` referenced its own `ios-simulator` and
`swift-changed-files` actions `@main`, and `ios-nightly-build.yml` nested `release-preflight.yml`
and `ios-ci.yml` `@main`. Separately, `firebase-tests.yml` keys its per-job concurrency on the
caller's ref with cancellation on, so a TestFlight release's backend tests on main were cancelled
by an unrelated merge, skipping the staging deploy and the upload.

## Approach

Probed on 2026-10-14 with a throwaway Evo caller: a local `./.github/workflows/...` reference
inside a called workflow resolves inside this repository at the called commit, and
`github.job_workflow_sha` is empty inside a called workflow's steps. So nested workflows use
local paths; composite actions are checked out (sparse, read-only, no credentials) at a new
`actions-ref` input that the consumer sets to the same commit it pins, used by local path.
`firebase-tests.yml` gains `concurrency-key`: a release passes its run id and is not cancelled;
the default keeps per-ref cancellation for pull requests. Tests pin all three shapes.
