## Context

Agents default to writing code and do not propose an open-source package unless explicitly asked —
Chris has hit this repeatedly with both Claude and Codex. Sometimes building is right; sometimes a
maintained lightweight package is. What he wants is the *proposal*: surface the option so he can
decide, rather than either silently building or silently adopting a dependency.

A standing preference ("prefer open source") does not change agent behaviour because there is no
moment it attaches to. What works is a convention tied to a concrete trigger — before writing a
generic module — with a required, visible output, the same mechanism as the inbox options format:
three real options cannot be written without doing the analysis, and a build-vs-borrow line in the
PR body cannot be written without doing the search.

## Approach

Add a "Build vs. borrow" convention to Working conventions in Morpheus's own `AGENTS.md` and in
the `agents()` template in `src/init/templates.ts`, so every future project scaffolds with it.
Three parts: a trigger (any generic, non-domain-specific capability), a cheap search step
(registry, last publish, downloads, dependency count, size), and the rule that the agent proposes
rather than silently decides in either direction — an ❗ inbox item when the choice shapes the
architecture, a line in the PR body when it is small. Prefer lightweight, low-dependency packages;
record outcomes in `.agent/decisions.md`.

Existing projects do not pick up template changes (`init` never overwrites), so the convention is
applied to each registered project's `AGENTS.md` by hand in per-repo PRs, tracked from this item.
