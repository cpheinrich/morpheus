## Context

Evo's `ios-qa` skill and `apps/ios/scripts/preview.mjs` owned the whole simulator QA lifecycle,
and the comment overlay was a second process the agent started by hand. Lakina now has an iOS app
and Chris wants to QA it the same way. Each agent also opened something different: Codex the raw
serve-sim page in its panel, Claude the native Simulator panel, and Grok has no panel at all.
Chris asked (2026-10-06) for every agent to use the same surface, with Grok opening the user's
default browser, and for the lifecycle to come out of Evo now.

## Approach

- `morpheus qa preview ios start|status|stop|doctor|help`: the lifecycle from Evo's script, driven
  by `morpheus.json` `qa.ios` (build, product, bundle id, launch modes with an optional
  credential-prepare hook). serve-sim becomes a pinned CLI dependency.
- The launchd supervisor starts serve-sim and then the comment overlay in one process, so one lease
  and one `stop` cover both.
- `morpheus qa guide` prints the agent instructions; the `comment-qa` skill (both `.agents/skills`
  and `.claude/skills`, from one template, scaffolded by `init`) points at it.
- One surface for every agent: the overlay URL, in Claude's Browser pane, Codex's browser panel,
  or `open <url>` for Grok.

## Acceptance checks

- A Lakina preview starts from config alone on a real simulator: a real frame in the overlay, input
  reaches the app, a pinned comment lands as a batch with a real-pixel frame, resolve, status, stop.
- An Evo preview starts through the same code, in demo and live modes, with Evo's previous launchd
  namespace and device names, without disturbing other checkouts' running previews.
- Two projects' previews run side by side without colliding.
- Every guarantee Evo's tests pinned is pinned again here.
