## Context

The shared build-time HQ search payload currently duplicates each document's full raw text in
stored result fields after MiniSearch has already indexed that text. Large repository-backed HQs
therefore transfer and parse substantially more private search data than the result UI needs.

## Mandate — 2026-11-02

- **Outcome:** shrink the shared build-time HQ search payload without reducing full-text match
  coverage.
- **Acceptance:** full document text remains indexed; full raw document text is no longer
  duplicated in stored result fields; result display uses a bounded precomputed excerpt;
  representative payload and size regression tests prove a material reduction; architecture
  documentation explains the design.
- **Authority:** change repository code, tests, documentation and committed distribution output;
  use the normal branch, pull-request, independent-review, CI, merge and deployment workflow. No
  access changes are authorized.
- **Budget:** no new monetary spend. Existing local tooling and included CI are allowed; no paid
  service, paid fallback or new dependency.
- **Stop:** after independent review, CI and merge, or at a concrete recorded blocker. This author
  stops before review clearance and merge so a fresh independent reviewer can assess the change.

## Approach

Keep full text in the fields MiniSearch indexes, but store only the metadata needed to render a
result plus one deterministic bounded excerpt prepared at build time. Pin search coverage,
excerpt bounds and serialized payload reduction with representative documents, update the shared
HQ search architecture, and regenerate committed `dist/` output.
