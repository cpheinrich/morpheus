## Context

Native projects need a reusable, governed way to upload the current reviewed `main` build to
TestFlight on a project-owned schedule. A nightly caller should not spend a macOS runner or mint a
new App Store Connect build when none of that app's owned paths changed since its last successful
upload.

## Approach

Add a secret-minimizing reusable workflow that reads the caller workflow's latest successful run,
diffs explicit project-owned paths, and skips loudly when the diff is empty. When a build is due,
compose the existing exact-main release preflight and secret-free iOS test workflow before entering
the caller's protected environment and invoking its repository-owned archive/upload script. Keep
schedule, path scope, app identifiers, environment policy, and Apple credentials in the caller.
