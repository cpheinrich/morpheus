## Context

`upload-testflight.sh` snapshots the runner user's keychain search list and default, installs its
temporary keychain as the default, and restores on exit. Two repository-scoped signing runners in
the same macOS GUI account (Evo and Lakina on the dedicated Mac mini) can overlap despite separate
workflow concurrency groups; one cleanup can remove the other's signing keychain from the search
list or restore a deleted default (#251). The host now carries a job-start `shlock` lease as a
mitigation, which is host-specific configuration rather than an action-wide guarantee.

## Approach

Make the same-account concurrency contract explicit in the action's documentation first. Then
choose between action-owned serialisation (a lock keyed on the GUI account, held from keychain
creation through cleanup, with a bounded wait and a clear timeout error) and isolated signing state
(never touch the user's search list or default; sign with `--keychain` pointed at the temporary
keychain and pass it explicitly to `xcodebuild`/`codesign`, so two jobs cannot see each other's
state). Isolation is preferable if Xcode's export honours an explicit keychain without it being in
the search list; test that on the mini before committing to it. Whatever lands, a regression must
prove two overlapping jobs both complete.
