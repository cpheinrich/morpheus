## Context

Darwin's production migration exposed two false classifications in the generated contract from
#591. An explicit dynamic route may overlap a concrete URL prerendered by an HQ catch-all; the
current membership-only check calls that explicit route static even when the manifest entry belongs
to the catch-all. The trace predicate also flags dependency README files, although the invariant is
specifically that request-serving HQ routes must not bundle repository `hq/**/*.md` source.

Correct this upstream before the next project migration so every later consumer receives the
production-proven behavior instead of another local exception.

## Approach

1. Classify an explicit route as static only when the prerender entry belongs to that route, while
   still recognizing catch-all prerenders from concrete entries when `dynamicRoutes` omits the
   pattern.
2. Restrict trace findings to repository `hq/**/*.md` paths in relative and absolute trace forms.
3. Add executable boundary tests for both Darwin shapes, rebuild the committed distribution, and
   update the contract documentation.
4. Merge through normal independent review and CI before resuming the next consumer migration.

The implementation authority is repository source, tests, documentation, PR, review and merge.
Use only existing local tooling and included CI; no new service, credential, package or spend is
authorized or needed.
