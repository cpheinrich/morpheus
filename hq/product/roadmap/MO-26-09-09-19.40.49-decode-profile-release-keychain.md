## Context

Every TestFlight upload attempted on Evo's self-hosted Mac mini runners since 2026-09-07 has failed in about twenty seconds with `security: cert import failed: Write permissions error`, `security: problem decoding`, and then the action's own "The decoded distribution profile is not a valid provisioning profile." The same script uploads fine from GitHub-hosted macOS runners, so the nightly only ships when someone dispatches it onto the hosted recovery lane by hand.

`security cms -D` verifies the profile's CMS signature by importing the signer certificates into a keychain, and without `-k` that is the user's default keychain. A headless runner user that has never logged in has no login keychain, so the default is the read-only System keychain and the import fails. Reproduced locally: decoding any installed profile with `-k /Library/Keychains/System.keychain` prints exactly the two `security:` lines from CI; decoding with a fresh unlocked temporary keychain succeeds.

## Approach

Create the ephemeral release keychain before reading the profile and pass it to `security cms -D -k`. The keychain already existed, was already unlocked for the import, and is already deleted by cleanup; the change only moves its creation above the decode and names it. No runner-side keychain setup is required, so the fix holds for any future self-hosted Mac whose runner user is created without a GUI login.
