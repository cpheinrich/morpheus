## Context

GitHub's `on.schedule` is best-effort and leaves no record of which occurrence a run was for, and
every repository encodes its cadence differently. Chris accepted one portable design: repositories
own their schedules, a host timer and a GitHub backup run the same tick, and run history is the
only ledger.

## Approach

- `.morpheus/schedules.json` per repository (`schemaVersion`, `schedules[]` of id, workflow, cron,
  timezone, inputs); a private host config lists enrolled repository names only.
- `morpheus scheduler tick --config <path> [--backup] [--dry-run]` reads definitions from each
  default branch, judges the latest due slot against the workflow's run history (run-name suffix
  ` [schedule:<id>:<instant>]`), and submits `workflow_dispatch` with `return_run_details`.
  Backup dispatches only after a 30-minute grace with nothing accepted since. Failures are isolated
  per repository and schedule; unreadable history is an error.
- `morpheus scheduler status` reports an atomic status file's freshness and errors.
- `morpheus scheduler admit` and `.github/actions/scheduler-admit` turn away duplicate runs of an
  occurrence under whole-workflow concurrency.
- Morpheus's hourly heartbeat cron is removed on Chris's instruction; the workflow stays manual.

Acceptance is the dispatch contract: a submitted, history-visible run per due slot. Consumer
delivery and host installation are separate work in their own repositories.
