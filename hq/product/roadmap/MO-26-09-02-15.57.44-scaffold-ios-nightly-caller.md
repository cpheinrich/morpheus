## Context

`init` scaffolds a caller `ci.yml` but nothing for iOS releases, so every iOS
project hand-writes `.github/workflows/ios-nightly-build.yml`. Two have, and
both arrived at the same two answers the expensive way.

Both chose `cron: "17 3 * * *"`, an arbitrary time neither project had a reason
for, which then had to be changed in two repositories when a standard slot was
agreed.

More costly: both discovered independently that GitHub does not pass a caller
repository's environment secrets into a cross-repository reusable workflow. The
upload job reads every secret as an empty string and fails on whichever the
upload script checks first — which reads as *missing secret*, so the obvious
response is to add secrets that are already there. Evo fixed it in
MO-26-09-02-12.23.59, which added `run-upload` and the `build`/`sha` outputs.
Kairos hit the identical failure four nights running and rediscovered the same
cause from scratch, forty minutes after that fix merged.

`run-upload`'s description already documents the constraint. Nobody reads an
input description while debugging a secret that they can see is set.

## Approach

Add an `iosNightly` template and write it from `init` when the repository has an
Xcode project under `apps/ios`.

It ships the two things that are not app-specific: 06:00 America/Los_Angeles as
the nightly slot, and the upload job in the caller with `run-upload: false`.
Everything else — team id, bundle id, App Store Connect app id, beta group — is
a `TODO` marker, because a plausible-looking wrong value fails later and less
clearly than a marker does.

The schedule ships commented out. A freshly scaffolded project has no signing
credentials, so a live cron would fail nightly until someone configured them,
and a scaffold that is red before it is touched teaches people to ignore red CI
— the rule `ci` already follows for `node-ci`. Uncommenting is one line;
leaving it commented is a supported end state for a project that releases on
demand.

Does not touch existing callers. `init` never replaces an authored file.
