## Context

The first implementation keeps PostHog initialization and capture helpers in Evo while Morpheus
owns only the provider-neutral schema scaffold. Extracting a runtime package before another client
exists would turn Evo-specific assumptions into a supposed standard.

## Approach

Revisit after a second web or mobile product implements the canonical event contract. Compare the
real adapters, then extract only repeated initialization, privacy filtering, schema validation and
test fixtures into `morpheus-kit/analytics`. Add `/hq/analytics` KPI readers with explicit mappings
from each project's events to shared business metrics; do not infer equivalence from event names.

## Acceptance

- Two production implementations are compared and the common behavior is documented.
- The package consumes project-owned schemas and does not define product event vocabulary.
- Web and mobile consumers have provider-independent tests for validation and privacy filtering.
- `/hq/analytics` reports named KPIs through explicit per-project mappings and links to PostHog.
