## Context

The router dropped every gateway of the coordinator's own provider, so a Claude session
could never use the Claude subscription behind the sub2api gateway (and a Codex task never
the Codex one). Chris: a gateway is a separate subscription reached as an API and a valid
delegate; only the coordinator's own native login is excluded, because that is circular.

## Approach

- Routing: any gateway below the threshold is eligible; the roomiest wins, else the work
  stays here. An explicit executor prefers its provider's gateway.
- Both start paths launch whichever worker routing chose, inheriting the coordinator's
  model, effort and permission mode or sandbox; saved sessions are keyed per gateway.
- `codex_answer` lets a Claude coordinator answer a gateway Claude worker's live question.
- Worker environments drop every variable a configured secret reference names.
