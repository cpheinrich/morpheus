## Context

`architecture.md` named **Semrush** as the canonical SEO tool in six places and, for ASO, only
"ASC integration" — no research tool at all. Chris has since subscribed to **OpenSEO** for website
SEO and **Appeeky** for app-store ASO, and both are live as remote MCP through claude.ai. Earlier
planning documents outside this repo also named **AppTweak** for ASO.

Leaving the spec stale is worse than an ordinary doc lag: `architecture.md` is what agents read to
decide which tool to reach for, so a wrong name here sends every future agent to a product the
account no longer pays for.

## Approach

Replace all six Semrush references, add ASO as a first-class canonical choice alongside SEO, and
add **§6.2** explaining the split — because the failure mode is not "agent cannot find the tool"
but "agent uses the website tool for an app question". The two vocabularies overlap ("keywords",
"rank", "visibility"), and app-store search volume rendered in a table is indistinguishable from
Google search volume while meaning something entirely different.

§6.2 keeps a short note that OpenSEO and Appeeky *supersede* Semrush and AppTweak, rather than
deleting the old names outright — the names appear in planning docs in other projects, and a
reader who arrives with "we use Semrush" needs to land somewhere that says otherwise.
