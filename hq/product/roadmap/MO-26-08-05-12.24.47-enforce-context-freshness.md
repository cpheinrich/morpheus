## Context

An agent can currently claim a task, write a plan, or open a draft pull request
without proving that it has loaded the current project state or made a
substantive implementation checkpoint. That makes a stale session look active,
and lets a long-running session carry on after another agent changes the
canonical GitHub record.

Morpheus must make freshness and progress observable and enforceable at the
boundaries where local work becomes durable or externally consequential.

## Approach

- Add local, gitignored context receipts and five-minute session leases. A
  receipt records the remote SHA and canonical records read; it never stores
  raw agent memory or conversation contents.
- Gate durable and governed actions on a fresh lease, beginning with pure,
  provider-neutral PM/session logic that CI can exercise with a mock adapter.
- Add runner adapters only after the local guard works: Codex app-server
  steering/interruption and Claude lifecycle/tool hooks share one lease format.
- Distinguish claimed/context-current/substantive-started/blocked in PM and
  retain deterministic CI checks plus a read-only local review rung.

## Acceptance

1. CI tests simulate fresh, stale, unknown/offline, and acknowledged receipts
   with a mock AI-session adapter; no test needs a provider account.
2. Stale or unknown leases block commit/push and governed Morpheus actions,
   with an explicit offline exception that cannot push or operate external
   controls.
3. Session start/resume refreshes before PM work can begin; a five-minute
   active lease names the smallest relevant canonical delta after drift.
4. Codex and Claude adapters have contract tests and never write raw session
   data.
5. CI validates the PR's receipt/progress semantics against the pushed SHA,
   and generated projects receive hooks, policy, and adoption reporting.
