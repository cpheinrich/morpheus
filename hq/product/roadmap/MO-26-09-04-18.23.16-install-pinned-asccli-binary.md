## Context

The first Intel Evo TestFlight run proved the source-build fallback from #211 works, but installing
`asccli` consumed 17m45s of a 60-minute protected upload job before Xcode could begin. The upstream
v0.18.2 release publishes separate macOS arm64 and x86_64 binaries with SHA-256 checksums, so every
nightly can use the same pinned release without depending on Homebrew bottle coverage or compiling
a release tool from source.

## Approach

Download the official architecture-specific v0.18.2 asset before credentials enter the process,
verify it against the upstream published checksum, and put only that verified executable on the
job path. Keep OpenSSL and optional Sentry installation unchanged, cover both architectures in the
workflow contract tests, and retain the same behavior in the composite action and legacy built-in
upload lane. Preserve the upload id and poll its resource alongside the builds collection so Apple
processing failures surface their code and description immediately instead of degrading into a
20-minute build-list timeout.
