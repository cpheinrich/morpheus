## Context

There was no website initializer. `morpheus init` scaffolds a repository — the manifest, records,
the `hq/` tree, CI, a deny-by-default Firestore gate — and writes no application code at all:
no `apps/web`, no `/hq`, no Firebase wiring. `apps/web` is not even in `doctor`'s expected
directories. So every project's web surface was hand-built, and the three that exist disagree.

Chris shipped email waitlist capture on Darwin's home page
([darwin-health/darwin#35](https://github.com/darwin-health/darwin/pull/35)) and asked for it to
be a default of setting up any Morpheus website, together with the two things a site needs before
it can have one: a real Firebase project, and `/hq` behind Google sign-in.

The provisioning half was also missing. `morpheus init status` lists `gcp-project`, `firebase` and
`vercel` as checklist items with prose instructions and no automation; only
`morpheus firebase auth setup` actually does anything.

## Approach

A separate command, `morpheus web init`, rather than folding this into `morpheus init` — Chris's
call. §12.11 says `init` provisions nothing so it can never be blocked on a token, and an `init`
that shelled out to `gcloud` would break that for a command routinely re-run on established repos.
The new command is allowed to be blocked on a credential, and its provisioning half is
context-gated (`external`) while its scaffolding half is not gated at all.

Provision, then scaffold, in that order: GCP project → APIs → Firebase → Firestore (`nam5`) →
web app and its *read* SDK config → Workload Identity Federation for Vercel → `firebase auth
setup` last, because it is the only step that can need a human at a consent screen.

Everything Firebase-dependent is written only once the project is real. `--no-provision` and a
blocked step both skip the waitlist and `/hq` and say so, rather than emitting a sign-in page
against a placeholder config.

Never overwrites, so the same command creates a site and completes a live one. Three merges are
unavoidable and each is reported: app dependencies, the shared package's `exports` map, and the
Firestore rules — the last anchored on the generated catch-all rather than inserted at a guessed
position.

Scaffolded projects gain a `website-init` skill so an agent finds the command when someone asks
for a website, rather than hand-rolling a worse version of it.

Specified in `architecture.md` §12.12.
