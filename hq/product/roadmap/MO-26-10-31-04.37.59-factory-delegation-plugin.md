## Context

`plugins/codex-claude/` is a two-way delegation bridge between Codex and Claude
Code, but it is named for that specific pair and is native-auth-only: it strips
`ANTHROPIC_*`/`OPENAI_*` overrides and requires a `claude.ai`/ChatGPT sign-in.
Chris now pools subscriptions behind a sub2api gateway and wants the plugin to
delegate to those pooled subscriptions first, falling back to native only when
the pool is exhausted. The plugin should be a general-purpose "factory"
delegation layer: either Claude or Codex can coordinate, and it fans out to
workers (native or gateway) without knowing which API it is hitting.

## Approach

1. Rename `plugins/codex-claude/` → `plugins/factory/` and generalize the
   user-facing surface (package name, tools, skills, env marker).
2. Add a `gateways` config — a list of `{ name, provider, baseUrl, keyRef }` —
   as the auth seam. `keyRef` is `env:NAME` or `secret:path`, never a raw key.
3. Read each gateway's usage from the sub2api admin API
   (`GET /api/v1/admin/accounts`, the `*_used_percent` fields).
4. Replace the threshold routing with placement: explicit model → the gateway
   with the most headroom (if any is below `threshold`, default 90) → native.
5. When a gateway is selected, set the provider overrides instead of stripping
   them, and skip the native auth check. Native mode is unchanged.

## Acceptance

- The plugin is renamed to `factory` and installs/registers under that name.
- A configured gateway routes a delegated run through sub2api (overrides set,
  native check skipped); native mode still strips overrides and verifies sign-in.
- Placement picks the most-headroom gateway below the threshold, honors an
  explicit model, and falls back to native when the pool is exhausted.
- Existing tests pass; new tests cover the gateway config, quota parsing, and
  the placement rule.
