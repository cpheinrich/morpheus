## Context

`ios-nightly-build.yml` runs its `test` job through `ios-ci.yml`, which already accepts a
`skip-testing` input, but the nightly workflow neither declares nor forwards it. A consumer
pinned to the shared release workflow therefore cannot ask one release run to leave a test
target out: Evo needed an urgent staging TestFlight build that still runs its unit target but
skips the multi-hour UI target, and had only the full suite or no release
([#401](https://github.com/cpheinrich/morpheus/issues/401)).

## Approach

Add an optional `skip-testing` string input (default empty, same semantics as `ios-ci.yml`) and
pass it to the `test` job. Nothing changes for callers that do not set it; the caller decides
what a release may skip and when, and the input's description says a production path should keep
it off. `tests/workflows.test.ts` checks the default and the forwarding.
