## Context

Delegating a cpheinrich.com task from Codex to Claude failed with "No Claude model mapping for
Codex model "gpt-6.1-sol"" (#479). Every Codex model released after the plugin's default
`modelMap` blocks delegation until the user is asked to pick a Claude model. Chris authorized
an automatic fallback for this whole class, suggesting latest Opus or Fable.

## Approach

A validated `modelFallback` setting, default `opus` (a family alias the installed Claude CLI
resolves), selects the model when neither an explicit override nor `modelMap` names one.
Explicit overrides and configured mappings keep precedence; moving aliases stay refused for
the fallback too; `null` restores the visible failure with a diagnostic naming the setting.
The run's `selection` records `source` (override, mapped or fallback) and the requested
Codex model, so the coordinator can report what ran without asking. No retry on CLI errors,
no API-key or paid-overage path. README and the delegate skill are updated narrowly.

## Acceptance

- `gpt-6.1-sol` and any other unmapped Codex model select `opus` with fallback provenance and
  start without a model question; configured mappings and explicit overrides are unchanged.
- Existing saved settings without the key load with the default.
- A disabled or moving-alias fallback is refused with a clear diagnostic.
