## Context

Rung 2 fires on `pull_request`, which includes `synchronize` — so every push buys another review.
`learned.md` already records what that costs: *"the cost is not per PR, it is per push, and an agent
that iterates diligently is the worst case."* The gate added in response
(`morpheus review needed`) removed the records-only pushes, which was the cheap half. A branch
that pushes code five times still pays five times.

Chris's call, 2026-08-17: review once when the pull request opens, then again only when someone
asks for it by name.

The trigger is the right lever rather than a smarter gate. The decision that reverted rung 2 to
Opus said it plainly — **the gate, not the model, moves the bill** — and a heuristic guessing which
pushes deserve a second look is a worse version of a signal that already exists: a human typing
`@claude`.

## Approach

Two changes, both to triggers, neither touching the reviewer itself.

**Review on open.** `ci.yml`'s `agent-review` job gates on `github.event.action`, so `synchronize`
runs every other rung and skips this one. `ready_for_review` is not in `pull_request`'s default type
list, so the types are spelled out — a draft marked ready is the moment a review is wanted most.

**Re-review on request.** A separate caller on `issue_comment`, because that event carries no
`pull_request` payload. Three things it has to get right, and each has a failure mode that looks
like success:

- **The comment author must be trusted.** This repo is public and takes external contributions, so
  a bare `@claude` check lets any stranger spend the API budget. `OWNER`, `MEMBER` and
  `COLLABORATOR` only — the settled rule that Morpheus does nothing by default for anyone without
  repo collaboration access.
- **The checkout must be the pull request's head.** An `issue_comment` workflow runs the copy of
  itself on the default branch with `github.ref` pointing at `main`. Checked out naively the
  reviewer reads `main`, finds nothing wrong, and posts a clean review of the wrong code.
- **The reusable workflow must stop reading `github.event.pull_request.*`.** Four places do — the
  review cursor, the prompt's branch, and both ends of delivery — and all four are empty on a
  comment event. They become a `pr-number` input resolved once, with the rest derived from the API.

Reviewing on open only would otherwise trade a real capability away: the most useful re-review this
rung has done confirmed a fix it had itself asked for. The request path is what keeps that, and it
keeps it at the moment a human judges it worth a dollar rather than on every push.

## Acceptance

- A `synchronize` push runs `node`, `pm` and `pr` and does not run `agent-review`.
- `@claude` from Chris on an open pull request runs rung 2 against that branch's head.
- The same comment from an outside contributor does not.
