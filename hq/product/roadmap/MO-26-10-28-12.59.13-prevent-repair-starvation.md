## Context

The current worker selects the first insertion-ordered due repair before checking
pause or typed-intent exclusion. A repeatedly invoked older work item can keep
winning ahead of another due repair, and a paused/typed first candidate can end
the pass even when a later ordinary repair is eligible. This is a verified source
mechanism; its exact contribution to Evo's production stall is not yet proven.

This is the next bounded recovery improvement under Chris's 2026-10-28 live-data
and supported read/write CD mandate. The protected quota-diagnostic fix is already
merged as PR536/cb502558; this item preserves it and addresses default selection
only. It grants no subscription, review, source-age or upload bypass.

## Approach

Build a deterministic selection view over current due, non-complete,
lease-eligible work. Prefer runnable ordinary/unpaused candidates by least recent
actual invocation start (creation time when never invoked), with stable ID ties.
When none can run, retain existing paused/observe/idle diagnostics. Explicit
work-id behavior and every subsequent quota, pause, typed-intent, global executor,
lease/fence and host/session guard remain unchanged. Do not reorder native state,
add persistence or introduce a scheduler framework.

Root owns PM/public/operations and the source review/CI/merge loop. One source
author owns worker selection, focused tests and the narrow controller-doc update
in this new task worktree. Future normal-worker runtime binding and exact
operational adoption remain separate from source publication.

## Acceptance

- An insertion-first paused or typed candidate does not block a later eligible
  ordinary repair; no typed work launches through ordinary selection.
- A repeatedly invoked work item does not always win over an older never-invoked
  eligible item; not-yet-due and unexpired lease work remain excluded.
- Selection ties are deterministic, explicit target behavior stays intact, and
  normal pause/observe/idle diagnostics remain when no work can run.
- Existing fresh-quota, CAS/fence, reservation, host/session and evidence guards
  continue to pass meaningful focused regression tests.
- No new native scheduler, model/account probe, runtime adoption, review grant or
  TestFlight receipt is inferred from the source tests.
