## Context

Chris was building darwin's `/hq` page and the dashboard did not match the folder structure it
rendered. Adding a README to `hq/` explaining what the folder is for fixed it — and raised the
general question.

The explanation already existed, in `architecture.md`, in another repo. **Locality is what a
README buys**: eight lines where an agent is standing beat 1,400 lines it never opens.

## The rule, and why not "every folder"

Measured across six repos: 361 directories, ~55 with a README. "Every folder" would mean 150-200
new files, most restating the directory name. Written in a sweep that is filler — it looks
documented, says nothing, and can then go stale. The same reason inbox options must not be padded.

So: **a folder gets a README when an agent could plausibly do the wrong thing without it** — it
feeds something else, carries a convention filenames do not reveal, is generated, or is a seam.
Framework-standard directories are excluded. That is roughly 30 folders, each earning its place.

## What changes

- `init` writes **real** READMEs for `hq/inbox`, `hq/marketing`, `hq/finance`, `hq/ops`, `qa`,
  `qa/acceptance` and `infra` — replacing a placeholder that wrote `Nothing here yet.` into every
  directory, which is that filler already in the codebase
- `qa/acceptance` and `infra` join the expected structure. Both are in the specification and were
  in no project's scaffold, so every repo grew them by hand or not at all
- the rule goes in `AGENTS.md` and `.agent/decisions.md`

## Deliberately not a check

`doctor` does not require a README. A check that demands a file gets a file — stubs written to
silence it, which is the failure this item is fixing.

## Not in scope

Backfilling existing repos. This ships the rule and the scaffold; the ~30 folders across six repos
that qualify are a follow-up, and worth doing by hand rather than generated.

## Test plan

Five cases: the READMEs say something specific, they point at `architecture.md` rather than
restating it, `qa/` and `infra/` are scaffolded, and `hq/brand/` still gets no README because the
brand wizard owns that filename.
