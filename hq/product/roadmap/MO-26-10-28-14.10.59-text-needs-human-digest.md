## Context

PRs labelled `manager:needs-human` by the GitHub Manager rose from 4 to 16 between 2026-09-24→10-07
and 10-09→10-22 ([worklog](../../../.agent/worklog/2026-10-28-profiling-round-2.md)). The label is the manager's whole escalation path and only
works if Chris looks at GitHub; he reads texts, not dashboards, and `zoe-text` is the established
way to reach him. Open `❗` inbox items across repositories have the same problem — MO-26-08-01-047
(`inbox status`, one front door) solves reading them in a terminal, not being told about them.

## Approach

- A weekly job collects, across opted-in repositories: open PRs labelled `manager:needs-human`
  with the decision the manager quoted, open `❗` inbox items, and `blocked` roadmap items with
  their `needs:`.
- Each becomes one line with its options — manager escalations and inbox decisions already carry
  A/B/C/Other — and a link, sent with `zoe-text me "…"` and split across texts when long. It is
  one-way: answers go where they go today (PR comment, inbox reply), and the text says where.
- Home: `zoe-text` works from cloud sessions with `ZOE_TEXT_TOKEN`, so a schedule in the private
  operations repository that already runs the GitHub Manager needs no machine to stay awake. The
  token would be a new secret there; weigh that against a Mac-hosted scheduled task.
- Reuse MO-26-08-01-047's reader if it has shipped; otherwise build the shared reader once for both.
- Quote the manager's own escalation text, never untrusted PR titles or bodies verbatim.

## Needs from Chris

A yes on cadence and shape before anything is sent:

- **A — weekly, Monday morning Pacific, one text per item (recommended).**
- **B — weekly, one combined text with links.**
- **C — only when new items appeared since the previous digest.**
- **Other.**

## Acceptance

- Chris receives a digest whose item count matches the GitHub and inbox query run at the same time.
- The `manager:needs-human` trend is reported in the profiling re-run (MO-26-10-28-14.11.08).
