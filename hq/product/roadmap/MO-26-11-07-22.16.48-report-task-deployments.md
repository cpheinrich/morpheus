## Context

Operations Desk needs bounded deployment evidence on existing enrolled scheduled task rows.
The existing task wire, producer document and owner-only reader must stay compatible.

## Approach

Extend only the canonical optional reporting protocol with optional deployment history and
source-relative clock validation. Keep the existing reporter pass-through and file security.
Consumers vendor the canonical file verbatim and accept it server-first before producers activate.
Source-only draft: no runtime, credential, enrollment, deployment or merge action is authorized.

## Acceptance

- Missing deployment history stays absent; existing v1 task rows remain valid.
- At most five deployments per task, unique by run ID, with positive safe numeric identities,
  closed state values, nullable full lowercase source SHA and at most sixteen distinct stage IDs.
- Deployment timestamps reject future observations/starts beyond the existing sixty-second
  tolerance against the source sample clock; rereads preserve actual producer timestamps.
- Unknown stage IDs stay valid without authorizing arbitrary links, payloads, names or logs.
- Focused document/wire and real-file reporter tests preserve private-file and size restrictions.
- Provide exact canonical bytes/hash and an independent review packet; leave PR draft.

- Existing GitHub job rows optionally carry up to three deduplicated positive safe PR numbers
  from explicitly same-base-repository run references only. Absent proof preserves legacy shape;
  malformed/foreign/conflicting evidence is excluded, with no new GitHub call or arbitrary text.
