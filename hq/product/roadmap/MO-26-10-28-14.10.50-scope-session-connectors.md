## Context

Profiling round 2 ([worklog](../../../.agent/worklog/2026-10-28-profiling-round-2.md)) measured Claude's first-turn context growing from 91k to
101k to 107k tokens across its three windows (2026-09-24→10-07, 10-09→10-22, 10-22→10-28). The
largest single mover was the deferred-tool list that claude.ai connectors add to every session:
about 6k tokens before, about 14k after new or re-enabled connectors (OpenSEO, Google Calendar,
Sentry, Cloudflare, Granola, Webflow, Asana). Every coding session and every subagent pays it
whether or not the work touches those services, and nothing in any repository changed when it grew,
so no review or test could have caught it.

The session that filed this item is an example: a Morpheus records task whose deferred-tool list
carried Vercel, OpenSEO, Calendar, Sentry, Cloudflare, Granola and other connectors, none used.

## Approach

1. **Audit.** List every connector enabled on the claude.ai account and every MCP server in each
   registered project's and the user's Claude and Codex configuration, with its measured
   deferred-tool cost (first-turn usage with it on and off) and whether each project's sessions
   called it in the last 30 days (`morpheus profile` already reads tool calls from transcripts).
2. **Find the scoping mechanism before building one.** Establish what Claude Code and Codex offer
   to scope claude.ai connectors and MCP servers per project or per session (project settings, the
   desktop app's per-session connector toggle, Codex profiles), and whether a subagent inherits its
   parent's set. Build nothing if configuration suffices.
3. **Per-project profiles.** Record the chosen set per project somewhere checked in that
   `morpheus doctor` can compare with the live configuration, and report drift — a connector
   re-enabled on the account should surface as a finding, not as a slow context regression.
4. Keep the canonical research tools reachable where that work happens: OpenSEO for websites and
   Appeeky for app stores (`architecture.md` §6.2). Being connected stays no licence to use Semrush.

## Needs from Chris

Which connectors belong where. Several are account-wide and also serve claude.ai chat, Cowork and
marketing sessions, so the trade-off is his. The audit produces a project × connector table with
measured cost and use; the proposed default to react to is that coding repositories get only the
connectors their sessions called in the last 30 days, and everything else is opt-in per session.

## Acceptance

- Audit table committed: project × connector × token cost × 30-day use.
- First-turn context of a Morpheus coding session measurably below the 107k of 10-22→10-28, in the
  profiling re-run (MO-26-10-28-14.11.08).
- `morpheus doctor` reports a connector enabled outside a project's profile.
