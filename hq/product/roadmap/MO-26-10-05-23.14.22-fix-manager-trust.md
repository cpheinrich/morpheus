## Context

The GitHub Manager's first run on Evo (2026-10-05, ops run 37422417014) skipped seven of Chris's
own pull requests as `untrusted-author`. Evo is in the `darwin-health` organization and Chris's
membership there is private. `author_association` is computed from what the reader can see, and
an App installation token cannot see private membership, so an owner with admin rights read as
`CONTRIBUTOR`. Robbie's pull requests, whose membership is visible, were trusted correctly.

## Approach

When the association alone does not establish trust, read the author's repository permission
(`GET /repos/{repo}/collaborators/{user}/permission`, which needs only metadata read) and trust
`admin`, `maintain` or `write`. A permission that cannot be read stays unknown and is not trust.
A fork is still refused whatever the permission.
