## Context

Review-coverage failures — a commit pushed after the reviewer's `covered` commit, so the record no
longer covers the head — rose in Evo from 6 to 14 in the sampled windows (2026-09-24→10-07 vs
10-09→10-22; [worklog](../../../.agent/worklog/2026-10-28-profiling-round-2.md)). Each costs a CI cycle, a review turn, or a stall the GitHub
Manager later clears. The author finds out from CI minutes after pushing, though
`morpheus review validate` can say it locally in seconds.

Visual-evidence failures feed the same loop. When the `## Visual evidence` section exists but no
URL is approved, the message in `src/check/visual-evidence.ts` names neither the paths that need
evidence, nor the configured `allowedUrlPrefixes`, nor the URLs it found and why each was refused,
so the author guesses and pushes again.

## Approach

1. **Warn before the push.** A managed `pre-push` block — the same marked-block mechanism as the
   existing `post-merge` and `post-rewrite` blocks, beside any existing hook — that, when the
   branch has a committed review record, runs `morpheus review validate` on the commits being
   pushed and **warns, never blocks**, when they fall outside what the record covers, naming the
   remedy (late correction with `scopeReason`, finalization, or a hand-resolved trunk merge to
   record). Skip fast when there is no record; no network.
2. **Name the missing artifact.** Visual-evidence findings list the paths that require evidence,
   the configured prefixes, and each URL found with its rejection reason (prefix, query string,
   `authuser` shape).
3. Same for review-coverage failures in `check pr`: name the commits past `covered` and the paths
   they touched.

## Needs from Chris

Whether the `pre-push` block may install under the existing device consent for managed Git hooks,
which was given for automatic updates, or needs its own question. Until he says, treat it as its
own opt-in.

## Acceptance

- Pushing a code commit after `covered` prints the warning locally with the commit and the remedy;
  a worklog-only commit prints nothing. Tests assert both.
- Visual-evidence failure text includes the paths, the prefixes and the rejected URLs, asserted by
  value.
- Evo review-coverage failures per two weeks back toward the 09-24→10-07 level in the profiling
  re-run (MO-26-10-28-14.11.08).
