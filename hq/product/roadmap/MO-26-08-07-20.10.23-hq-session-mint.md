## Context

`morpheus-kit/hq` verifies Firebase session cookies and decides access from them. Nothing in the kit
ever *created* one, and the omission had a cost downstream: with no mint available,
`cpheinrich.com` stored the raw **ID token** as its session cookie. Google fixes those at one hour,
so the site asked for Google again on nearly every visit.

The natural fix is the wrong one. Raising the cookie's `maxAge` produces a longer-lived cookie
carrying a token that expired an hour in; verification fails on `exp` and the login page returns on
exactly the same schedule. That is a change which looks like it worked and did not, which is the
kind of trap the kit exists to remove.

Reported by `cpheinrich.com` — see the linked issue.

## Approach

- `src/hq/session.ts` — the mint and its policy. `createHqSessionCookie` takes the caller's
  already-initialised Admin `Auth` **as a parameter and never imports `firebase-admin`**, for the
  same reason `gate.ts` returns a decision rather than a `NextResponse`: the kit is imported by edge
  middleware and `firebase-admin` is Node-only. Three lines of call are not worth pinning every
  consumer's runtime; the policy around them is what is worth sharing.
- `clampExpiresIn` clamps rather than throws. A project asking for 30 days has made a reasonable
  request against an unreasonable API limit, and failing their sign-in over a constant helps nobody.
- `renewalDue` — renewal, not duration, is what makes a session permanent. Reads `iat`/`exp` off the
  payload the gate already verified, so there is no second store to keep consistent.
- `src/hq/return-to.ts` — `safeReturnTo`. The gate produces a `next` parameter and shipped no
  narrowing for it, so every project writes its own and `raw.startsWith("/")` admits
  `//evil.example`. An open redirect on the one route that exists to be trusted.
- `architecture.md` §11.1 gains the ID-token-versus-session-cookie table, the renewal model, and the
  two consequences that are load-bearing and non-obvious — that minting needs a service-account key,
  and that a long session weakens automatic revocation.

## Acceptance criteria

- [x] `createHqSessionCookie` mints through a caller-supplied `Auth` and imports no Firebase package.
- [x] Requests outside Firebase's 5-minute–14-day range are clamped, not thrown.
- [x] `renewalDue` returns false on an unreadable window rather than re-minting every request.
- [x] Cookie attributes are shared, `sameSite: lax`, with a matching clear.
- [x] `safeReturnTo` rejects protocol-relative URLs, backslashes, control characters, prefix
      near-misses, and denied destinations.
- [x] `architecture.md` explains why raising `maxAge` does not lengthen a session.
- [x] Tests cover all of the above, including that the module never imports `firebase-admin`.

## Open questions

- **Distribution.** `.agent/decisions.md` settles this as a git dependency, and the stated reason is
  that the repo is public and therefore needs no token. Chris plans to make Morpheus private within
  days, which invalidates that premise: a private git dependency needs a credential in every
  consumer's CI and in Vercel. Raised in the linked issue; not decided here.
- **`morpheus hq session revoke <email>`** — a CLI wrapper for `revokeRefreshTokens`. Wanted before
  it is needed rather than during an incident. Not in this change.
