## Context

Reported from Evo, where it cost a review round and a CI round trip
([darwin-health/evo#281](https://github.com/darwin-health/evo/pull/281)).

`ios-ci.yml` defines what "the Swift files this change touched" means, in shell, inside a workflow
step. Nothing outside that step can call it. Evo needed the same answer locally — to catch a
formatting violation in a second rather than after a nine-hour queue on a shared Mac mini — and so
reimplemented it, and drifted within one commit:

- a bare `apps/ios/**/*.swift` pathspec instead of `:(glob)…`, which silently omits a Swift file
  sitting directly under the working directory, so local reports clean and CI fails
- no `-z`, so a filename outside ASCII comes back quoted by `core.quotePath` and is dropped without
  a word

Both were found by a reviewer comparing the two lists by hand, which is the only way they *can* be
found. Every consumer that ever wants a local pre-check has to write this again, and each rewrite
is an independent chance to approximate the pathspec or forget the delimiter.

Three more consumers are about to need it: Chris has asked for `swift-format` to be adopted in
Kairos, Lakina and Pace.

## Approach

One committed implementation — `scripts/swift-changed-files.sh` — with two modes that differ only
in which commits they compare:

- **commit** (what CI asks): `HEAD^1..HEAD`, falling back to every tracked file when there is no
  first parent, exactly as the step does today
- **base** (what a developer asks): the merge base with a named ref, optionally including
  uncommitted and untracked work

A composite action wraps it for the workflow, which is how `ios-simulator` already reaches this
repository's files from a caller's checkout. The package ships `scripts/` so a consumer can call
the same file from `node_modules`, and `morpheus ios changed-swift` exposes it without anyone
needing to know that path.

The test is the point: one scratch repository, both modes, identical lists — including a Swift file
directly under the working directory and a non-ASCII filename, the two cases Evo's rewrite got
wrong. Neither mode can drift from the other without failing it.

Base-ref *policy* stays with the consumer. `merge-base` against a configured trunk is a
developer-loop concern with no analogue in CI, where the commit and its first parent are the whole
world.
