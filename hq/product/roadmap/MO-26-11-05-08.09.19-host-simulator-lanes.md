## Context

A consumer's CI VMs are not all the same size: one host's VMs can hold two booted simulators and
another's cannot, and two workers on a host too small for them has caused memory pressure and
timed-out tests. The
reusable `ios-ci` workflow only takes a fixed `parallel-testing` / worker count from its caller, so
a caller whose jobs land on mixed hosts must choose one count for all of them.

## Approach

- New boolean input `simulator-lanes-from-host` (default false). When true, the runner's
  `MORPHEUS_IOS_SIMULATOR_LANES` decides the first attempt: absent or `1` runs with Xcode's parallel
  testing off, `2` adds `-parallel-testing-enabled YES -maximum-parallel-testing-workers 2`;
  anything else fails before tests. It cannot be combined with the caller's own `parallel-testing`.
- Retries stay serial on the erased job simulator. `test-attempts.json` records the lane count.
- The host declares the value privately (its runner environment); Morpheus names no host.
