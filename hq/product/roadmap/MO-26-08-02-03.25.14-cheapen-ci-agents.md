## Context

Three replies from Chris after the first day of the CI agents running for real, all pointing the
same way: **the agents are good, and they need to be cheap enough to leave on.**

Rung 2 cost **$8.01** across seven runs fixing one bug, averaging **$1.14 a review** on
`claude-opus-5[1m]` — the action's default, unpinned. The heartbeat cost nothing, because assess is
a deterministic ranker with no model in it.

Chris asked why #69 took five review passes and whether that could be reduced. The answer is
measurable rather than a matter of opinion.

## Why five passes, and what to do about it

Every push re-triggers a review, and I pushed after each finding to verify the fix. Two of those
passes were worth every cent — they found defects in that PR's own guards. The other three read
**successive edits to one roadmap item's prose**.

| Run | What the push changed | Cost |
| --- | --- | --- |
| #68 | inbox cycle — no code | $0.86 |
| #69 pass 1 | workflow, tests | $0.91 |
| #69 pass 2 | tests, item | $1.24 |
| #69 pass 3 | tests, item | $0.93 |
| #69 pass 4 | **item only** | $1.99 |
| #69 pass 5 | **item only** | $1.17 |
| #69 final | **item only** | $0.91 |

**Four of seven runs changed no code at all: $4.93 of $8.01.** Rung 2 reads code; a records-only
push has nothing for it.

## Approach

**1. Skip the review when nothing reviewable changed.** `morpheus review needed` returns false when
the diff is entirely records and board bookkeeping, and the workflow gates the model call on it.

The predicate is `hasNoSubstantiveChange` — the same one `check pr` uses to refuse a claimed branch
that did no work, and `pm ship` uses to refuse a merged PR that did none. Third consumer, one
definition. This repo spent yesterday fixing three bugs whose root cause was a second copy of
something, so a fourth copy was not on the table.

An **unreadable** diff reviews rather than skips. Absence of evidence is not evidence of absence, and
silently disabling the rung the day `git diff` changes shape is a worse failure than a wasted dollar.
The skip writes a job summary saying green means skipped — same shape as the unconfigured path,
because to a reader they are the same fact.

**2. Pin the model.** `claude-sonnet-5`, Chris's call: most of what the rung caught was careful source
reading and cross-referencing records rather than depth, and the difference is better spent on more
repos than more thinking on one. Pinning also removes a silent variable — an unpinned default can
move underneath you, changing both cost and quality with no diff to show for it.

**Measured after the fact, and the estimate was wrong.** The inbox option said "roughly a fifth the
cost". The first Sonnet review of this very PR came in at **$0.88 against an Opus average of $1.14** —
about 23% cheaper, not 80%. It used *more* turns to get there (28 vs 20), so per-token pricing is not
what dominates; the turn count is. Recorded rather than quietly dropped, because a saving claimed at
5× and delivered at 1.3× would otherwise sit in the record as fact.

The gate is doing the real work on cost, not the model swap. Its review was good — it caught a stale
comment in `schedule.yml` that the new one contradicted — so the quality question is still open on
one data point, which is what running it for a while will answer.

**3. Beat hourly, every day.** `0 * * * *`, Chris's call: *"if there is nothing to do then it is
cheap."* It is, and that is not luck — the beat is a deterministic ranking function with no model in
it, so a run that picks nothing costs a runner minute. This is the design decision from MO-050
paying off in a way that was not the reason for making it.

## What this gives up

The reviewer *did* find real problems in item prose — including a claim that a file existed when it
did not, and three successive wrong definitions in a detector spec. Those catches are now
out of scope by construction. Stated plainly rather than buried: this trades a real capability for
roughly 60% of the bill, and if item prose turns out to need review, the honest fix is a cheaper
trigger rather than pretending the gate was free.

## Test plan

- `needed()` as a pure function: source, records-only, board-only, mixed, workflow-only, and the
  unreadable-diff case that must review rather than skip.
- Workflow guards: a model is pinned, the model call is gated on the `needed` output, the skip says
  green means skipped, and the cron is hourly.
- Exercised against the real branch and against synthetic file lists.
