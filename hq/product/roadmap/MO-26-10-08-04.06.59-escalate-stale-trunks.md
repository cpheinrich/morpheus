## Context

Observed 2026-10-08: `~/code/lakina`'s main checkout sat 188 commits behind `origin/main` for three
weeks because an Xcode-regenerated edit to a tracked `project.pbxproj` (Sep 15) made trunk dirty.
`context brief` correctly refused to fast-forward a dirty trunk but printed only a soft "behind;
existing edits preserved" notice that every session ignored. Same class: `~/code/morpheus` had
orphaned untracked `dist/` output from deleted modules that blocked a self-install with a bare
"source checkout has local changes".

## Approach

Chris's call: a dirty trunk should move its uncommitted changes to a branch and push it as a WIP PR.

- `context brief` commits tracked edits on the trunk branch to `wip/trunk-<date>-<host>`, pushes it,
  opens a draft PR, resets and fast-forwards. Untracked files are never committed; orphaned build
  output is named as safe to delete. Skipped (loudly) mid-merge/rebase or off the trunk branch.
- A still-behind checkout escalates to `!!! STALE CHECKOUT` past 20 commits or 3 days.
- `doctor` (and `doctor --all`) reports dirty or stale trunk checkouts read-only.
- `self install` names tracked edits, orphaned build output and other untracked files.
- The GitHub Manager escalates an unadopted `wip/trunk-*` draft to a human, never a session.
