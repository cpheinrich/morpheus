## Context

The unattended gateway worker introduced in PR604 reserves an admission before resolving
credentials. A known credential-resolution failure can therefore leave a permanently
unknown admission even though no guardian or provider launched. The consumer correctly
refuses to retry an unknown effect, so a temporary setup failure strands remediation.

The supervising root reproduced this on merged main `9aa514d7bc925166df87320b9ba1add0272aafea`
using a synthetic environment key reference and a loopback gateway that could not receive
a provider call. The retained proof shows an initial failed result, then status and replay
reporting unverified termination with no native session after the resolver was restored.
The fix belongs to Factory's shared lifecycle owner, not a consumer workaround.

The claimed implementation now retains proven prelaunch failures in existing admission
evidence. Source validation is complete; the supervising root owns fresh independent
review, CI, merge and separate consumer/runtime qualification.

## Approach

Durably record a caught, proven failure before any guardian/provider spawn as a terminal
never-launched failure. Status and same-ID replay return that same failure without
launching a provider. After the setup cause is fixed, the consumer can use a fresh UUID
for one new invocation; absent a native session, it must not use `--resume`.

Preserve every ambiguous-spawn, missing/corrupt-evidence and unknown-existing-worker hold.
Do not mark cleanup verified merely because a PID is absent, an error occurred or the
credential resolver now succeeds. Reuse the current admission/result/guardian owner and
make the smallest lifecycle correction with no new options, quota gate, ledger, dependency,
provider selection, paid-vendor fallback or native-account fallback.

Add a minimal architecture and decisions entry documenting the new unattended API and
this lifecycle boundary; PR604's public README alone did not establish those records.
Do not rewrite PR604 history or borrow its completed claim.

## Acceptance

- Reproduce through the actual CLI with an isolated Factory home, fake provider and exact
  launch counter: missing synthetic credential after admission returns a durable terminal
  never-launched failure, and status reports the same failure with a null native session.
- Same-UUID replay remains idempotent before and after restoring the resolver: identical
  retained failure, zero provider launches. A fresh UUID after restoration launches once;
  it does not try to resume the absent native session.
- Other provable preparation failures receive the same truthful treatment. Missing Python
  or a known spawn error is included only if the implementation can establish no guardian
  or provider was created; ambiguity retains the existing unknown hold.
- A crash/ambiguous spawn, dead guardian, missing process evidence or unknown existing worker
  still blocks replacement admission. Never blanket-set cleanup or termination as verified.
- Normal native-session continuation, exact binding/permissions, one writer, owned-descendant
  cleanup, gateway-only routing and secret redaction remain intact.
- The guardian durably measures actual invocation time using a monotonic clock through
  provider/tool waits and owned cleanup, with UTC bounds for provenance. Public result,
  status and same-ID replay recover identical runner timing after a lost caller reply.
  Legacy/unmeasured, unknown and null-session results invent no reviewer duration; existing
  deadline/lease/cleanup behavior stays unchanged. Consumers compute minutes from milliseconds.
- Focused actual-CLI fake-provider tests, existing unattended/gateway/ownership regressions,
  normal independent review, required CI and protected merge pass. Provider-free fixture
  proof remains distinct from authenticated gateway and installed-runtime qualification.

## Implementation evidence

`prelaunchFailure` records a preparation or guardian-spawn phase, explicit never-launched
proof and a fixed sanitized summary. Status/replay reconstruct a terminal failed result
with verified termination, null native session and null exit code. The only supported
spawn refusal is an ENOENT error naming `spawn python3`, before any spawn event and with
no child PID. Other launch uncertainty keeps the prior hold. Existing operation history
is preserved; old unknown admissions are not repaired by inference.

51 focused provider-free CLI/gateway/guardian/ownership/resume tests passed, as did Factory
syntax checks, root typecheck, compile, PM index and diff checks. The actual CLI regression
asserts zero provider starts through missing-key status/replay/restoration, then exactly
one fresh-UUID start without resume. No live provider call, runtime install, consumer edit
or service operation was performed. Required independent review and CI remain pending.
The added lost-reply fixture discards CLI stdout, removes the derived result file, then
recovers identical UTC bounds and measured duration from guardian evidence via status
and same-ID replay. Its duration includes a bounded provider pause and detached-tool
cleanup pause. Legacy/incomplete/invalid timing and null-session fixtures omit timing.
