## Context

An authorized host service needs a bounded Factory gateway worker without an active
desktop conversation. Today's desktop bridge correctly requires a live root identity;
its background flag does not grant unattended admission. The remote Paperclip path
requires a registered pool and native authentication and is a separate contract.

Keep the current Codex subscription controller-only. The new entry point must use an
explicit existing gateway with a credential reference, never native-login or paid-vendor
fallback. Installation, service activation and consumer delivery acceptance are separate
from source publication.

The supervising root cleared implementation after the independent design critique.
This PR implements the reusable runner; fresh independent source review and rollout
verification remain required. No runtime activation or consumer acceptance is claimed.

## Approach

Extend only `plugins/factory/` with a public unattended worker command. Reuse the existing
provider arguments, credential-reference resolution, sanitized environment, structured
result handling and owned-process guardian. Preserve desktop permission admission.

Use one explicit job identity and private service configuration outside workspaces for
gateway, provider, model, effort, exact permissions, working directory and bounded run
limits. Read the prompt from stdin. Bind retained sessions/checkpoints to the job,
canonical checkout and gateway; never fabricate a desktop root identity. Resolve keys
only for the child environment and keep them out of argv, records and diagnostics.

The consumer owns incident policy, delivery-stage recovery and delivery receipts. Same
commit recovery should reuse GitHub's failed-and-dependent-jobs rerun, proven with a
controlled workflow canary, rather than inventing a cross-run stage cache. Actual
physical-device checks remain required. Neither behavior belongs in the Factory runner.

## Acceptance

- Explicit gateway-only launch works without native login or desktop metadata; missing
  configuration, credentials or gateway access never switches provider or billing path.
- Exact configured permission/sandbox settings are retained or refused, never widened.
- Prompts use stdin; credentials never enter logs, argv, results or persisted metadata.
- One canonical checkout admits one writer. Restart, timeout, output limit and unknown
  termination retain useful evidence and cannot silently launch a duplicate worker.
- A continuation resumes only its own job/checkout/gateway session and returns structured
  completion, checkpoint or needs-input evidence. A worker result is not consumer acceptance.
- Independent reviewers use distinct identities and isolated checkouts; prior findings,
  normal CI and protected merges remain mandatory. Additional rounds require the actual
  engagement authorization to be recorded where repository policy requires it.
- Focused runner and existing gateway/desktop regression checks pass; authenticated gateway
  smoke and installed-runtime proof are reported separately from fake-provider tests.

## Scope and handoff

Factory owns runner code, tests and public documentation only. The supervising root owns
private handoffs, consumer remediation, service operations, the delivery canary and live
recovery acceptance. No pool enrollment, new scheduler, native quota gate, paid service,
consumer source change or deployment is included. The working plan and historical lessons
are recorded in `.agent/worklog/2026-11-03-run-gateway-workers.md`.
