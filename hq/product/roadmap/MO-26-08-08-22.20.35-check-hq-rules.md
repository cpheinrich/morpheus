## Context

`pm-check.yml` already checks out and builds Morpheus to validate project records and generated
indexes. A downstream project with generated Firestore role helpers currently repeats that entire
setup in a separate job just to run one more CLI command. The duplicated setup includes details such
as `package_json_file: .morpheus/package.json` whose failure mode only appears in consumers.

The rule check is security-relevant: it proves the claim writer, route gate and Firestore data gate
still share one role vocabulary. It belongs beside the other generated-state checks, but projects
without Firestore rules must not start failing merely because reusable workflows pin `@main`.

## Approach

- Add a boolean `hq-rules` workflow-call input, defaulting to false.
- When enabled, run `node .morpheus/dist/cli/index.js hq rules --check` after the build already used
  by the PM validations.
- Parse the workflow in tests and pin the input's type/default, the conditional, and the exact
  command so a comment or disconnected input cannot make the test pass.
- Document the one-line consumer configuration beside the three-reader access invariant.

## Acceptance checks

- A caller omitting `hq-rules` preserves current behavior.
- A caller setting `hq-rules: true` runs the check against its repository's `firestore.rules`.
- The workflow remains valid YAML and the complete test/type/build/PM suite passes.

## Implementation outcome

- `pm-check.yml` declares `hq-rules` as a boolean, default-off workflow-call input and conditionally
  runs the existing CLI after the job's one checkout/build sequence.
- The workflow test parses the executable structure and pins the input type/default, conditional,
  and command. This matches GitHub's documented typed reusable-workflow input model.
- The architecture shows the one-line downstream configuration and explains why absence is not an
  error for projects without a Firestore data gate.
- 782 tests pass. TypeScript, the production build, PM validation, generated indexes, and whitespace
  checks are clean.
