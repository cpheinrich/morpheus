## Context

The CLI entry point ends every ordinary command with `process.exit(code)` straight after its
console writes, so a command still exits when some handle lingers. Node writes pipes
asynchronously on macOS, and `process.exit` discards what is still queued: `complexity check
--json` piped into a JSON parser received exactly 65,536 bytes and failed to parse, while the same
command redirected to a file wrote all of it. Agents pipe CLI JSON routinely, so large output was
silently cut.

## Approach

Keep the forced exit and the CD quota/worker `exitCode` path unchanged. Before `process.exit`,
write an empty chunk to stdout and stderr and exit from the second callback: a write's callback
runs only after everything queued before it has been flushed. A closed reader (`| head`) calls
back with an error and exits with the same code. Node built-ins only.

## Acceptance

- A compiled CLI command whose stdout JSON and whose stderr exceed several pipe buffers delivers
  every byte through a real pipe that is read late, and keeps its exit code.
- An ordinary command with an otherwise unused handle still exits.
- The CD quota/worker reader path and its tests are unchanged.
