## Context

The 2026-10-07 instruction change — "read records once, refresh once, then refresh only when a
gated command refuses" — did not change behaviour. Across agent transcripts from 2026-09-24 to
2026-10-28, `morpheus context refresh` per Claude session went from 2.3 to 3.1–3.2 (10–21 in one
session at the top), and Codex ran 2.4–5.1. Some agents took receipts with
`cat .agent/decisions.md .agent/learned.md hq/team/<handle>.md >/dev/null && morpheus context refresh`
— a receipt without reading, the failure `architecture.md` §7.10 says the protocol cannot detect.
`.agent/decisions.md` is 139 KB, so a genuine read is ~35k tokens: every redundant refresh costs
either tokens or honesty.

## Approach

Make the intent code, not prose:

1. **Idempotent refresh.** When the trunk and every required record are unchanged since this
   worktree's receipt, extend it and print one line; ask for no re-read. When something moved,
   print only the delta.
2. **Read evidence instead of assertion.** A provider `PostToolUse` hook (`morpheus context
   record-read`) appends what each Read or shell call actually showed the model of the required
   records to an ignored per-worktree `local/sessions/reads.jsonl`: path, content fingerprint at
   read time, line range. Credit is by content — record lines appearing verbatim in the tool
   result — so `>/dev/null`, `| wc` and truncating pipes earn nothing. Refresh certifies a record
   only where the session's evidence covers it at its current fingerprint: the whole record
   without a recorded baseline, otherwise the changed hunks.
3. **Never lock out.** Where no hook can be shown to be watching (human terminal, other tools,
   unwired projects, untrusted Codex hooks), fall back to the assertion with a visible warning.
   `context install` wires the hooks; `init` scaffolds them; `doctor` reports projects without.
4. Update `AGENTS.md`, the scaffold template, the context-freshness runbook and §7.10.

Coordinates with MO-26-10-28-14.10.57 (splitting the records): evidence is per required record
and content-addressed, so a required set of index plus core entries works unchanged.

## Acceptance

- Unchanged trunk and records → refresh extends the receipt and requires no reading.
- A changed record is refused until the read log covers its changed lines at the new fingerprint.
- `cat … >/dev/null` earns no credit; partial Read ranges add up.
- Without a live hook, refresh certifies by assertion with a warning; nothing breaks.
