## Context

PR611 (MO-26-11-04-20.01.14) gave one Factory task conversation task-owned checkouts across
repositories. After it merged, Chris authorized a documentation-only follow-up. Some
documentation no longer matched the source:

- The README, both delegation skills and `architecture.md` §18.0 described a `fresh:true`
  conversation as fully isolated. Ownership is per root task, so conversations of one task
  can share an adopted linked worktree (PR611's declined review finding FAC-R2).
- §18.0 said routing with no eligible gateway "keeps the work with the coordinator". In fact it
  picks the other provider's native login.
- Install guidance did not separate native-login prerequisites from gateway prerequisites.
- There was no end-to-end multi-repository example.
- Chris asked whether every session needs Full access or only multi-repository ones. The docs
  did not answer. The requirement depends on which agent coordinates, and it predates
  multi-repository support.

## Approach

Documentation only. No runtime, code or test change, and no new gate. Bring the canonical README,
the Codex `delegate` skill, the Claude `delegate-to-codex` skill and §18.0 into agreement with
current source (`workspace.mjs`, `config.mjs` `route`/`permissionMode`/`codexPermission`,
`service.mjs` `pinnedRoute`/`workspace`, `codex.mjs` `recordedSnapshot`). Keep the skills short and
point them at the README.

## Acceptance

- All four documents state the same routing (gateway, else the other provider's native login;
  never the coordinator's own; pinned after the first successful launch), the same fresh-
  conversation boundary, and the same coordinator-dependent permissions.
- The README has a worked example: A plus B, then C added on the same native conversation, then a
  delegation with no targets. It shows real `factory_delegate` argument shapes, the Factory-home
  tree, the task record, `workspaces.json` and native session references, plus a separate root
  task and a fresh conversation. It contains no personal paths or secrets.
- Install and update guidance covers both route types, the Claude-logout evidence, installed
  copies versus source, and preserved settings. It also states local execution and that
  Paperclip is not in agent-facing routing.
- Local Markdown links and anchors resolve. Both skills name the installed README path.
