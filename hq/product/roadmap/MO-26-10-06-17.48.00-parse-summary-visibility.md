## Context

Review of MO-26-10-06-17.16.12 found that the summary-visibility check in `check pr` is regex
based, so some Markdown shapes that hide text still count as a visible paragraph: an unclosed
fence, an indented code block, a link title, and a four-backtick fence around a three-backtick
one. It can also wrongly refuse a summary when an inline span contains three backticks. Both
predate that change.

## Approach

Decide whether a summary is visible from a real Markdown parse of the worklog (rendered text
nodes outside code blocks and comments) rather than regex stripping, and pin each hiding shape
in tests. Low priority: an author faking a hidden summary is already outside the contract.
