## Context

The reusable HQ postbuild guard rejects repository Markdown in dynamic traces only when it lives
under `hq/`. A route can therefore begin reading a root README, `.agent` record, or `docs` file at
request time without failing the permanent build-time-content boundary.

## Approach

Broaden canonical containment to the whole checkout while excluding dependency READMEs under
`node_modules`. Add boundary fixtures for root, `.agent`, `docs`, and `hq`, refresh committed dist,
and update the website contract so future projects inherit the full repository rule.

## Acceptance checks

- Dynamic HQ traces reject Markdown anywhere beneath the canonical repository root.
- Dependency and out-of-checkout Markdown remains excluded.
- Source, compiled output, tests, and website guidance describe the same boundary.
