## Context

The GitHub Manager (MO-26-10-01-12.38.16) shipped handling pull requests only, because that is
where the pile-up was: 20 open pull requests against 12 open issues across three repositories.
Chris's brief also asked it to review open issues and make a judgment call on each.

## Approach

Add an issue sweep beside the pull request sweep, under the same policy file and the same
three-job split. Deterministic first: skip bot-filed issues (`MAL-*` incident records stay with a
human), untrusted authors, and anything recently active. A session then decides per issue: close
as done or duplicate with the evidence, convert to a roadmap item (`pm new roadmap --issue`) on a
records branch, fix directly when the fix is small, or leave it with a reason. Every action is
posted on the issue and listed in the run digest.
