## Context

`morpheus-kit`'s `prepare` script was `pnpm build`. A git dependency is built by **whatever installed
it**, in a temporary clone with that tool on PATH and nothing else — so an npm-based consumer got:

```
npm error > morpheus-kit@0.1.0 prepare
npm error > pnpm build
npm error sh: 1: pnpm: not found
npm error code 127
```

That made the kit **uninstallable by npm**, which is every consumer project. It went unnoticed
because `.agent/decisions.md` settles distribution as a git dependency and nothing had exercised it:
Morpheus is consumed as a globally linked CLI, not as a package. The first real adoption
(`cpheinrich.com` PR #29) took its CI down on the install step.

It also passed a local check beforehand — because pnpm happens to be installed globally on that
machine. The failure needs an environment without it, which is exactly what CI and Vercel are.

## Approach

`prepare` becomes `npm run build`. npm is guaranteed present wherever npm is installing, `pnpm` and
`yarn` and `bun` all run `npm run` fine, and the build definition stays in one place rather than
being duplicated into the hook.

A test asserts no install-time hook names a package manager — `prepare` is the one npm runs for a
git dependency today, but `prepack`, `postinstall` and friends would run in the same borrowed
environment.

## Acceptance criteria

- [x] `prepare` does not name pnpm, yarn or bun.
- [x] No other install-time hook does either.
- [x] `files` still ships `dist`, which is what `prepare` produces and what a git consumer has
      nothing without.
- [x] Verified by installing the branch with npm in an environment where pnpm is not on PATH.

## Open questions

None. This is a one-line fix to a defect that made the settled distribution decision unusable.
