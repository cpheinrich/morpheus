## Context

[Issue #491](https://github.com/cpheinrich/morpheus/issues/491) requests shared Swift palette
generation so Apple consumers can stop copying a local token transformer. The established
[ownership contract](../../../architecture.md#121-token-ownership--one-canonical-owner-per-layer)
keeps primitives in brand tokens and semantic aliases in each project.

## Approach

Add opt-in `--swift <path>` to the existing build/check flow. Render `color.*` with optional
`theme.dark.color.*` overrides as adaptive SwiftUI colors for iOS and macOS. Preserve CSS/TS
bytes and defaults. Validate literal colors and deterministic Swift identifiers before writing.

## Acceptance

- Hex and numeric RGB(A) colors retain exact normalized light/dark channel values to six decimals.
- Missing dark overrides use the light primitive; macOS high-contrast dark resolves as dark.
- Stable Swift names, keyword escaping, collision and malformed-value diagnostics are covered.
- Opt-in generation and `--check` cover missing, stale and current outputs without unintended writes.
- Existing CSS/TS bytes and web-only color support remain unchanged.
- Generated Swift compiles on the available Apple SDKs; focused tests, full suite once,
  typecheck, compile, index and complexity pass before independent review.
- Consumer migration is separate; this task neither changes another repository nor activates a release.
