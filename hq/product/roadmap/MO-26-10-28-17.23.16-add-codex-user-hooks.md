## Context

Codex hook trust is per `hooks.json` file and per hook position (MO-26-10-28-17.16.16), so every
Morpheus project needs its own `/hooks` pass on every machine, repeated whenever a hook's command
changes. User-level hooks (`~/.codex/config.toml` or `~/.codex/hooks.json`) run in every project and
worktree under one trust. Chris asked whether trusting once from `~/code` would work; it does not,
because Codex never loads `.codex/` above a repository's root.

## Approach

The design is in `docs/runbooks/context-freshness.md`, "Proposed: trust Morpheus's Codex hooks once
per machine": an explicit, consented `morpheus codex hooks install [--check]` that writes a marked
block of the three hooks (session shim, read hook, poll guard) with stable commands that delegate to
the CLI and exit 0 outside a Morpheus checkout; per-repository `.codex/hooks.json` stays as the
bootstrap bridge, and each hook claims its event by session and tool-call id so a hook trusted in
both places runs once. Settle the write race with the desktop app, which rewrites the same file,
before building. A person runs the installer; no session or agent runs it against a live config.
