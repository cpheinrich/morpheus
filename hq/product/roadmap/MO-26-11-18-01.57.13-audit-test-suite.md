## Context

Chris asked for the test audit already run on another project to be run here: apply the
prune-tests method, keep the suite broadly intact, and say what it buys in CI waiting and
maintenance.

## Approach

Enumerate every tracked test file from the tree, map each to the CI job that runs it, and rate
all of them 1 to 5. Read the cases the scans nominate line by line. Take timing from Actions runs
that already finished. Change a test only where a local, reverted fault check proves the edit
keeps or adds detection. Report in [`qa/audits/2026-11-18-test-suite.md`](../../../qa/audits/2026-11-18-test-suite.md).

## Outcome

- 240 files, 4,057 declarations. No file rated below 3; one case rewritten, six ranked for a
  human decision.
- Pruning does not shorten CI. The wait is the browser lane: a browser install that took 17 to
  23 minutes in 4 of 35 recent runs, and a WebKit capture stall worth about 166 seconds a run.
- The rewritten case now guards the rule that a delegated worker cannot delegate again, which
  had no test.
- Follow-ups are proposed in the report, not filed: browser install caching, the WebKit stall,
  and a lane for the Firestore rules suite.
