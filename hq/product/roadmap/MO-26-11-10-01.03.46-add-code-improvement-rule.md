## Context

Anthropic's Fable 5.2 prompting guide ([Say who owns the code](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-fable-5-2#say-who-owns-the-code))
reports that, without an ownership statement, the model adds parallel copies of existing code and
reports nearby problems instead of fixing them. Codex's built-in system prompt says the same thing
on purpose: "Do not attempt to fix unrelated bugs … Changes should be minimal and focused on the
task." Chris wants agents on Morpheus projects to merge repeated code and fix clear nearby bugs. He
does not want unrequested feature changes, and found Anthropic's suggested sentence ("what it's
for and how it's built are your call") too permissive. All agents in use are Opus 5.5 or GPT 6.1
or newer.

## Approach

Add one model-neutral working convention, after **Simplicity first**, to Morpheus's `AGENTS.md`
and the scaffold template: merge repeated code, fix clear nearby bugs with a test, change feature
behaviour only when it is plainly broken and the fix is an unambiguous win, and list every
behaviour change in the PR body. It overrides any built-in default to only report nearby problems.
Evo adopts it by hand in its own PR. No `doctor` anchor yet: Chris is trying it in Evo before
other projects are asked to adopt it.
