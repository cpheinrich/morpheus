## Context

The first real Evo dispatch against `nightly-ios-build.yml` was rejected before any job started.
GitHub does not expose the `runner` expression context in a job-level `env` map, so the shared
workflow's `runner.temp` reference made the entire caller workflow unparsable.

## Approach

Remove the job-scope expression and derive `SOURCE_PACKAGES_PATH` from the runner-provided
`RUNNER_TEMP` variable inside the validated upload step, exporting it through `GITHUB_ENV` before
any protected secret is referenced. Add regression coverage for the expression-context boundary.
