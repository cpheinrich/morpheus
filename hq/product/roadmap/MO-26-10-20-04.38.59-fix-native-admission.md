## Context

The CD controller chooses its 15-minute admission or 180-minute test timeout
from overall workflow status. A Linux preflight can make that status in-progress
while native work remains queued. Its terminal fallback also treats an empty
native-job census as proof that no native executor started and ignores assignment.

## Approach

Use the existing paginated GitHub boundary and exact run-attempt route. Classify
complete native job evidence, including assignment and steps; apply the admission
bound to actual waiting native work and require positive no-start evidence before
an ordinary hosted successor. Preserve started-executor quiescence and upload
ownership. Empty/unknown/preflight-only evidence remains repairable through the
existing verified termination and operational-repair path.

Acceptance: focused Controller/Git CAS sequences cover exact 15/180-minute
boundaries, mixed preflight/native work, assignment/start/unknown/empty evidence,
pagination failure and late upload ownership; prove one normal hosted successor
with unchanged source/slot/debt and burned old/new build reservations.

This is source-only work. Keep its PR draft, auto-merge disabled and unmerged
until the campaign coordinator explicitly opens the release gate. No native
campaign dispatch, host/VM/service operation, configuration/ledger mutation,
provider key, tester change or held Evo PR is part of this task. Synthetic tests
do not establish an actual hosted native delivery.
