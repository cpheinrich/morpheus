The initializer, built from the notes taken during MO-007. Scaffolds from
templates, provisions GCP and Firebase, wires DNS and Vercel, creates the repo.

Deliberately after the first retrofit, not before.

## Shipped

`morpheus init` writes the manifest, `AGENTS.md` with `CLAUDE.md` symlinked to it, the four
`.agent/` records, the `hq/` tree for the kind, an inbox, a CI workflow delegating to the reusable
ones, and `.gitignore` entries. Then it registers the prefix and prints `init status`.

**Never overwrites**, so *initialise* and *retrofit* are the same command rather than two that
drift.

## Scope: repository only

No GCP, no DNS, no Vercel. Those live in someone else's console, need credentials this command
should not hold, and MO-030's checklist already tracks them.

Drawing the seam there is what makes this shippable now — every infrastructure item is blocked on a
token and `init` is blocked on nothing.

## Folds in MO-015

`.agent/` and `hq/inbox/` are scaffolded, each with a tracked file, because git drops empty
directories and that is how Evo shipped without a worklog.

## Verified against the tools it has to satisfy

A scaffolded project passes `doctor`, `inbox validate`, `pm validate`, and a `pm new` → `pm index`
round trip with no drift. A scaffold that fails its own CI on day one would be worse than none.
