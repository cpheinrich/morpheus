## Context

The shared TestFlight upload action installs `asccli` through Homebrew before
protected credentials enter the process. Homebrew's current formula has an
arm64 Tahoe bottle but no Intel bottle, so `macos-26-large` exits before archive
with `asccli: no bottle available`. Evo reproduced this in release run
33929043260 while working around an independent arm64 runner-image regression.

## Approach

Keep the fast bottled install as the first path, then fall back to Homebrew's
documented `--build-from-source` install when no bottle is available. Apply the
same boundary to the composite action and reusable workflow, pin both paths in
workflow-contract tests, and verify the fix through Evo's Intel TestFlight job.
