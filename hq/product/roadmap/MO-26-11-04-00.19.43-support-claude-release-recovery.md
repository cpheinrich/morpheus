## Context

Chris accepted a design for an Evo release controller that pins each release's app source while
`main` keeps moving. The shared `release-preflight.yml` refused any source that was not main's
current head, so a run that waited behind another, or raced an unrelated merge, failed on a
process-only property and lost its slot. The design's reviewed amendment replaces that equality
with ancestry plus the existing merged-PR evidence. Architecture §18.2 already named this
relaxation as planned.

An earlier draft of this item also proposed Claude support in the Factory unattended gateway worker;
the coordinator withdrew that scope. Runtime repair stays on the existing Codex gateway path, and
no Factory source changes here.

## Approach

Keep the workflow's interface (no inputs, `github.sha`, `sha` output). Keep the `refs/heads/main`,
exact clean checkout and merged-PR-whose-merge-commit-is-this-SHA checks. When current main differs
from the source, ask GitHub's compare (`source...main`) and require `ahead`; anything else refuses.
Execute the real script against a fake `gh` for head, ancestor, behind/diverged/identical/empty,
failed compare, malformed main, missing or head-only PR, and dirty checkout. Update architecture
and decisions. The Evo controller and its scheduling are a separate Evo item.
