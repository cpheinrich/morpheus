## Context

Chris accepted a design for an Evo release controller that pins each release's app source while
`main` keeps moving. The shared `release-preflight.yml` refused any source that was not main's
current head, so a run that waited behind another, or raced an unrelated merge, failed on a
process-only property and lost its slot. The design's reviewed amendment replaces that equality
with ancestry plus the existing merged-PR evidence. Architecture §18.2 already named this
relaxation as planned.

An earlier draft of this item also proposed Claude support in the Factory unattended gateway worker;
the coordinator withdrew that scope. Runtime repair stays on the existing Codex gateway path, and
no Factory source changes here.

## Approach

Add one `workflow_call` boolean, `allow-pinned-source`, defaulting to false. By default, for every
caller, invocation and re-run, the source must be main's current head, exactly as before. Opted in,
the preflight also accepts a reviewed merge that main strictly contains: GitHub's compare must
report `ahead`, and the existing exact-merge-commit PR binding still applies. Keep
`refs/heads/main`, the exact clean `github.sha` checkout, read permissions and the `sha` output.

Removing the head requirement for every caller was tried first. Independent review then found three
successive ways an older `ios-nightly-build` source could still ship: a re-run, a re-run during an
Actions outage, and a re-run of failed jobs that reused a cached build decision. So the nightly
guards were removed and the default stays strict. Only Evo's release controller, which owns source
ordering, will opt in, in its own PR.

Executed fixtures run the real script for every default and opt-in case, for an unreadable main,
for the PR binding, and for non-main ref, mismatched and dirty checkouts. A cached-decision re-run
regression renders the nightly's actual call.
