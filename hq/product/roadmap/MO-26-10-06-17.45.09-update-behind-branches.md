## Context

On the GitHub Manager's first Morpheus run (ops run 37549663365, 2026-10-07) it correctly enabled
auto-merge on #262 and #322, and both then sat `BEHIND` main for hours. Morpheus's `main` requires
branches to be up to date, and GitHub's auto-merge never updates a branch itself, so a queued pull
request waits until something merges the base in. The sweep routed such a pull request to
`waiting` on every run. The Dependabot maintainer already solved this for its own lane with the
head-SHA-guarded `update-branch` endpoint.

## Approach

Read REST's `mergeable_state`; `behind` routes a queued, green pull request to `update-behind`.
Every merge plan ends with `update-branch`, guarded on the head the plan was made for, when the
branch is behind; auto-merge is queued first so it follows the new CI run. An update GitHub
performs is an exact trunk merge, so it keeps any review on record, the author's or the
manager's, valid. Behind and failing, or behind and conflicting, still goes to a session.
