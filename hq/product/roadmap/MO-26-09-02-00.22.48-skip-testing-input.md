## Context

While profiling Evo's per-PR iOS suite, the single most expensive test turned out to be
`EvoUITestsLaunchTests.testLaunchPerformance` — an `XCTMeasureOptions`-based launch benchmark that
runs three iterations, and runs twice more because of `runsForEachTargetApplicationUIConfiguration`.
A launch-speed regression is exactly the kind of thing that is fine to catch nightly rather than
gate every pull request on, but `ios-ci.yml` had no way to exclude a specific test from one caller
while another caller (the nightly release workflow, which also delegates to `ios-ci.yml`) keeps
running it.

## Approach

Add `skip-testing` (default empty): newline-separated `xcodebuild -skip-testing:` identifiers,
applied only to the "Run unit and UI tests" step. The build-for-testing step compiles the whole
scheme regardless of which subset will execute, so a build-time exclusion would be a no-op there.
A caller that never sets it is unaffected; `ios-nightly-build.yml` does not forward it, so a
nightly caller runs the full scheme by omission with no plumbing required on that side.
